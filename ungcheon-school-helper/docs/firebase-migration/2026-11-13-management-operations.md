# 관리자 운영 제어와 추적 활성화 경계

2026-11-13. 사용자가 기존 업무도우미를 계속 사용할 수 있는지 확인한 뒤 다음 단계 진행을 지시했다. **개발본의 관리자 기능 연결과 합성 시험을 완료했다. 운영 배포·속성·시트 본문·세션은 변경하지 않았다.** 개발 소스 서비스 63, 실제 운영 서비스 60이다.

## 구현 결과

`MigrationOperations.gs`와 기존 PC 관리자 패널을 연결했다. 추가한 네 가지 POST 요청은 `runMigrationReplica`, `setMigrationReplicaPaused`, `prepareMigrationReview`, `confirmMigrationReview`다. 기존 직원 세션 검사 뒤 관리자 비밀번호를 검사하며, 권한 없는 요청은 시트·Firestore 접근 전에 거부한다. 대상 프로젝트/학교 범위/원본/기준 사본과 실행 예산은 서버 설정으로만 결정한다. 관리자 인증 값은 GET 주소·저널·보고서에 넣지 않는다.

관리자는 현황 새로고침으로 기록 번호·복제 확인 번호·대기 변경 번호·확인 필요 건수·자료별 복제 건수를 본다. 복제 확인 번호는 완전 동기화·업무 동작 검증 완료가 아니다. 대기 번호는 빈 예약 번호도 포함할 수 있다. 자동 폴링이나 자동 전송은 없으며, 변경분 반영을 누를 때 고정된 최대 2단계·단계 사이 8초 예산으로 실행한다. 외부 호출 하나의 시간을 강제 제한하는 것은 아니다. 해당 PC 관리 요청의 통신 제한은 60초이며 일반 조회·모바일 35초 계약은 바꾸지 않았다.

동시 실행은 10분 만료의 임시 실행 소유 기록으로 억제한다. 잠금을 잡은 채 Firestore 통신을 기다리지 않는다. 새 실행은 진행 중이면 `BUSY`, 복제 일시정지면 `PAUSED`로 종료한다. 일시정지 요청 중 이미 시작한 한 단계는 끝날 수 있고 다음 단계에서 멈춘다. 실행 종료·오류 후 소유 기록을 정리하며 응답 유실은 기존 복제 체크포인트로 재개한다. 원본 저장과 변경 기록은 복제 일시정지 중에도 계속된다.

불확실 작업 검토는 자료 종류와 변경/삭제/결과 건수만 화면으로 보낸다. 원본 시트에서 실제 결과를 확인했다는 체크 후 확정할 수 있다. 검토 참조는 서버가 인증한 직원 세션의 해시에 묶고 10분 동안만 유효하다. 다른 사용자·만료·원본/후속 기록 변경·명시적 확인 누락을 거부한다. 확정은 관측 상태를 복제 대상으로 삼는 것이며 원본 재실행·과거 성공 응답 생성·업무 성공 판정이 아니다. 화면에서 관리자 해제 후 도착한 응답을 버리고, 요청 실패 때 이전 집계값을 제거한다. 메뉴 이름과 순서에 맞춰 검색 도우미 설명도 갱신했다.

## 소유자 설정과 저장 요청 경계

다음 함수는 내부 함수이며 HTTP·PC 버튼·트리거에 노출하지 않았다. 이번에 운영에서 실행하지 않았다.

| 함수 | 역할과 조건 |
| --- | --- |
| `migrationPrepareOperations_(book, deployment)` | 검토한 새 고정 배포 번호·전체 소스 지문과 서버 대상 설정을 기록. 대상 Firestore 읽기 접근 확인이 실패하면 준비 설정을 기록하지 않음. 기존 설정과 다른 대상/배포를 조용히 덮어쓰지 않음 |
| `migrationActivatePreparedTracking_()` | 준비 후 최소 10분 경과·같은 원본 확인 후 공통 잠금 아래 저널 초기화·추적 활성화. 기존 비밀번호/세션 속성에 접근하지 않음 |
| `migrationFreezeConfiguredBaseline_()` | 추적된 원본의 기준 사본 고정. 이미 설정한 기준을 재사용. 장시간 전체 캡처 가능성이 있어 화면에서 실행시키지 않음 |
| `migrationInvalidateReplica_()` | 추적 없는 코드로 되돌리기 전 또는 누락된 저장 경로 발견 시 기존 복제의 재개를 차단. 시트 저장/추적 설정과 과거 사본·기록은 보존 |

준비 설정 이후의 업무 쓰기는 추적이 아직 꺼져 있어도 공통 잠금으로 직렬화한다. 잠금 취득 후 추적 설정을 다시 읽으므로, 활성화 직전 대기 중이던 요청이 과거 비활성 판단으로 저장하는 경계를 막는다. 준비 이전 코드로 시작한 실행의 종료를 위해 준비 시점부터 10분을 둔다. [Apps Script 공식 실행 제한](https://developers.google.com/apps-script/guides/services/quotas)의 1회 6분을 참고한 여유이며, **실제 고정 배포·모든 쓰기 경로가 새 코드인지 확인하는 절차를 대신하지 않는다.** 일반 조회와 모바일은 이 쓰기 잠금 경로에 들어가지 않는다.

`deploymentVersion`·`sourceFingerprint`는 운영자가 검증 후 전달하는 기록이다. 내부 함수가 배포 API를 조회해 진위를 독립 검증하는 것은 아니다. 현재 기록한 @89/서비스 60 지문을 새 배포 준비에 재사용해서는 안 된다. 새 고정 배포와 HEAD를 검사한 뒤 그 번호와 지문을 사용해야 한다.

기존 복제 무효화 후에는 `REBASE_REQUIRED`로 표시하고 복제 실행·재개·기존 기준 사본 재사용을 거부한다. 이를 자동 해제하는 기능은 없다. 새로운 검토된 기준을 만드는 복구 절차는 운영 적용 준비에서 별도로 마련해야 한다. 실제 고정 배포를 이전 버전으로 되돌리는 동작·리허설도 아직 수행하지 않았다. 무효화 표시만으로 배포 복귀가 구현됐다고 보지 않는다.

## 다음 운영 적용 작업

1. 최신 main·고정 배포·HEAD를 다시 확인하고 보호된 데스크톱 변경을 main에서 검토·검증한다. 기존 배포 가드를 수정하거나 우회하지 않는다. 공유 로그인/모바일/업무 계약을 유지하는 실제 배포 묶음과 고정 배포 복귀 절차를 준비한다.
2. 운영 manifest의 기존 필수 권한을 보존하면서 Firestore용 OAuth/IAM 접근을 준비한다. 현재 운영 manifest에는 명시적 OAuth 목록이 없으며, 이것이 실제 권한이 없다는 뜻은 아니다. 시험 스크립트의 `datastore` 승인이 운영 스크립트에도 적용됐다고 가정하지 않는다. 새 권한이 실제 필요해지는 시점에 해당 운영 프로젝트의 소유자 승인을 받는다.
3. 검증한 고정 배포 적용 후에만 소유자 준비 함수에 새 배포 기록을 전달한다. 설정 준비 시점부터 대기하는 동안 기존 업무 조회·저장은 계속 제공한다. 그 후 공통 잠금에서 추적을 활성화하고 요청별 기록 경계를 확인한다. 비밀번호나 유효 세션을 초기화하지 않는다.
4. **실학교 기준 사본 캡처가 저장 요청을 얼마나 기다리게 하는지 아직 실측하지 않았다.** 현재 함수는 잠금 안에서 전체 대상을 캡처한다. 실제 R0를 만들기 전에 합성 대량 자료로 시간을 측정하고, 필요하면 단계별 보존 사본 방식으로 잠금 시간을 줄인다. 지금 바로 정상 운영 중 전체 캡처를 실행하지 않는다.
5. 인덱스 제외 설정 적용, 실제 기준 사본·변경분 복제, 필요한 범위만 읽는 Firestore 조회 구조, PC/모바일 응답 대조와 전환/복구 리허설을 진행한다. 최종 전환은 완전 동기화 검증 보고 후 사용자의 전환 지시를 따른다.

이미 승인·검증한 시험용 OAuth·Spark 프로젝트·초기 백업을 다시 만들거나 반복 승인받지 않는다. 비용/무료 한도 실측을 매 개발·배포의 필수 중단 관문으로 만들지 않는다. 현재 기능이 운영에 가동 중이거나 상시 장애를 감시한다고 보고하지 않는다.
