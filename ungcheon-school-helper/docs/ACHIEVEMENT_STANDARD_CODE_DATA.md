# 웅천고 정식 과목명·성취기준 코드 데이터

작성일: 2026-08-14

## 목적

`타학교 평가계획`에서 단순 과목명 포함 여부가 아니라 실제 성취기준 코드를 근거로 해당 과목의 평가계획인지 판정하기 위한 기준 데이터이다.

시간표의 축약 과목명은 사용하지 않는다. 웅천고의 정식 과목명은 아래 학교 교육과정 편성표만을 기준으로 한다.

- 파일: `C:/MYBOX/2026. 교육과정부/1. 편성표/2026학년도 웅천고등학교 학교교육과정 편성표(0721).xlsx`
- 시트: `2026 전학년`
- 과목명 열: `D`
- 현재 1·2학년: 2022 개정 교육과정
- 현재 3학년: 2015 개정 교육과정

## 산출물

- 데이터: `resources/curriculum/achievement-standard-subject-prefixes.json`
- 정식 과목 검색 대상: 94과목
  - 2022 개정: 57과목
  - 2015 개정: 37과목
  - 현재 편성표에서 실제 개설(`O`)된 과목: 85과목
  - 편성표에는 있으나 현재 미개설(`X`)인 과목: 9과목
- 공식 성취기준 코드 접두부 확인: 93과목
- 별도 예외: `프로그래밍` 1과목

편성표의 `음악↔미술`은 출처 표기를 그대로 보존하되, 두 과목의 공식 성취기준 코드가 서로 다르므로 검색 데이터에서는 `음악`과 `미술`로 분리했다.

## 데이터 필드

각 `records` 항목의 주요 필드는 다음과 같다.

- `curriculumRevision`: `2015` 또는 `2022`
- `officialSubjectName`: 편성표에 근거한 검색용 정식 과목명
- `sourceOfficialLabel`: 편성표 원문 표기. `음악`, `미술`은 `음악↔미술`로 보존
- `codePrefix`: 뒤의 영역·성취기준 번호를 제외한 과목 식별 코드
- `matchPattern`: 문서 본문에서 실제 대괄호 성취기준 코드만 찾는 안전한 정규식
- `exampleCodes`: 공식 원문에서 확인한 대표 코드 최대 3개
- `sourceFile`: 코드를 확인한 공식 별책 파일
- `offeredAtUngcheon`: 학년·학기·편성표 행·학점·개설 여부
- `status`: `verified` 또는 예외 상태

## 안전한 판정 규칙

접두부만 `startsWith`로 비교하면 안 된다. 예를 들어 2022 개정의 다음 과목들이 서로 잘못 걸릴 수 있다.

- `미술(12미)` ↔ `미디어 영어(12미영)`
- `미술(12미)` ↔ `미적분Ⅰ(12미적Ⅰ)`
- `정보(12정)` ↔ `정치(12정치)`

따라서 다음 순서로 판정한다.

1. 문서 텍스트를 Unicode NFC로 정규화한다.
2. 여러 종류의 유니코드 하이픈을 ASCII `-`로 통일한다.
3. 대괄호 안의 불필요한 공백을 허용한다.
4. `codePrefix` 바로 뒤에 숫자형 영역·성취기준 번호가 이어지는지 `matchPattern`으로 확인한다.
5. 정식 과목명 문자열만 있다는 이유로 일치 처리하지 않는다.

예시:

- 공통국어1: `10공국1` → `[10공국1-01-01]`
- 문학: `12문학` → `[12문학01-01]`
- 동아시아 역사 기행: `12동역` → `[12동역-01-01]`
- 일본어Ⅱ: `12일Ⅱ` → `[12일Ⅱ-01-01]`

## 예외 처리

2015 개정 전문교과의 `프로그래밍` 원문은 성취기준을 서술형으로 제시하고 대괄호형 코드를 제공하지 않는다. 일반 선택 과목 `정보`의 프로그래밍 영역 코드인 `12정보04`는 다른 과목이므로 대신 사용하지 않는다.

`프로그래밍` 평가계획은 향후 기능 연결 시 다음과 같이 별도 판정해야 한다.

- 문서의 과목 제목·표 머리글에서 `프로그래밍`을 확인
- 평가 영역과 성취기준 표 구조를 함께 확인
- 코드 일치 결과와 동일한 수준의 확정값으로 자동 승격하지 않고 `검토 필요`로 표시

## 현재 적용 범위

시험판 `1.1.12-preview.12`부터 `타학교 평가계획` 검색 판정에 연결한다. 과목명이 문서에 단순히 포함된 것만으로는 `자료 있음`으로 확정하지 않으며, 이 데이터의 과목 코드 접두부와 뒤의 숫자 구조가 실제로 확인될 때만 코드 일치로 판정한다. 코드를 확인할 수 없는 문서는 `원문 확인 필요`로 구분한다.
