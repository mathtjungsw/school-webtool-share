# 7번 상세계획 · 파일 처리 도구 통합 및 기능 점검

2026년 11월 18일 · 기존 PC판 기능 검토 완료 · 전체 개선계획 확정 후 통합 시험판 제작

## 1. 교사가 사용할 메뉴

사이드바의 세 메뉴를 ‘파일 처리 도구’ 하나로 합친다. 화면 상단에 아래 세 버튼을 항상 표시한다. 처음 열면 첫 번째 작업을, 이후에는 이 PC에서 마지막으로 사용한 작업을 연다. 예전 검색어·즐겨찾기·바로가기로 들어가면 마지막 작업보다 사용자가 선택한 도구가 우선한다.

| 상단 버튼 | 교사가 하려는 일 | 유지할 기능 |
| --- | --- | --- |
| 엑셀 자료 정리 | 공백·날짜·빈 셀·중복 행을 정리한 사본 만들기 | XLS/XLSX 선택·드롭, 처리 옵션, 통계, XLSX 저장 |
| PDF 글자 추출 | 한 개 또는 여러 PDF의 내용을 파일로 저장하기 | 다중 선택, TXT·MD·JSON, 파일별 상태, Java·OCR 사용 가능 여부 안내 |
| 파일 내용·구조 확인 | 파일을 열어 시트·열·병합·문서 본문을 확인하기 | 시트 전환, 표 미리보기·내보내기, 한글·PDF 본문 미리보기와 저장 |

메뉴 등록부·사이드바·업무 검색·기존 페이지 경로와 즐겨찾기를 함께 연결한다. 예전 ‘Excel 전처리’, ‘PDF 텍스트 추출’, ‘만능 파일 파서’는 해당 작업으로 바로 이동한다. 여러 옛 메뉴를 고정한 경우에도 각 작업으로 바로 들어가는 경로를 보존한다. 작업 전환 중 이미 선택한 파일이나 실행 중인 작업이 조용히 사라지지 않게 한다. 재실행을 위해 기억하는 정보는 마지막 작업 종류로 제한한다.

## 2. PC판 1.1.43 기능 점검 결과

정식 1.1.43 패키지의 UI·메인 프로세스·프리로드 코드를 분리된 Electron 31.7.7 검증 환경에서 실행했다. 버전 표식으로 프로젝트의 로컬 시험 로그인 경로를 사용했다. 가상 교사로 로그인해 실제 메뉴 버튼을 조작했다. 운영 자료·기존 사용자 프로필은 사용하지 않았다. Windows 파일 선택창에는 시험 경로를 자동으로 반환하도록 했고, 앱의 실제 읽기·파싱·내보내기 코드가 만든 파일을 다시 열어 판정했다.

| 기능 | 확인한 결과 |
| --- | --- |
| 엑셀 정리 기본 | XLS와 XLSX 모두 공백·중복 행을 정리하고 결과 XLSX를 저장했다. 고정 길이 날짜 변환, 숫자 7 유지, 빈 셀을 N/A로 채우는 동작도 확인했다. |
| 엑셀 정리 예외 | 시험 원본의 수식과 병합이 처리 사본에서 사라졌다. 날짜 통일을 켜면 품목번호 87654321을 8765-43-21로 바꾸고, 한 자리 월·일을 쓴 2026/1/2는 그대로 두었다. 원본과 별도 파일에 저장한 결과다. |
| PDF 글자 추출 | 현재 시험 PC의 기본 실행 환경에서는 Java 미인식 안내가 뜨고 추출 버튼이 비활성화됐다. 기존 Java 21을 시험 프로세스에서만 지정하자, 한글 본문·고유 표식을 넣은 PDF 2개가 TXT·MD·JSON 각각 2개씩 정상 저장됐다. JSON은 다시 파싱해 확인했다. |
| PDF 파일명 충돌 | 서로 다른 폴더의 동명 PDF를 함께 TXT로 저장하면 ‘2개 파일 저장 완료’라고 나오지만 실제 파일은 1개였다. 두 번째 본문이 첫 번째 출력 파일을 덮었다. |
| 짧은 PDF와 스캔본 | 글자층에 ‘확인’ 두 글자만 있는 PDF는 엔진이 정확히 읽었는데도 앱이 빈 문서로 분류해 TXT를 저장하지 않았다. 이미지 전용 PDF는 OCR 미설치 안내를 띄웠고 빈 TXT를 만들지 않았다. 실제 스캔 인식률은 미검증이다. |
| 파일 파서의 엑셀·CSV | 여러 시트, 병합 셀 개수와 값, 숫자·참/거짓, JSON·CSV·MD 내보내기는 동작했다. 계산 결과 캐시가 없는 시험 수식은 빈 셀로 보였다. 두 번째 시트를 본 상태에서 한 시트짜리 CSV를 열면 화면 전체가 비었다. UTF-8 한글 CSV는 BOM이 있으면 정상, 없으면 한글이 깨졌다. |
| 파일 파서의 문서 | 같은 한글 본문과 2×2 표가 담긴 HWP와 HWPX를 비교했다. HWP는 본문과 표가 모두 표시·저장됐다. HWPX 원본에는 네 셀의 텍스트가 있었지만 화면과 저장한 MD에는 본문만 남았다. Java 21 조건에서 일반 한글 PDF 본문을 미리보고 MD로 저장하는 경로도 확인했다. |

시험 범위는 위 가상 파일과 기본 선택·저장 경로다. 실제 학교 문서, 다른 교직원 PC의 설치 환경, 모든 형식·레이아웃·대용량 파일까지 검증한 결과는 아니다.

## 3. 시험판에 반영할 수정

1. **엑셀 원본 구조를 보호한다.** 값 정리가 필요한 셀만 변경하고 수식·셀 형식·병합을 보존한다. 중복 행 삭제가 수식 참조나 병합 범위를 바꾸는 경우 이를 안전하게 반영하거나, 보존이 어려운 작업을 저장 전에 알리고 해당 옵션을 끌 수 있게 한다. 날짜는 실제 달력 날짜를 검증하고 식별번호와 구분한다. 한 자리 월·일 표기도 처리한다.
2. **PDF 저장 충돌을 막는다.** 한 번의 일괄 처리에서 같은 출력 이름이 나오면 서로 다른 이름을 배정한다. 출력 폴더에 이미 같은 파일이 있는 경우에도 기존 결과를 보호한다. 실제로 기록된 파일 수와 실패·취소 건수를 구분해 보여 주고, 저장에 실패한 항목은 다시 저장할 수 있게 한다.
3. **짧은 문장과 스캔본을 구별한다.** 유효한 본문은 두 글자라도 출력한다. 형식용 JSON 구조나 MD 표시 기호가 있다는 사실만으로 본문 추출 성공을 판정하지 않는다. Java가 없는 환경의 설치 안내를 유지하고, 실제 스캔 OCR 성공은 OCR 엔진을 갖춘 별도 환경에서 검증한다.
4. **파서의 파일 교체와 내용 판독을 보완한다.** 새 파일을 열면 시트 선택을 유효한 첫 시트로 초기화한다. 결과 없는 수식은 수식 자체와 계산값 부재를 구분해 표시한다. 한글 UTF-8 CSV는 BOM 유무 두 경우를 지원한다. HWPX 표 셀 텍스트와 행·열 순서를 미리보기·MD 출력에서 대조한다.

## 4. 시험판 합격 기준

- 사이드바 진입, 옛 메뉴명 검색, 즐겨찾기 직접 진입, 재실행 후 마지막 작업 복원이 각각 의도한 작업을 연다. 탭을 바꿔도 파일이 다른 도구로 전달되지 않는다.
- 공백·중복·빈칸·날짜·식별번호·수식·병합을 섞은 XLS/XLSX로 옵션을 켜고 꺼서 결과를 재열람한다. 기존 원본이 그대로이고 정리 대상 이외의 값과 문서 구조가 보존되어야 한다.
- 같은 이름의 PDF 2개와 미리 생성된 동명 출력 파일을 시험한다. 세 파일의 서로 다른 내용을 확인하고, 화면의 저장 건수가 실제 파일 수와 일치해야 한다. ‘확인’ 2글자 PDF는 정상 저장돼야 한다.
- 일반 한글 PDF 2개의 TXT·MD·JSON 결과와 스캔본의 OCR 사용 가능·불가 경로를 검증한다. 취소나 부분 저장 실패도 성공으로 표시하지 않는다.
- 파서에서 두 번째 시트를 연 직후 한 시트 파일을 열고 이어서 UTF-8 CSV 두 종류, HWP, HWPX, PDF를 연다. 화면이 계속 동작하고, 한글 본문·표 셀·수식·내보낸 파일이 기준값과 일치해야 한다.

이번 단계의 결과물은 상세계획과 기존판 점검 기록이다. 통합 화면 구현과 수정 후 회귀 검사는 전체 상세계획이 끝난 뒤 시험판에서 진행한다.
