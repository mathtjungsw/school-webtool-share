# 교직원 이름·공통 비밀번호 로그인 상세 개발계획

> 2026-11-04 정식 개발·배포 승인. PC 로그인 유지시간은 120시간으로 변경하며, 아래 과거 72시간 설계보다 이 지시를 우선한다. 기존 모바일 로그인·세션은 보존한다.


- 작성일: 2026-11-03 / 현재 단계: **3. 초기 테스트버전 개발·검증**. [개발·검증 기록](../testing/2026-11-03-preview.md)의 구현 범위와 미확인 항목을 함께 확인한다.
- [통합 상세계획](2026-11-03-admissions-reading-tabs.md)의 여덟 번째 개선 항목. [누적 개선안](../IMPROVEMENT_PLAN.md)을 기준으로 한다.
- 사용자 지정 공통 비밀번호는 이번 대화의 지정값을 사용한다. 실제 값은 공개 문서·소스·테스트 fixture에 기록하지 않으며 운영 반영 시 서버의 보호된 설정에 별도 등록한다. 다시 값을 요청하는 절차를 추가하지 않는다.
- 별도 테스트버전의 로그인과 시험 서비스 설정을 구현했다. 정식 로그인·서버·비밀번호 설정·배포는 변경하지 않았다.

## 1. 현재 흐름과 목표

저장된 origin/main 참조의 PilotLogin은 이름을 입력하고 명렬과 대조한다. authStore는 이름·만료시각을 로컬에 저장해 72시간 유지한다. 위젯은 같은 인증 상태를 읽는다. 이 확인은 전체 서버 보안 감사나 현재 설치본 실행 검증이 아니므로 개발 시작 시 최신 main·Release·실제 서버 코드를 다시 대조한다.

목표는 **등록된 교직원 이름과 공통 비밀번호를 모두 확인한 뒤 업무 기능을 제공하는 것**이다. 공통 비밀번호를 아는 사람의 이름 도용까지 막는 개인별 본인 인증으로 표현하지 않는다. 공개 설치파일의 다운로드 자체를 제한하는 변경도 아니다.

## 2. 화면과 진입

```text
웅천고 업무도우미
[교직원 이름]
[비밀번호 · 마스킹] [표시/숨김]
[로그인]
현재 버전 / 업데이트 상태 / 업데이트 확인·설치
```

- 명렬 전체를 로그인 화면에 내려받아 목록으로 공개하지 않고 본인 이름을 입력한다. 이름은 앞뒤 공백을 정리하고 비밀번호의 공백·대소문자는 임의 변경하지 않는다.
- 둘 중 하나라도 비었으면 요청하지 않고 필요한 입력을 안내한다. 중복 제출은 막고 입력·서버 확인 상태를 구분한다.
- 인증 실패는 이름 존재 여부를 세밀히 노출하지 않는 공통 오류로 안내한다. 네트워크 장애·서버 오류·구버전은 인증 실패와 구분한다. 암호 입력은 제출 완료·화면 이탈 시 메모리에서 해제하고 자동 기억하지 않는다.
- 로그인 전에는 개인정보 없는 로그인·버전·업데이트 확인/설치·일반 도움말만 허용한다. 업무자료·교직원 명렬·학생정보·기존 캐시 본문·자료집·개인 위젯은 읽거나 표시하지 않는다.
- 본창·위젯·고정 메뉴·검색·뒤로 가기·바로가기와 보호 IPC의 진입을 같은 인증 기준으로 관리한다. 로그인 성공 후 원래 요청한 허용 메뉴로 이동한다.

## 3. 서버 인증과 세션

1. 기존 학교 공유 서비스에 전용 로그인·세션 확인·로그아웃 경로를 추가한다. 이름과 암호는 HTTPS 요청 본문으로 보내고 URL·로그에 넣지 않는다. 응답에는 암호/검증값/명렬 전체를 반환하지 않는다.
2. 서버가 활성 교직원 이름과 공통 비밀번호를 검증한다. 암호는 솔트가 있는 검증값으로 보호된 서버 설정에 보관한다. 실제 서버 런타임에서 지원하는 검증 방식을 선택·측정하고, 클라이언트에 검증 비밀이나 운영 암호를 넣지 않는다. 클라이언트가 보낸 고정 해시를 재사용 가능한 로그인 암호처럼 신뢰하지 않는다.
3. 충분한 무작위 세션 토큰을 발급한다. 서버에는 원문 토큰 대신 해시, 교직원 ID, 발급/만료시각, 인증 설정 버전, 폐기 상태를 보관한다. 로그인 유지 기간은 기존 이용 흐름을 고려해 **발급 후 최대 72시간, 자동 연장 없음**으로 정한다.
4. 서버 세션은 기존 저장 서비스의 전용 범위에서 관리한다. 토큰 해시로 필요한 세션만 조회하며 교직원·학생 DB 전체를 반복 다운로드하지 않는다. 세션 캐시는 제한된 TTL로 쓰고 로그아웃·비밀번호 변경·명렬 변경의 정상 관리 경로에서 캐시와 세션을 함께 무효화한다. 정확한 저장 수단·한도는 실제 서버에서 검증한다.
5. 보호된 요청은 서버에서 매번 세션의 유효성·만료·폐기·계정 상태·필요 권한을 검증한다. 요청 본문의 viewerName 등은 권한의 근거가 아니며 세션의 교직원과 대조한다. 개인정보 있는 조회뿐 아니라 수정·삭제·동기화 manifest·일괄 조회·우회 action도 목록화해 동일 기준을 적용한다.
6. 인증 공개 경로는 로그인·세션 검증 등 최소 경로만 명시적으로 허용한다. 새 action을 등록하면 기본은 보호 대상이다. 잘못된 세션에서 오래된 비인증 API로 재시도하거나 오류를 캐시 성공으로 바꾸지 않는다.

잘못된 암호 시도는 서버에서 이름·요청 출처 등 확인 가능한 범위의 빈도를 제한하고 재시도 대기시간을 반환한다. Apps Script의 실행 주체를 실제 사용자 신원으로 오인하지 않는다. 공통 암호 변경은 운영자가 보호된 설정을 바꾸고 인증 버전을 올려 기존 세션을 폐기하는 방식이며, 일반 로그인 화면에 임의 암호 변경 기능은 추가하지 않는다.

## 4. PC 보관·위젯·오프라인

- 메인 프로세스가 토큰과 인증 상태의 원본을 관리한다. 토큰은 OS 보호 저장을 적용하고 렌더러에는 이름·유효기간·상태만 제공한다. 서버 요청 계층이 필요한 요청에 토큰을 붙이며 범용 설정 조회·로그·다른 사이트로 노출하지 않는다.
- 앱 재시작 시 저장된 세션은 서버 재검증 후 복원한다. **첫 로그인과 앱 시작 시 검증에는 인터넷 연결이 필요하다.** 실패하면 로그인 화면과 업데이트 안내를 제공하며 로컬 이름/만료시각만 믿고 업무를 열지 않는다.
- 같은 실행 세션에서 인증을 마친 뒤 연결이 끊기면 유효기간 안의 로컬 기능은 사용할 수 있다. 서버 쓰기/조회는 성공으로 가장하지 않으며 만료·폐기 응답을 받으면 본창과 위젯 모두 즉시 잠근다. 오프라인 중 원격 폐기를 즉시 알 수 있다고 보장하지 않는다.
- 로그인·로그아웃·만료·이름 전환은 메인에서 본창/위젯에 같은 인증 세대로 알린다. 이전 세대의 요청·worker·캐시 응답은 폐기한다. 미인증 위젯에는 로그인 이동과 개인정보 없는 업데이트 표시만 남긴다.
- 로그아웃은 서버 세션 폐기와 로컬 토큰 제거를 수행한다. 서버 연결 실패 시 로컬 접근은 즉시 잠그고 미완료 폐기를 암호화된 전용 범위에서 재시도한다. 서버 폐기까지 완료했다고 잘못 안내하지 않는다.
- 이름 전환 시 이전 사용자의 개인 상태를 표시하지 않는다. 로그인 해제는 업무 원본·학생부·산출기 데이터·개인 설정 전체 삭제와 구분한다. 저장된 자료는 인증 후 해당 기능의 범위에 따라 다시 읽는다.
- 교장·교감 추가 인증과 우수사례 `0000` 열람 권한은 별도 유지한다. 일반 로그인 토큰을 추가 권한으로 취급하지 않고, 로그아웃 때 추가 권한도 폐기한다.
- 로컬 성적·우수사례 자료의 서버 전송 금지는 유지한다. 인증 요청에는 이름·인증 정보만 보내고 학생자료·검색어·자료집을 첨부하지 않는다.

## 5. 구버전 전환과 배포

- 기존 pilotLogin 이름/만료값은 새 세션으로 전환하지 않는다. 최초 업데이트 후 한 번 다시 인증하고 이전 인증값만 정리한다. 업무 데이터와 개인 설정은 보존한다.
- 서버의 모든 보호 action과 PC 앱뿐 아니라 동일 서버를 사용하는 모바일·관리 도구의 호출 경로를 조사한다. 기존 별도 인증이 있으면 검증된 동등 권한으로 연결하고, 모바일 등을 이유로 이름만 받는 공개 우회 경로를 남기지 않는다. 영향이 확인된 클라이언트 수정은 인증 전환의 필수 작업으로 범위에 기록한다.
- 서버 인증 API 준비 → 새 클라이언트 테스트 → 업데이트 제공 → 보호 요청 강제 적용 순서와 전환 시점을 기록한다. 인증 API만 추가한 단계는 접근 차단 완료가 아니다. 구버전은 보호 데이터에 대해 재로그인/업데이트 필요 오류를 받고 공개 업데이트 경로로 설치할 수 있어야 한다.
- 새 UI는 구버전에 소급 표시되지 않는다. 초기 전환용 수동 설치·기존 업데이트 이용 안내를 준비하되 별도 지시 없이 교직원에게 메시지를 발송하지 않는다.
- 복구 시에도 비인증 업무 조회를 다시 허용하지 않는다. 서버·앱 계약을 맞춘 더 높은 패치로 복구하고, 인증 서버 장애 때 개인정보 없는 업데이트 경로를 유지한다.

## 6. 파일과 구현 순서

| 영역 | 변경 |
| --- | --- |
| PilotLogin·authStore·App | 두 필드·오류·신규 세션 bootstrap·로그인 전/후 UI·업데이트 예외 |
| electron/main 인증 모듈·preload·타입 | 토큰 OS 보관·요청 자동 첨부·IPC 검증·인증 상태 snapshot/세대 |
| schoolHub 서비스·메인 요청/캐시 계층 | 보호 action 인증·401/403/만료 처리·캐시 읽기 전 인증·늦은 응답 폐기 |
| server/Code.gs 또는 최신 기준의 실제 서버 진입점 | 로그인/세션/로그아웃·검증값·세션 저장·기본 보호 dispatcher·action별 권한 |
| WidgetApp·개인 자료 어댑터·보호된 로컬 기능 | 인증 snapshot·이름 전환·잠금·추가 보호 기능 유지 |
| 동일 서버의 모바일/관리 클라이언트 | 조사로 확인한 인증 계약 호환 작업. 무관한 기능 변경은 제외 |
| 프리뷰·검증·사용 안내 | 합성 명렬/암호·격리 서버·전환/오프라인/복구 안내 |

실제 서버 대상은 최신 소스·배포 ID와 대조해 확정한다. 이름이 비슷한 다른 프로젝트의 Code.gs나 기존 미커밋 변경을 일괄 덮어쓰지 않는다.

순서는 기준 소스/호출 경로 조사 → 합성 환경 서버 인증·action 목록 → 메인 세션/IPC → 로그인 UI → 위젯/캐시/추가 권한 → 구세션 전환/모바일 호환 → Windows 패키징·서버 강제 검증 → 정식 전환과 복구이다. 신규 유료 인증 서비스는 추가하지 않고 인증 결과·필요 세션만 읽는 방향으로 비용을 줄인다.

| AU-01 | 이름/암호 누락·오류·미등록/비활성 이름 거부, 정상 두 필드 인증만 허용 |

| AU-05 | 로컬 이름·만료값 변경과 구세션으로 우회 불가, 재시작 시 서버 확인 |
