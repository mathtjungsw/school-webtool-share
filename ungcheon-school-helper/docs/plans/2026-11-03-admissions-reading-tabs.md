## 1. 최종 메뉴와 사용자 동작

공통 진입은 교직원 이름과 대화에서 지정한 공통 비밀번호의 서버 인증으로 변경한다. 로그인 전에는 개인정보 없는 버전·업데이트 안내를 제공한다. 기존 이름만 저장된 세션은 새 인증으로 인정하지 않는다. 일반 로그인과 우수사례 0000/교장·교감 추가 인증은 별도 권한이다.

본창·로그인 화면·펼친/접힌 위젯·트레이가 업데이트 상태를 공유한다. 나중에를 눌러도 배지를 유지하며 실제 실행 버전으로 설치 완료를 확인한다. 이 두 공통 개선으로 별도 사이드바 메뉴를 추가하지 않는다.

```text
평가·교육과정·진로
  ├ 타학교 평가계획
  ├ 성적 산출 미리보기
  ├ 추정분할점수 도우미
  └ 교육과정 편제표 출력

진학·대입
  ├ 대학 권장과목               ← 기존 탭 이동
  ├ 웅천고 생기부 생성 도우미   ← 새 사이트 연결
  ├ 대학 웹진(아로리)           ← 대학별 자료 통합 열람
  ├ 평균내신등급 산출기         ← PDF·XLSX 로컬 계산·저장자료 비우기
  └ 수시모집 우수사례           ← 대학·학과별 검색·로컬 원문·비밀번호 열람

독서교육
  ├ 웅천 서가                   ← 새 사이트 연결
  └ 대학 추천도서               ← 서울대 100선·도서 해설·진로 탐색

인사·교사용 도구
  └ 기존 메뉴 유지
```

- 두 새 모임은 `평가·교육과정·진로` 다음에 위 순서로 배치하고 처음에는 펼쳐 표시한다.
- 사용자가 말한 `대학 과목 추천`은 기존 표시명 `대학 권장과목`에 해당한다. 표시명과 기능을 유지하고 소속 모임만 옮긴다.
- 두 사이트는 각각 독립된 탭으로 앱 본문에 표시한다. 기존 앱 로그인 외에 새 관리자 전용 제한을 추가하지 않는다.
- 수시모집 우수사례에는 사용자 지정 비밀번호 `0000`을 별도로 적용한다. 모든 진입 경로와 같은 탭 재클릭에서 잠금을 거치고 이탈 시 열람 권한을 폐기한다. 자료는 관리자 중앙 등록 후 인증된 경로로 제공하며 공개 앱 배포물에는 포함하지 않는다.
- 사이트 상단에 제목, 간단한 용도, `새로고침`, `기본 브라우저로 열기`를 제공한다.
- 메뉴 선택·업무 도우미 검색·앱 뒤로 가기에서 같은 페이지 ID를 사용한다. 사이트 안의 이동 기록과 앱 메뉴 뒤로 가기는 구분한다.
- 사용자의 기존 고정·숨김 설정이 있는 메뉴는 개인 설정을 우선한다. 고정한 메뉴는 기존 고정 영역에 표시되며 기본 모임에 중복 표시하지 않는다.

## 2. 사이트별 주소와 표시 방식

| 항목 | 주소·구현 결정 |
| --- | --- |
| 생기부 생성 도우미 | `https://ungcheon-tools.github.io/saenggibu/` |
| 웅천 서가 | `https://script.google.com/macros/s/AKfycbx_uawLjhfejiIdd6mWV5D1TCULX-1K1BtINa-WWBOGkuWrw05KrpVHSIx43L2Qq_xw7A/exec` |
| 생기부 표시 | 격리된 `iframe` 방식 우선. 기존 계획과 미리보기의 앱 본문 구성을 따른다. |
| 웅천 서가 표시 | 전용 `WebContentsView`로 사이트를 별도의 최상위 웹 문서로 불러오고, 앱 본문 자리에 배치한다. |
| 공통 대체 경로 | 기존 `shell.openExternal` 경로로 위 공식 진입 주소를 기본 브라우저에서 연다. |

### 직접 확인한 내용

- 생기부 사이트: 앞선 2026-11-03 조회에서 HTTP 200, 사이트 버전 `2026.10.30`, 로컬 저장과 공식 AI API 직접 호출 코드를 확인했다. 앞서 제공한 이미지는 실제 사이트 화면을 넣은 설계 미리보기이며 개발 완료 화면은 아니다.
- 웅천 서가: 이번 2026-11-03 직접 HTTP 조회에서 HTTP 200과 HTML 제목 `웅천 서가`를 확인했다.
- 웅천 서가 응답에는 **`X-Frame-Options: SAMEORIGIN`**, **`Content-Security-Policy: frame-ancestors 'self'`**가 있었다. 따라서 외부 앱의 일반 HTML 프레임에 그대로 넣는 방식은 표시 제한에 걸릴 가능성이 높다.
- 웅천 서가의 실제 Electron 표시, 사이트 로그인 조건, 서버 저장 구조, AI 키 처리 방식은 아직 검증하지 않았다. HTTP 응답 성공을 실제 기능 검증으로 보고하지 않는다.

### 방식 선택의 근거

- Electron은 프레임과 `WebContentsView`를 외부 웹 콘텐츠 표시 수단으로 제공한다. `WebContentsView`는 메인 프로세스에서 생성·배치하므로 별도 크기 및 표시 상태 관리가 필요하다. [Electron Web Embeds](https://www.electronjs.org/docs/latest/tutorial/web-embeds), [WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)
- 웅천 서가는 보안 헤더를 제거하거나 외부 사이트 배포 설정을 바꾸는 대신, 전용 웹 보기에서 원래 사이트를 불러오는 방식으로 검증한다. 사이트 자체의 Google Apps Script 내부 프레임은 그대로 사용한다.
- Google Apps Script의 프레임 제한과 링크 이동 정책은 공식 문서를 참고한다. 앱 본체를 웹사이트로 덮어쓰게 하는 권한을 열지 않는다. [XFrameOptionsMode](https://developers.google.com/apps-script/reference/html/x-frame-options-mode), [HTML Service 제한](https://developers.google.com/apps-script/guides/html/restrictions)
- Google 로그인이나 학교망 조건 때문에 앱 안에서 이용할 수 없는 기능이 있으면 기본 브라우저 경로를 유지하고 해당 제약을 보고한다. 브라우저로 연결만 되는 상태를 앱 내 표시 완료로 처리하지 않는다.

## 3. 기준 소스와 작업 공간

- 현재 작업 폴더의 앱 버전은 `1.0.1`이고, 저장된 `origin/main` 참조는 `d186ce0a`(2026-10-08, 소스 버전 `1.1.37`)이다. 이번 계획 작성에서 원격 최신 버전과 동일하다고 확인한 것은 아니다.
- 정식 계열 소스에는 `navigationRegistry.ts`, 개인 메뉴 설정, 검색, 메뉴 모임이 구현되어 있다. 오래된 로컬 사이드바를 수정해 최신 프로그램 전체를 대체하지 않는다.
- 3단계 시작 시 원격 `main`과 최신 Release를 대조해 기준 커밋을 기록한다. `codex/admissions-reading-tabs-preview` 계열의 별도 브랜치·작업 공간에 이번 아홉 항목만 구현한다. 서버 인증은 운영과 분리한 시험 대상에서 확인한다.
- 현재 폴더의 기존 변경, 누적 문서, 다른 업무 파일은 보존한다. 기존 소스의 미커밋 변경을 일괄 스테이징하거나 배포에 섞지 않는다.
- 실제 기준 버전의 타입·빌드 설정에서 선택한 API의 지원 여부를 확인한다. 이 기능을 위해 Electron이나 관련 스킬을 무조건 최신 버전으로 교체하지 않는다.

6. 숨긴 새 메뉴도 기존 환경설정에서 복원할 수 있게 한다. 검색이나 뒤로 가기로 이동할 때 새 소속 모임이 활성화되게 한다.

메뉴 소속 변경만으로 대학 권장과목의 데이터셋, 검색·비교·역검색·학생부 분석 로직을 수정하지 않는다. 기존 페이지 재진입 시 유지되는 상태의 범위도 이번 이동 때문에 축소하지 않는다.

## 5. 생기부 생성 도우미 구현

- `SaenggibuGeneratorPage.tsx`에 사이트 표시와 공통 상단 도구를 연결한다. 외부 사이트 주소를 앱의 메인 창 주소로 직접 바꾸지 않는다.
- 사용자가 최초로 탭을 선택했을 때 한 개의 프레임을 만든다. 앱 시작·메뉴 펼침·검색 결과 표시만으로 사이트를 불러오지 않는다.
- 최초 방문 후에는 페이지 전환 애니메이션의 재마운트 영역 밖에 프레임을 유지한다. 다른 메뉴를 다녀와도 입력 내용과 진행 중 작업이 프레임 생성 때문에 끊기지 않도록 한다.
- 비활성 상태에서는 숨기고 포인터·키보드 접근을 막는다. 명시적인 새로고침에는 입력·진행 중 작업에 영향이 있음을 확인받는다.
- 사이트에 필요한 스크립트·저장·사용자 실행 다운로드·인쇄만 허용하도록 프레임 권한을 구성한다. 클립보드는 사용자 클릭에 따른 복사를 기준으로 검증한다.
- 부모 앱이 교차 출처 프레임의 내부 저장 상태나 오류를 직접 읽을 수 있다고 가정하지 않는다. `onLoad`만으로 저장 성공·AI 생성 성공을 표시하지 않는다.
- 앱 종료·재실행 시 자료 복원은 사이트의 로컬 저장 기능을 사용하며 별도의 서버 동기화를 추가하지 않는다.

## 6. 웅천 서가 구현

### 6.1 전용 웹 보기 생성

- `UngcheonLibraryPage.tsx`는 앱 상단 도구와 본문 자리만 제공한다. 메인 프로세스의 관리 모듈이 `WebContentsView`를 생성해 본문 위치에 붙인다.
- 웹 보기에는 앱의 preload를 넣지 않는다. `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`, `webSecurity: true`로 구성한다.
- 기본 앱 세션과 분리된 `persist:ungcheon-library` 세션을 사용해 사이트 쿠키·저장소를 관리한다. 테스트판은 별도 프로필 안에서 같은 이름의 세션을 사용한다.
- 첫 진입에서만 원래 `/exec` 주소를 불러온다. 운영 사이트 데이터를 별도로 수집·복제하지 않고 원래 사이트의 화면과 통신을 이용한다.
- Apps Script 실행에 필요한 Google 내부 프레임·리소스 통신을 허용하되, 이 사이트 외의 임의 주소를 입력하는 범용 브라우저 기능은 만들지 않는다.

### 6.2 생성·이동·종료 상태

| 상황 | 동작 |
| --- | --- |
| 방문 전 | 웹 보기 없음. 사이트 로딩 요청 없음 |
| 첫 방문 | 한 개 생성 → 본문 좌표 적용 → 사이트 로딩 |
| 다른 메뉴 이동 | 웹 보기 숨김. 앱 메뉴와 작업에 초점 이동 |
| 다시 방문 | 같은 웹 보기 재표시. 자동 재로딩 없음 |
| 앱 공지·업데이트·검색·로그·인증 팝업 표시 | 팝업과 겹치는 웹 보기를 숨기고 팝업 입력을 우선 처리 |
| 팝업 닫기 | 다른 팝업이 없고 현재 메뉴가 웅천 서가일 때만 복원 |
| 앱 창 최소화·복원·크기 변경 | 숨김·복원과 본문 좌표 갱신. 사이트 재접속 없음 |
| 웹 프로세스 오류 | 앱 본문에 오류와 수동 다시 열기를 제공. 자동 반복 재생성 없음 |
| 앱 창 종료 | 웹 콘텐츠와 이벤트 구독을 해제. 정상 종료를 위해 저장 파일을 지우지 않음 |

네이티브 웹 보기는 HTML의 `z-index`만으로 팝업 뒤에 가려지지 않을 수 있으므로, 앱의 팝업 표시 상태와 웹 보기의 표시 상태를 명시적으로 연결한다. 팝업이 중첩되면 모든 가림 사유가 해제된 뒤 복원하도록 한다.

### 6.3 크기·포커스·오류

- 본문 자리의 `ResizeObserver`와 창 크기·사이드바 변경 이벤트를 통해 좌표를 갱신한다. 프레임 단위로 중복 갱신을 합치고 주기적 폴링을 사용하지 않는다.
- 메인 프로세스는 전달된 좌표를 유한한 값인지 검사하고 창의 허용 본문 영역 안으로 제한한다. 창 배율·디스플레이 배율 변경과 사이드바 애니메이션도 확인한다.
- 웹 보기에서 키보드를 사용해도 기존 업무 도우미 열기 단축키 등이 필요한 범위에서 작동하게 한다. 전체 입력 내용이나 키 입력을 로그로 수집하지 않는다.
- 최초 로딩 지연과 `did-fail-load`, `render-process-gone` 등 실제 이벤트를 구분한다. 하위 프레임 오류를 전체 페이지 장애로 잘못 표시하지 않는다.
- 약 15초 지연 시 다시 열기·기본 브라우저 안내를 제공하되 기존 로딩을 강제로 반복하지 않는다.
- Google 계정 인증이 필요하면 사이트 원래 인증 절차를 따른다. Chrome·Edge 쿠키를 복사하거나 앱 로그인 정보로 자동 로그인시키지 않는다.

## 7. 공통 연결 관리와 보안 경계

앱 공통 로그인은 로그인 상세 설계의 서버/메인 세션을 적용한다. 아래 사이트 제어 IPC와 각 로컬 기능의 자료 IPC도 일반 인증을 확인한다. 로그인 전 허용되는 업데이트 IPC는 신뢰한 앱 최상위 프레임에서 개인정보 없는 고정 동작만 허용한다. 기존 비인증 서버 action이나 로컬 이름값으로 우회하지 못하게 한다.

이 절의 사이트 도구 IPC는 외부 사이트 표시·제어에 한정한다. 평균내신등급 산출기와 수시모집 우수사례의 파일 선택·자료 읽기·저장·삭제는 각각의 전용 화면과 전용 IPC로 분리하며, 성적·우수사례 본문·검색어/결과를 외부 사이트 제어 채널이나 메인 앱의 공통 상태로 전달하지 않는다. 산출기 상세 설계 8절과 우수사례 상세 설계 9~10절의 잠금·보관 경계를 함께 적용한다.

- 두 독립 사이트와 대학 웹진 목록의 ID·이름·고정 진입 주소·표시 방식을 순수 데이터 모듈 한곳에서 관리한다. API 키나 사용자 자료는 이 모듈에 넣지 않는다.
- 렌더러에서 메인 프로세스로 전달하는 것은 도구 ID, 표시 상태, 본문 좌표, 새로고침·브라우저 열기 같은 동작뿐이다. 임의 URL·API 키·학생 자료를 전달하는 새 IPC는 만들지 않는다.
- 신규 IPC는 앱 메인 창의 신뢰한 최상위 프레임에서 보낸 요청인지 확인하고, 등록된 도구 ID·동작·좌표 범위만 받는다. 외부 웹 콘텐츠가 같은 채널을 호출해 앱 설정을 읽거나 쓰지 못하게 한다.
- 외부 링크는 사용자 클릭과 검증된 HTTPS 대상에 한해 기본 브라우저로 넘긴다. 새 창 생성은 기본 차단하고 필요한 링크만 별도 처리한다. Apps Script의 정상 내부 이동과 외부 링크 열기를 구분한다.
- `script.google.com`에서 다른 임의 Apps Script 배포로 이동하는 것은 허용 범위로 보지 않는다. 시작 주소는 제공된 배포 경로로 고정하고 실제 정상 이동에 필요한 대상만 확인해 추가한다.
- 권한 처리는 웅천 서가 전용 세션에 한정한다. 필요한 파일 선택·다운로드·출력·사용자 실행 복사는 개별 검증하고 카메라·마이크·위치 같은 불필요한 권한을 일괄 허용하지 않는다.
- 기존 Google 관련 헤더 변경 처리가 있더라도 새 기능의 성공 근거로 사용하지 않는다. 새 전용 세션에 보안 헤더 제거를 복제하거나 범위를 확대하지 않는다.
- 보안 기준은 [Electron 보안 지침](https://www.electronjs.org/docs/latest/tutorial/security)을 따른다. 다른 앱 기능의 보안 설정을 전역으로 변경하지 않는다.

## 8. API 키·저장 자료·서비스 비용

| 데이터·동작 | 처리 기준 |
| --- | --- |
| 생기부 사이트 API 키 보관 | `이 컴퓨터에 키 기억하기` 선택 시 사이트 로컬 저장소에 보관. 현재 방식은 암호화 저장이 아님 |
| 키 기억하기 해제 | 사이트의 기존 키 삭제 동작을 검증. 서버 삭제 기능이 있다고 표현하지 않음 |
| AI 제공업체 전송 | 사용자의 AI 생성·모델 조회 시 선택한 제공업체 공식 API 인증에 사용. 로컬 보관과 별개의 전송 |
| 학교 공유 서버·중계 서버·로그 | 탭 연결을 위해 키를 수집·보관·업로드하지 않음. 오류 로그에도 요청 헤더·키를 남기지 않음 |
| 기존 앱 AI 키·교직원·학생 자료 | 두 사이트에 자동 전달하거나 사이트끼리 공유하지 않음 |
| 앱과 Chrome·Edge 자료 | 저장소가 별개이며 자동 동기화·이전되지 않음 |
| 웅천 서가 데이터 | 원래 사이트의 서버·저장 정책을 따름. 이 사이트까지 로컬 전용이라고 안내하지 않음. API 키를 입력하는 기능이 있다면 키 처리 경로를 별도로 확인 |
| 개인별 분리 | 사이트 자료가 앱 로그인 이름만으로 자동 분리된다고 가정하지 않음. 실제 앱 프로필·세션 범위로 안내 |
| 정식판·테스트판 | 앱 프로필과 사이트 저장소를 분리. 테스트판의 키·작업 내용을 정식판으로 자동 복사하지 않음 |
| 평균내신등급 산출기 | 원본·학생 성적·결과를 외부에 전송하지 않는 독립 로컬 기능. 전용 LocalAppData 저장소·암호화·통신 차단·자료 비우기 적용. 사이트의 저장 정책과 구분 |
| 수시모집 우수사례 | 일반 로그인/추가 PIN 해제 후 인증된 중앙 원문 제공·암호화 캐시/색인·본문 검색. 이탈 시 재잠금·읽기 권한 폐기. 공개 저장소/설치파일 자료 미포함, 외부 전송 차단. 산출기 자료와 별도 관리 |
| 일반 로그인 | 이름·공통 암호는 HTTPS 인증 요청에만 사용. 서버 검증값/세션 해시·PC OS 보호 토큰·72시간 절대 만료. 암호 평문 소스/문서/로그 미포함. 학생자료·우수사례는 인증 요청에 첨부하지 않음 |
| 업데이트 | 메인 updater 하나의 상태와 다운로드를 공유. 6시간 확인·백오프·버전별 재안내·실제 설치 확인. 별도 사용자별 추적 서버 없음 |

- 사용자의 `서버로 전송하지 않기` 요구는 API 키를 학교 서버나 별도 중계 서버에 수집·보관하지 않는 구현 기준으로 기록한다. 공식 AI API 인증 전송까지 금지한다는 뜻이라면 온라인 AI 호출과 양립하지 않는 점은 앞서 안내했다.
- 탭 연결 자체는 신규 유료 서비스나 중계 서버를 추가하지 않는다. 실제 AI 생성에는 선택한 제공업체 요금제에 따른 비용이 발생할 수 있다.
- 웅천 서가는 페이지 로딩과 사용 중 기존 Apps Script 처리를 실행할 수 있다. 단순 탭 추가를 이유로 기존 사용량이나 운영비가 항상 0이라고 보장하지 않는다. 이번 조사에서는 사용량을 측정하지 않았다.
- 앱 시작 시 두 사이트를 미리 로딩하거나 상태 확인 요청을 반복하지 않는다. 첫 방문 후 화면과 HTTP 캐시를 재사용한다.
- 앱 연결 계층에서 AI 호출·재시도·정기 새로고침·전체 DB 다운로드를 추가하지 않는다. 원래 사이트의 통신과 구분해서 검증한다.

## 13. 테스트버전 제공

- 버전은 기준 정식 버전을 확인한 뒤 `<다음 후보 버전>-preview.1`로 정한다. 이번 문서에서는 실제 정식 버전 번호를 확정하지 않는다.
- 프리뷰 전용 앱 이름·식별자·`userData`·사이트 세션 저장 경로·빌드 출력 경로를 적용한다. 기존 설치 위치와 바로가기를 덮어쓰지 않는 별도 실행본을 우선 제공한다.
- 정식 자동업데이트 피드에서 설치하지 않게 하고, 프리뷰의 업데이트 제외 처리도 확인한다. 정식판의 로그인·학생 자료·API 키를 테스트판으로 자동 복사하지 않는다.
- 개발 서버 화면만으로 완료하지 않고 Windows 패키징 실행본에서 확인한다.
- 로그인은 합성 암호/명렬의 분리 서버에서 확인한다. 업데이트는 별도 앱 ID·프로필·격리 피드의 두 버전으로 실제 설치하며 운영 Release를 시험 목적으로 게시하지 않는다. 운영 비밀번호는 시험판·fixture·공개 문서에 넣지 않는다.
- 공통 확인 순서는 로그인 실패/성공·구세션 재인증 → 기존 일곱 메뉴의 검증 → 본창/위젯/로그인 전 업데이트 표시·나중에·저장 확인·설치/재시작 버전 판정 → 로그아웃/추가 권한 폐기이다.
- 제공 자료: 실행본 위치, 기준 커밋·버전, 일곱 메뉴의 실제 화면 이미지, 항목별 통과·미확인·제약 목록, 사용자 확인 순서. 산출기·우수사례의 공개 화면과 자동 검사에는 합성 자료만 사용하며 실제 자료집·색인은 테스트 실행본에도 포함하지 않는다.
- 사용자가 확인할 순서: 새 모임 확인 → 대학 권장과목 진입 → 생기부 사이트 진입·샘플 복사/저장 → 웅천 서가 표시 → 대학 웹진의 아로리 기본 화면·대학 전환 → 대학 추천도서의 카드·상세·출처·검색·관심 저장 → 평균내신등급 산출기의 두 입력·두 범위·복원·자료 비우기·원본 보존 → 우수사례의 PIN·로컬 등록·대학/학과/전형별 탐색·검색/원문·이탈 후 재잠금 → 메뉴 왕복·창 크기 변경·검색 → 브라우저 열기.

## 14. 정식 반영·배포와 복구

1. 정식 반영 및 배포 요청 시 검증한 아홉 항목의 변경을 최신 정식 소스에 통합한다. 기준 소스가 바뀌었으면 충돌 해결 후 영향을 받는 검사를 수행한다. 로그인 API 준비·클라이언트 업데이트 제공·서버 보호 강제 순서와 모바일/관리 호출 호환을 확인한다.
2. 프리뷰 설정이 정식 빌드에 섞이지 않게 한다. 정식 앱 ID·사용자 저장 경로·개인 설정은 유지한다. 기존 이름만의 로그인값은 보존 대상 세션으로 인정하지 않고 최초 재인증한다. 업무 데이터는 유지한다.
3. 버전·사용 안내·변경 내역을 갱신하고 타입검사·빌드·Windows 설치파일과 자동업데이트 설정을 검증한다. 우수사례 원문·추출 본문·색인·미리보기·실제 fixture가 Git 추적·번들·asar·리소스·설치파일에 포함되지 않았는지 SC-18로 확인한다. 자료가 공개 배포물에 섞인 상태는 배포 완료로 판정하지 않는다.
4. `main`의 앱 소스 변경은 자동 배포를 유발하므로 정식 단계에서만 반영한다. 배포 워크플로와 설치파일·blockmap·`latest.yml` 게시 성공을 확인한다.
5. 신규 프로필과 기존 설정이 있는 프로필에서 메뉴 구성과 사이트 진입을 확인하고 결과를 기록한다.
6. 배포 후 문제는 이번 변경을 수정하거나 되돌린 더 높은 패치 버전으로 복구한다. 사이트 저장소나 기존 사용자 자료를 삭제하지 않는다.

외부 사이트 장애와 앱 연결 오류를 구분한다. 사이트 문제 발생 시 오류·브라우저 안내를 제공하고 다른 앱 기능은 계속 사용할 수 있게 한다.

## 15. 완료 판정과 현재 상태

- 상세 계획 완료: 아홉 요구사항과 기존 일곱 메뉴, 로그인·업데이트 공통 동작, 서버/로컬 보안·수정 대상·구현·검증/배포 기준을 기록했다. 각 추가 상세 설계를 함께 적용한다.
- 테스트버전 완료 조건: 아홉 항목을 실제 실행본에서 구현하고 필수 검사를 통과한다. 사이트의 앱 내 표시 제한을 기록하고 도서100개 콘텐츠 대조, AG-01~18, SC-01~20, AU-01~16, UP-01~18을 검증한다. 새 로그인은 실제 서버 강제 적용과 전체 호출 경로를, 업데이트는 두 패키징 버전의 설치·재실행을 확인한다.
- 정식 배포 완료 조건: Release·업데이트 파일, 기존 자료/설정 보존, 일곱 메뉴·일반/추가 로그인·업데이트 알림/설치, 우수사례 자료 미포함과 구버전 전환을 확인한다.
- 현재 실행 검증: Windows 시험판에서 주요 정상 경로와 기존 검사·타입/빌드·패키징을 확인했다. 전체 계획의 완료를 의미하지 않으며, 실제 서버 배포·자료 전수 대조·전권 콘텐츠·업데이트 현장 검증 등 남은 항목은 개발 기록에 명시했다.
