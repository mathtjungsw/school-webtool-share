# 4번 상세계획 · 모바일 오늘 일정 우선 조회

2026년 11월 18일 · 상세계획 작성 완료 · 전체 항목 검토 후 통합 시험판 제작

## 1. 화면별로 언제 무엇을 받을지

현재 모바일은 지난주 월요일부터 다음 주 일요일까지 21일을 묶어 요청한다. 시험판에서는 교사가 연 화면을 기준으로 요청 범위를 정한다. 상단 탭과 주 선택 위치는 [6번 상세계획](2026-11-18-mobile-weekly-navigation.md)을 따른다.

| 교사의 행동 | 조회 범위와 화면 동작 |
| --- | --- |
| 처음 로그인해 오늘 열기 | 한국 시간 기준 오늘 하루만 요청한다. 교사의 오늘 수업, 당김·교환·대강·휴강, 담당 일정, 급식과 출결 요약을 표시한다. 지난주·다음 주 조회는 예약하지 않는다. |
| 같은 날 다시 열기 | 유효한 세션에 이 교사의 오늘 자료가 있으면 즉시 표시하고 마지막 정상 확인 시각을 함께 보여 준다. 현재 화면의 변경 여부를 확인해 바뀐 자료만 갱신한다. |
| 날짜 화면에서 다른 날짜 선택 | 선택한 날짜만 받는다. 날짜 선택 버튼은 날짜 계산만으로 표시하며, 버튼을 그리기 위해 미래 일정을 미리 받지 않는다. |
| ‘주간 시간표’ 열기 또는 주 이동 | 이번 주·지난주·다음 주 중 선택한 주의 표시 기간을 요청한다. 같은 날짜의 기본 수업과 실제 변경을 합쳐 교시별로 표시한다. |
| ‘주간 일정’에서 이번 주 또는 다음 주 열기 | 선택한 주의 월요일부터 일요일까지 조회한다. 앞서 받은 날짜·자료는 재사용한다. 아직 받지 않은 주를 처음 누르면 해당 주에만 로딩을 표시한다. |
| 교시의 출결 상세 열기 | [1번 계획](2026-11-18-private-rosters-timetables.md)에 따라 서버가 그 교사의 해당 교시 수강 관계를 확인해 명렬을 제공한다. 닫거나 날짜·사용자를 바꾸면 상세 화면과 메모리에서 비운다. |

## 2. 조회와 캐시 처리

1. 모바일의 기간 계산과 갱신 함수를 분리해 화면마다 조회할 날짜를 지정한다. 공용 서버의 기존 시작일·종료일 요청과 계약 버전 3을 유지한다. 이전 모바일 버전의 21일 요청도 전환 중 계속 처리한다. 여러 날이 필요한 경우 주 단위 한 요청으로 묶어 날짜마다 서버를 호출하는 방식은 피한다.
2. 요청에는 해당 사용자가 보유한 날짜·자료의 버전을 선택적으로 보낸다. 서버는 바뀐 부분과 처음 요청한 부분만 회신한다. 변경 판정에는 자료의 실제 변경 버전을 사용한다. 단순히 서버에 접속한 시간을 변경 버전으로 취급하지 않는다. 기본 주간 수업표는 같은 버전이면 재사용한다.
3. 캐시는 로그인 사용자별로 구분한다. 일정·급식·출결 요약은 날짜와 출처별로, 기본 시간표는 적용 기간과 버전별로 보관한다. 서버 응답에는 정상 확인한 기간, 변동 없는 부분, 변경된 부분, 자료 없음 및 조회 실패를 구분한다. 기존 21일 캐시는 사용자·날짜·기간을 확실히 식별할 수 있는 부분만 임시 표시하고 나머지는 새 방식으로 다시 받는다.
4. 오늘과 같은 주를 차례로 열어도 기존 날짜를 지우지 않는다. 자료가 정상적으로 삭제되거나 일정이 다른 날로 이동하면 원래 날에서도 제거하고 새 날짜에 한 번만 표시한다. 당김·교환의 원래 날짜가 요청 기간 밖이어도 서버에서 필요한 연결을 확인하여 선택 날짜의 수업을 빠뜨리지 않는다. 한 출처가 실패하면 해당 날짜·출처만 이전 자료로 표시한다. 처음 조회에 실패한 날짜는 ‘확인 필요’로 표시한다.
5. 탭 변경·복귀·수동 갱신이 겹칠 때 같은 범위의 요청은 한 번만 보낸다. 늦게 도착한 지난 화면의 응답이 현재 날짜나 더 최신 자료를 덮지 않게 한다. 기존 5분 자동 확인과 앱 복귀 확인은 열린 화면 범위에 적용한다. 한국 시간 자정 이후에는 새 오늘 날짜와 주 경계를 다시 계산한다.
6. 기존 35초 요청 제한과 출처별 마지막 확인 시각을 유지한다. 망이 끊기면 이미 받은 날짜만 ‘이전 자료’로 표시하며, 받은 적 없는 날짜에는 ‘아직 내려받지 않음’을 안내한다. 세션 만료·사용자 전환 시 이전 사용자의 자료를 다시 표시하지 않는다. 기기 캐시 쓰기에 실패해도 화면에서 정상 수신한 자료는 보여 준다.
7. 급식은 학교에서 동기화한 자료를 재사용한다. 선택 날짜 급식과 기존 앱의 오늘 급식 호환 필드를 날짜로 구분한다. 모바일이 NEIS를 직접 조회하거나 전체 학생 명렬을 받는 경로는 추가하지 않는다. 서비스 워커는 인증 요청과 상세 출결을 저장하지 않는다.

### 급식·출결 요약을 따로 다시 확인하기

- **급식**이 실패하면 해당 날짜의 급식 칸에 ‘급식 자료를 확인하지 못했습니다’와 ‘급식 다시 확인’을 표시한다. **출결 요약**이 실패하면 오늘의 출결 요약 위치에 ‘출결 요약 다시 확인’을 표시한다. 실패 전에 받은 자료가 있으면 내용과 마지막 정상 확인 시각을 함께 보여 준다.
- 서버에서 정상 조회했지만 급식이 비어 있으면 ‘등록된 급식이 없습니다’로 표시한다. 출결 요약이 없는 경우도 정상 응답으로 구분하며, 두 경우 모두 오류용 버튼을 숨긴다. 단순히 화면의 목록 길이로 실패를 판정하지 않는다.
- 버튼을 누르면 선택한 날짜와 자료 종류만 요청한다. 서버도 그 자료에 필요한 원본만 읽는다. 급식은 학교에서 동기화한 급식을 조회한다. 출결은 기존처럼 오늘의 해당 교사 수업과 시간표 변경을 확인해 요약만 반환한다. 상세 학생 명렬은 해당 교시를 따로 열 때만 받는다.
- 다시 확인하는 동안에는 해당 칸에만 진행 상태를 표시하고, 연속으로 눌러도 같은 요청은 하나만 보낸다. 실패가 기록된 기존 묶음 응답을 그대로 돌려주지 않는다. 성공하면 그 항목과 확인 시각만 갱신한다. 정상 응답이 빈 목록이면 오래된 사본을 화면에서 지우고, 다시 실패하면 마지막 정상 시각을 유지한다. 날짜나 사용자가 바뀐 뒤 도착한 응답은 현재 화면에 반영하지 않는다.

## 3. 시험판 합격 기준

| 시험 상황 | 확인할 결과 |
| --- | --- |
| 신규 로그인 후 오늘 화면만 이용 | 첫 기간 요청의 시작일과 종료일이 모두 오늘이다. 다른 주 본문 요청은 0건이다. 수업 변경·일정·급식·출결 요약이 기존 21일 방식의 같은 날짜와 일치한다. |
| 오늘 → 주간 시간표 → 같은 주 일정 | 이미 받은 오늘 자료의 버전이 같으면 본문을 다시 받지 않는다. 아직 없는 기간은 묶어서 조회한다. 토·일 일정까지 포함해 누락·중복이 없다. |
| 다음 주 조회 도중 오늘로 복귀 | 오늘 화면이 즉시 복원된다. 늦은 응답이 오늘 수업이나 급식을 바꾸지 않는다. 다음 주의 새 일정·취소·날짜 변경은 해당 날짜에만 반영된다. |
| 날짜 경계·수업 예외 | 일요일 밤과 월요일 아침, 대강·당김·주간 범위 밖 원수업, 휴강·재개, 3학년 오후 수업 종료 전후를 합성 자료로 대조한다. |
| 오프라인·부분 실패·로그아웃 | 미조회와 등록 자료 없음을 구분한다. 정상 자료를 오류로 덮지 않는다. 사용자 변경 후 이전 일정이 보이지 않으며 출결 창을 닫은 뒤 상세 명렬이 기기에 남지 않는다. |
| 시간표는 정상이고 급식만 실패 | 버튼을 연속으로 누르면 선택 날짜 급식 재조회는 1건, 이 동작으로 발생한 전체 일정 요청과 서버 시간표 원본 조회는 각각 0건이다. 화면의 시간표와 일정은 계속 보인다. |
| 오늘 출결 요약만 실패 | 해당 교사의 오늘 요약을 복구한다. 급식 조회와 상세 학생 명렬 전송은 0건이다. 수업 변경 확인에 필요한 자료는 반영한다. |
| 이전 급식이 있는 상태에서 재시도 | 다시 실패하면 이전 급식과 마지막 정상 확인 시각을 유지한다. 정상 응답이 빈 목록이면 ‘등록된 급식이 없습니다’로 바뀌고 재시도 버튼이 사라진다. |
| 체감 속도와 호출 비용 | 같은 기기·네트워크·합성 자료로 기존판과 시험판을 반복 비교한다. 로그인 성공 후 오늘 수업이 실제 표시될 때까지, 다음 주를 처음 눌러 일정이 표시될 때까지, 재방문 시 캐시로 표시될 때까지를 각각 기록한다. 중앙값과 함께 요청 수·수신량·서버 원본 조회 횟수를 비교한다. 요청 범위 축소가 서버 읽기 감소로 이어지는지도 확인한다. |

**검증 환경.** 분리된 모바일 시험판과 시험 서버에서 먼저 검증한다. 수치 기록에는 이름·학번·수업 원문을 포함하지 않는다. 실제 속도 개선 폭은 측정 후 기록한다.
