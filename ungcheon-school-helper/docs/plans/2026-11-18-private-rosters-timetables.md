# 1번 상세계획 · 명렬과 수업 시간표의 비공개 보관 및 동기화

2026년 11월 18일 · PC·모바일 점검 개선안 · 상세계획 작성 완료, 통합 시험판 제작 대기

## 1. 교직원이 경험할 변화

교사는 평소처럼 업무도우미에 로그인한다. 새 PC에서는 현재 조회 권한이 있는 명렬과 시간표를 처음 한 번 내려받는다. 오늘 시간표를 먼저 보여 주고 나머지 허용 자료는 뒤에서 받는다. 이후에는 학교가 수정한 자료 묶음만 갱신한다. 교직원이 GitHub에 가입하거나 자료 파일을 직접 설치할 필요는 없다.

| 이용 상황 | 제공할 자료와 동작 |
| --- | --- |
| 일반 교직원의 PC | 기존 업무에서 허용된 교직원·학생 명렬, 교사·학생별 시간표와 개별 수업 편성을 제공한다. 기존 학생 위치 찾기, 시간표 조회, 출석부 출력의 대상 범위와 출력 순서를 유지한다. |
| 교장·교감 또는 관리자 PC | 현재의 추가 인증과 관리 권한을 각각 확인한다. 관리 전용 자료는 일반 로그인 때 받는 묶음에서 제외한다. 명렬에 표시하지 않는 로그인 전용 교직원의 기존 이용 권한도 별도로 보존한다. |
| 위젯 | 로그인한 사용자의 오늘 수업과 허용된 요약을 본창과 같은 버전으로 표시한다. 같은 PC에서 두 창이 동시에 열려도 자료는 한 번만 받는다. |
| 모바일 | 로그인한 교사의 시간표와 일정만 개인 캐시에 둔다. 기존 급식·학교 일정 표시와 교시별 출결 요약을 유지한다. 학생 이름과 출결 비고는 교사가 해당 교시를 열 때 서버가 수강 관계를 확인한 뒤 전달하고, 창을 닫으면 메모리에서 비운다. |
| 성적 도구 | 성적·학생부 원본, 산출 결과와 작업 초안은 비공개 GitHub에 넣을 수 있는 자료 목록에서 제외한다. 1인 1PC의 자동 암호화·복원은 [2번 상세계획](2026-11-18-local-grade-encryption.md)을 따른다. |

## 2. 원본과 권한 관리

- 학교가 관리하는 비공개 GitHub 저장소에 학생 명렬, 교직원 명렬, 교사 시간표, 학생별 시간표, 개별 수업 편성 및 당김수업을 자료 종류와 적용 학기별로 보관한다. 실제 이름과 학번은 파일명·커밋 메시지에 쓰지 않는다. 보존기간과 과거 버전 정리는 학교 담당자가 관리할 수 있게 한다.
- 기존 업무 서버가 요청자의 로그인과 조회 권한을 확인한 뒤 해당 자료만 전달한다. 로그인 자격 확인용 명단은 서버 내부에서 대조한다. 일반 사용자나 앱에 저장소 접근 키와 원본 다운로드 주소를 전달하지 않는다. 읽기 자격과 관리자 갱신 자격을 분리하고 해당 비공개 저장소로 범위를 제한한다.
- 담당자는 기존 관리자 메뉴에서 명렬과 시간표를 올린다. 서버가 관리자 권한·파일 형식·학기·중복·학생 및 교사 연결을 검사하고 검증된 새 버전만 게시한다. 동명이인은 이름만으로 연결하지 않는다. 입력 파일에 예상 밖의 성적 열이 섞이면 게시를 중단하고 해당 열을 안내한다.
- 첫 시험 대상은 명렬·시간표 원본과 현재 공개 소스에 들어 있는 개인별 편성 자료다. 교환·대강 요청, 승인·취소, 일일 예외 입력은 기존 화면에서 처리한다. 승인·취소가 시간표를 바꾸면 해당 사용자의 적용 일정 버전도 갱신한다. 로그인·급식·업무센터까지 한꺼번에 이전하지 않는다.

## 3. 최초 다운로드와 변경 동기화

1. **로그인 성공.** 서버가 계정·역할·기기 유형에 맞는 자료 목록, 버전, 적용 기간을 반환한다. 권한 확인 전에는 성명·학번·시간표 본문을 응답하지 않는다.
2. **처음 쓰는 기기.** 내 시간표와 오늘 화면에 필요한 자료부터 받고 PC의 나머지 허용 자료는 뒤에서 받는다. 아직 받지 못한 자료는 ‘자료 받는 중’ 또는 ‘다시 받기’로 표시한다. 이 상태를 공강이나 빈 명렬로 표시하지 않는다.
3. **다시 로그인하거나 앱으로 돌아올 때.** 사용자별 로컬 버전과 서버 버전을 비교한다. 같으면 본문 다운로드는 0건이어야 한다. 교직원 명렬만 바뀌었다면 명렬만 받고, 명렬·시간표가 함께 바뀌면 같은 기준 시점의 자료를 한 벌로 적용한다. 삭제·전출·수업 취소도 반영한다. 관리자가 저장한 직후와 사용자의 ‘지금 확인’ 요청은 다음 주기까지 기다리지 않는다.
4. **중단·동시 편집.** 다운로드가 끝나고 자료 무결성과 참조 관계를 확인한 뒤 로컬 버전을 교체한다. 중간에 끊기면 유효한 기존 세션의 마지막 정상 자료에 확인 시각을 표시하고 재시도한다. 두 관리자가 편집하면 먼저 게시된 버전과 대조해 충돌을 알린다. 같은 갱신 요청을 재시도해도 중복 반영을 막는다.
5. **호출 비용.** 공용 서버가 자료 버전을 재사용해 교직원마다 GitHub 원본을 반복 조회하지 않도록 한다. 개인별 응답 캐시는 사용자·권한 범위·자료 버전별로 구분한다. 본창과 위젯은 진행 중인 요청과 마지막 확인 시각을 공유한다.

## 4. 기기 보관과 접근 종료

PC 파일은 Windows 보안 저장소를 이용해 암호화하고 앱 사용자별로 분리한다. OS 암호화를 쓸 수 없으면 해당 세션의 메모리에서만 사용한다. 기존 공용 캐시에서 소유자를 판별할 수 없는 자료는 새 사용자에게 승계하지 않고 로그인 후 다시 받는다.

로그아웃·사용자 전환 시 화면과 위젯을 즉시 비우고 해당 계정의 동기화 요청을 취소한다. 취소 전에 시작한 응답도 이전 정보를 되살릴 수 없어야 한다. 온라인에서 권한이 회수되면 그 범위의 캐시를 폐기한다. 오프라인에서는 서버의 권한 변경을 즉시 알 수 없으므로 기존의 유효한 세션과 이미 받은 범위에서만 마지막 확인 시각을 붙여 표시한다. 만료 후에는 재인증까지 잠근다. 모바일 상세 출결은 매번 온라인 권한 확인을 거친다.

설정의 ‘공유자료 캐시 삭제’는 로그인한 사용자의 동기화 자료만 비운다. 사용자가 입력한 성적과 로컬 초안은 삭제 대상에서 제외한다.

## 5. 기존 업무를 유지하면서 전환하는 순서

| 단계 | 작업과 다음 단계로 넘어갈 기준 |
| --- | --- |
| 통합 시험판 준비 | 기존 서버의 자료별 읽기·쓰기 경로와 직무별 조회 범위를 표로 확정한다. 프로젝트 인계 기록의 Firebase 주 저장 경로, 관리자 등록, PC 위젯, 모바일 출결을 함께 추적한다. 시험용 비공개 저장소와 분리된 시험 서버에는 가상 명렬·시간표만 사용한다. |
| 읽기·쓰기 연결 | PC 공유자료 서비스와 모바일 서버 응답을 통해 새 원본을 연결한다. 학생 개별 편성 및 당김수업을 PC 코드·모바일 정적 파일에 복사하는 빌드 절차를 제거한다. PC 날짜별·주간 시간표와 모바일 교시별 출결이 같은 편성 기준을 사용하게 한다. |
| 정식 전환 전 대조 | 현행 원본을 기준으로 새 저장소를 채우고 이후 변경분을 따라잡는다. 전환 시점까지 기존 경로만 업무 쓰기의 기준으로 삼는다. 마지막 변경 버전, 명렬 건수·순서와 교시별 결과를 서버 안에서 대조한다. 차이가 남으면 현행 운영 경로를 유지한다. |
| 전환·복구 설계 | 정식 반영 시 대상 자료의 관리자 쓰기와 읽기를 같은 버전 기준으로 넘긴다. 구버전 PC와 공개 모바일이 사용하는 응답 형식도 보존한다. 장애 시 직전 정상 버전을 제공하고, 원래 저장 경로로 복귀할 때는 전환 후 관리자가 저장한 변경을 대조·반영한 뒤 전환한다. |
| 기존 공개 사본 대응 | 학교 담당자와 현재 공개 소스, Git 이력, 과거 설치본·릴리스, 모바일 정적 파일·서비스 워커 캐시의 범위를 별도로 확인한다. 새 배포물 교체로 이미 내려받은 사본까지 회수되지는 않는다. 기존 기록 정리와 설치본 교체는 학교 업무 중단·자동 업데이트 경로에 미치는 영향까지 검토해 별도로 결정한다. |

## 6. 시험판 합격 기준

| 시험 상황 | 통과 조건 |
| --- | --- |
| 깨끗한 PC에서 최초 로그인 | 로그인 전 학교 명렬·시간표 본문 수신 0건. 로그인 후 허용 자료가 자동으로 준비되고 화면이 준비 중·완료·오류를 구분한다. |
| 변경 없음 / 한 종류 변경 | 재실행 시 같은 버전 본문 수신 0건. 한 자료만 수정하면 해당 자료 및 실제로 영향받는 일정만 갱신된다. 본창·위젯 동시 요청도 중복되지 않는다. |
| 사용자·권한 전환 | 같은 Windows 계정에서 교사 A 로그아웃 후 B 로그인, 보호 메뉴 잠금, 세션 만료, 권한 철회를 시험한다. 검색·인쇄·위젯·캐시 어느 경로에서도 이전 사용자의 자료를 열 수 없어야 한다. |
| 모바일 출결 | 본인 시간표·일정·급식은 정상 표시된다. 전체 명렬과 다른 교사 수업은 기기로 전달되지 않는다. 상세를 닫은 뒤 브라우저 저장소와 서비스 워커 캐시에 학생 이름·비고가 남지 않는다. |
| 일정 정확성 | 동명이인, 전출, 당김·교환·대강·취소, 일일 예외, 3학년 오후 수업 종료 전후 날짜를 합성 자료로 검증한다. 학생별 시간표·학생 위치·인쇄·위젯·모바일이 각 사용자의 같은 날짜·교시를 일관되게 표시한다. |
| 장애·복구 | 다운로드 중 종료, 저장 공간 부족, GitHub 일시 장애, 관리자 동시 수정을 재현한다. 유효한 직전 자료가 부분본으로 덮이지 않으며, 권한 만료 후 오프라인 캐시를 열 수 없어야 한다. |
| 배포물 검사 | 공개 소스·생성 파일·PC 설치 패키지·모바일 빌드에 운영 개인별 편성과 저장소 자격이 포함되지 않아야 한다. 테스트에는 가상 데이터만 사용하고 로그에는 버전·건수·성공 여부만 기록한다. |

**단계 구분.** 이 문서는 1번 항목의 상세계획이다. 점검 항목별 검토와 상세계획 작성을 모두 마치면 통합 시험판을 제작한다.
