# 11번 상세계획 · PC 위젯과 본창의 첫 화면 속도 개선

2026년 11월 18일 · PC판 · 전체 항목 검토 후 통합 시험판에서 검증

## 현재 동작

Windows 시작 시 위젯만 실행하는 경로는 이미 있다. 다만 위젯과 본창이 같은 HTML을 열고, 시작 파일이 두 화면과 위젯 스타일을 모두 불러온 뒤 표시할 화면을 고른다. HTML에서는 Google Fonts에 연결해 한글 글꼴을 요청한다. [화면 진입 코드](../../src/main.tsx) · [시작 HTML](../../src/index.html) · [창 열기 처리](../../electron/main/index.ts)

기존 점검에서 다시 빌드한 주 진입 JavaScript는 약 2.19 MB였다. 격리된 정식판 1.1.43에서 실행부터 로그인 폼 감지까지 한 번 측정한 값은 약 2.85초였다. 위젯이 보이는 시간과 로그인 칸이 입력을 받는 시간은 시험판 비교 때 기존판에서도 같은 방식으로 새로 측정한다.

## 구현 계획

1. 현재 본창·위젯 실행 경로를 유지하고, 시작 파일이 창 종류를 확인한 뒤 해당 화면 모듈만 불러오도록 한다. 위젯 전용 스타일은 위젯 모듈에서 읽는다. 두 창이 함께 쓰는 밝은 테마, 공통 스타일, 숫자 입력 처리, 오류 기록은 양쪽 첫 화면에서 동작하게 한다. 위젯 단독 실행 중에는 본창을 미리 열거나 본창 전용 코드를 미리 받지 않는다.
2. 외부 글꼴 스타일시트와 사전 연결을 제거한다. 본창과 위젯의 기본 한글 글꼴은 Windows에 설치된 ‘맑은 고딕’을 우선 사용하고, 사용 가능한 시스템 글꼴로 대체할 수 있게 한다. 위젯의 개별 스타일도 점검해 제목·과목명·버튼에 같은 한글 기준을 적용한다.
3. 위젯의 ‘프로그램 열기’와 메뉴 바로가기는 기존 창이 있으면 앞으로 가져오고, 새로 여는 경우에는 본창이 요청을 받을 준비가 된 뒤 목적 메뉴를 표시한다. 로그인 확인이 필요한 사용자는 기존 로그인 절차를 거친다. 일반 실행, Windows 시작 시 위젯 자동 실행, 트레이에서 다시 열기를 모두 확인한다.

## 속도 측정 방법

| 비교할 동작 | 시작 | 측정 종료 |
| --- | --- | --- |
| 위젯 단독 실행 | 앱이 완전히 종료된 상태에서 위젯 실행 | 첫 실행 안내 또는 위젯의 실제 글자·버튼이 보이고 버튼 입력을 받음 |
| 본창 직접 실행 | 로그아웃 상태에서 일반 바로가기 실행 | 이름 입력칸에 시험용 글자 한 자가 실제로 입력됨 |
| 위젯에서 본창 열기 | 위젯의 ‘프로그램 열기’ 클릭 | 로그인 상태에 맞는 본창이 보이고 입력을 받음. 기존 본창이 숨겨진 경우와 본창을 처음 만드는 경우를 구분 |

같은 PC, 같은 화면 배율, 같은 로그인 조건에서 설치형 기존판과 시험판을 비교한다. 각 경로를 최소 5회 반복해 중앙값과 최솟값·최댓값을 기록한다. 위젯 단독 실행 후 곧바로 본창까지 여는 총시간도 함께 기록해 대기가 다음 동작으로 옮겨갔는지 확인한다. 개인 일정이 서버에서 도착하는 시간은 화면이 입력을 받는 시간과 구분한다.

## 통합 시험판 확인 기준

- 위젯 단독 실행에서 본창 전용 화면 코드 로드가 0건인지, 두 창의 첫 화면에서 외부 글꼴 요청이 각각 0건인지 설치형 빌드의 요청 기록으로 확인한다. 외부 글꼴 도메인을 차단한 상태에서도 한글과 버튼이 처음부터 표시되어야 한다.
- 기존판과 시험판의 세 경로를 각각 비교한다. 반복 측정 편차보다 작은 차이는 개선 여부 판단을 유보한다. 본창 열기가 반복해서 늦어지면 지연 구간을 찾아 수정하고 다시 측정한다.
- Windows 화면 배율 100%·125%·150%에서 접힌 위젯과 펼친 위젯을 확인한다. 교시·긴 과목명·업데이트 버튼·로그인 입력칸의 잘림, 겹침, 첫 표시 후 글자 위치 이동을 확인한다. 합성 과목명과 시험용 업데이트 상태를 사용한다.
- 위젯에서 본창 열기와 목적 메뉴 이동, 기존 창 재사용, 로그인 전 개인정보 잠금, 위젯의 직접 업데이트 버튼 동작을 함께 검증한다.
