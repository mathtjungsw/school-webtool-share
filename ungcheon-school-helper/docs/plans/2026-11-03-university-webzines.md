# 대학 웹진(아로리) 탭 상세 개발계획

- 작성일: 2026-11-03
- 현재 단계: **3. 초기 테스트버전 개발·검증**. [개발·검증 기록](../testing/2026-11-03-preview.md)의 구현 범위와 미확인 항목을 함께 확인한다.
- 통합 계획: [진학·대입 및 독서교육 탭 통합 상세 개발계획](2026-11-03-admissions-reading-tabs.md)
- 사용자 요구: 상단에서 대학을 선택해 같은 본문에서 웹진을 읽고, 기본 화면은 서울대 아로리로 하며 외부 브라우저에서도 열 수 있게 한다.
- 이 문서는 구현 범위와 검증 기준이다. 시안은 실제 사이트 화면과 제안 UI를 조합한 이미지이며, 실행 가능한 테스트버전이나 Electron 표시 검증 결과가 아니다.

## 1. 메뉴와 화면 구성

```text
진학·대입
  ├ 대학 권장과목
  ├ 웅천고 생기부 생성 도우미
  └ 대학 웹진(아로리)

[대학 웹진(아로리)]                 [새로고침] [기본 브라우저로 열기 ↗]
[서울대] [성균관대] [고려대] [한양대] [아주대] [단국대] …
서울대학교 · 아로리 · 입학 안내          snuarori.snu.ac.kr
┌────────────────────────────────────────────────────┐
│ 현재 선택한 대학의 공식 웹진 원본 화면              │
└────────────────────────────────────────────────────┘
```

- 새 메뉴 ID는 `university_webzines`로 정한다. 기존 `admissions` 모임 아래에 추가하며 대학별 사이드바 메뉴는 만들지 않는다.
- 상단 대학 버튼과 도구 버튼은 사이트 본문과 분리해 표시한다. 사이트를 스크롤해도 대학 선택과 외부 열기를 사용할 수 있게 한다.
- 대학 버튼은 기본 창에서 두 줄 이내로 배치하는 것을 우선한다. 폭이 줄면 줄바꿈하고, 본문은 남은 높이를 사용한다.
- 서울대 버튼에 초기 선택 상태를 표시한다. 선택은 배경·테두리·텍스트 상태와 접근성 속성으로 구분한다.
- 사이트명과 성격을 표시한다. 대학 입학 안내, 대학 종합 웹진, 온라인 매거진, 부서 발행 웹진을 모두 입학전형 안내로 표현하지 않는다.

## 3. 선택·전환 동작

1. 앱 실행 후 이 탭에 처음 들어오면 `snu_arori`를 선택하고 아로리를 불러온다. 앱 시작 자체로 사이트를 미리 열지 않는다.
2. 다른 대학 버튼을 누르면 버튼 선택, 대학·웹진명, 유형, 로딩 안내, 외부 열기 대상이 함께 바뀐다.
3. 전환 중에는 이전 대학 화면을 새 대학 화면으로 잘못 보이지 않게 가리고 로딩 상태를 표시한다. 주소·실패 이벤트가 선택한 대학에 해당하는지 대조한다.
4. 대학을 빠르게 연속 선택하면 마지막 선택을 기준으로 처리한다. 이전 요청의 지연 응답이 현재 대학·상태 표시를 덮어쓰지 않게 한다.
5. 이미 선택한 대학 버튼을 다시 눌러도 새로고침하지 않는다. 새로고침은 명시적인 도구 버튼에서만 수행한다.
6. 다른 앱 메뉴를 다녀오면 같은 앱 창에서는 마지막 선택과 페이지를 유지한다. 앱을 종료하고 새로 실행하면 기본 선택은 다시 서울대다. 이를 위한 서버 저장은 추가하지 않는다.
7. 다른 대학으로 전환했다가 돌아올 때는 해당 대학의 공식 진입 화면을 연다. 대학별 전체 문서·스크롤·입력 상태를 각각 메모리에 보관하는 기능은 이번 범위에 넣지 않는다.
8. 앱 상단 뒤로 가기는 기존 메뉴 이동 기록을 따른다. 대학 버튼 선택마다 앱 메뉴 기록을 추가하지 않는다.

## 4. 본문 표시와 외부 열기

- 대학별 프레임 정책과 이북 동작 차이에 대응하기 위해 **웹진 탭 전용 `WebContentsView` 한 개**를 만들어 대학 선택에 따라 주소를 바꾸는 방식을 기본으로 계획한다.
- 통합 계획의 웅천 서가 웹 보기 관리 모듈을 재사용하되, 웹진과 서가의 콘텐츠·선택·세션은 분리한다. 학교별 열 개의 웹 보기를 만들지 않는다.
- 전용 `persist:university-webzines` 세션을 사용하고 앱 preload를 주입하지 않는다. `sandbox`, `contextIsolation`, `webSecurity`를 유지하고 Node 접근을 끈다. 실제 기준 Electron 버전에서 지원 여부를 확인한다.
- 본문 크기 관찰, 사이드바 애니메이션·창 크기·배율 변화, 앱 팝업에 따른 숨김·복원, 종료 정리는 통합 계획의 동일한 수명주기 기준을 적용한다.
- 메인 프로세스는 `university_webzines`와 등록된 site ID만 받는다. 렌더러에서 임의 URL을 전달받아 여는 범용 브라우저 IPC를 만들지 않는다.
- `기본 브라우저로 열기`는 현재 선택 대학의 검증된 HTTPS 페이지를 연다. 실제 표시 주소가 허용한 기사·이북 주소이면 그 주소를 사용하고, 로딩 중이거나 허용 범위를 벗어나면 해당 대학의 등록 진입 주소를 사용한다.
- 브라우저로 열면서 앱의 쿠키·로그인·학생 자료·API 키를 자동 복사하지 않는다. 동일한 로그인 상태가 유지된다고 보장하지 않는다.
- 등록된 공식 사이트의 정상 기사 이동과 공식 외부 이북 리디렉션은 검증해 허용한다. 임의 외부 링크는 사용자 클릭에 따라 브라우저로 열고 앱 본체를 덮어쓰지 않게 한다.
- 일부 사이트가 앱 내부에서 제한되면 원인과 브라우저 열기를 제공한다. 보안 헤더 제거·서버 프록시·사이트 복제본으로 우회하지 않는다.

## 5. 로딩·오류·권한·비용

- 상태는 `방문 전 / 로딩 / 표시 / 지연 / 실패`로 나눈다. 실제 로딩 성공도 사이트의 모든 기능 검증 성공과는 구분한다.
- 약 15초 지연 시 사이트 이름과 수동 재시도·브라우저 열기를 안내한다. 자동 반복 재접속을 추가하지 않는다.
- 오프라인, TLS·네트워크 오류, 접근 제한, 웹 프로세스 종료를 구분할 수 있는 범위에서 처리하고 다른 대학 선택·앱 메뉴 이용은 유지한다.
- 대학별로 정확한 호스트와 필요 경로를 등록한다. 모든 대학 도메인·Google 전체·임의 HTTPS를 일괄 허용하지 않는다. 공식 연결된 외부 이북·블로그 대상은 확인 근거를 남긴다.
- 웹진 열람에는 앱 API 키를 사용하지 않는다. API 키·학번·이름·학생부를 대학 사이트에 자동 전달하거나 로그·서버에 저장하는 기능을 추가하지 않는다.
- 현재 선택한 사이트만 로딩하며 기존 HTTP 캐시를 재사용한다. 다른 대학 사전 로딩, 뉴스 본문 수집, 백그라운드 크롤링, 전체 자료 다운로드, 주기적 새 글 확인을 추가하지 않는다.
- 추가 서버·DB·유료 API는 필요하지 않다. 외부 사이트의 네트워크·영상·이북 트래픽과 기기 메모리는 사용할 수 있으며 사용량을 측정하지 않은 상태에서 비용 0을 보장하지 않는다.

## 8. 테스트·배포·시안 구분

- 통합 계획의 정식판과 분리된 테스트 프로필·앱 식별자·업데이트 제외 정책을 그대로 적용한다.
- 이번 시안은 서울대가 선택된 기본 상태를 보여준다. 상단 대학 선택 버튼의 설계와 실제 아로리 사이트 캡처를 합친 이미지다.
- 실제 테스트버전 개발 시에는 같은 기본 상태와 다른 대학을 선택한 상태를 각각 캡처한다. 이번 시안이 모든 대학의 Electron 연결 검증을 대신하지 않는다.
- 정식 반영 및 배포는 후속 4단계에서 수행한다. 기존 생기부·서가·권장과목 이동과 함께 검사·패키징·Release 결과를 기록한다.
