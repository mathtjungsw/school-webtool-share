# 평균내신등급 산출기 상세 개발계획

- 작성일: 2026-11-03
- 현재 단계: **3. 초기 테스트버전 개발·검증**. [개발·검증 기록](../testing/2026-11-03-preview.md)의 구현 범위와 미확인 항목을 함께 확인한다.
- 통합 계획: [진학·대입 및 독서교육 탭 통합 상세 개발계획](2026-11-03-admissions-reading-tabs.md)의 여섯 번째 개선 항목.
- 기준 요구사항: [누적 개선계획](../IMPROVEMENT_PLAN.md)의 평균내신등급 산출기 및 로컬 저장자료 비우기.
- 입력 구조 근거: [제공 PDF·XLSX 및 나이스 화면 확인 메모](../research/2026-11-03-average-grade-samples.md). 원본 학생 자료는 문서·저장소·설치파일에 포함하지 않는다.
- 이 문서는 설계 기준이다. 별도 테스트버전에서 로컬 산출기를 구현했다. 실제 성적의 전수 대조와 정식 배포는 아직 수행하지 않았다.

## 1. 기능 범위와 메뉴

[공통 로그인 상세계획](2026-11-03-staff-password-login.md)을 함께 적용한다. 최초 로그인·앱 시작의 세션 검증에는 연결이 필요하며, 인증된 실행 세션에서 이 기능의 자료 판독·계산·보관·삭제는 오프라인으로 수행한다. 성적 자료는 인증 서버에 보내지 않는다. 오프라인 검사는 유효한 일반 인증 상태에서 기능 자체의 외부 통신이 없는지 확인한다.

`진학·대입 > 평균내신등급 산출기`를 추가한다. 메뉴 ID는 `average_grade_calculator`, 검색 별칭은 `평균 내신`, `평균내신등급`, `내신 계산`, `학생부 등급`, `교과학습발달상황`으로 정한다. 기존 성취도 분포 기능인 `성적 산출 미리보기`와 별도 기능으로 안내한다.

필수 범위는 PDF·XLSX 가져오기, 학생·학기별 성적 확인, 두 가지 반영 교과 선택, 학점 가중평균 표시, 로컬 저장·재실행 복원, 저장자료 비우기, 나이스 다운로드 안내이다. 대학별 환산식·진로선택 가산점·상위 N과목·AI 상담·외부 성적 전송·새 클라우드 백업은 추가하지 않는다.

## 2. 화면 구성과 이용 순서

```text
평균내신등급 산출기              [나이스 다운로드 안내] [산출기 저장자료 비우기]
자료 읽기·계산·저장은 이 PC에서 처리합니다.

[학생부 올리기 · PDF]             [교과학습발달사항 올리기 · XLSX]
불러온 파일 / 읽는 중·확인 필요·완료 / 학생 수 / 추가 가져오기

반영 교과  (●) 전교과 평균 등급  ( ) 국어·영어·수학·과학·사회 평균 등급
계산 범위  [전체 학년·학기 기본]  학생 선택 / 등급 체계 표시

학생 목록·검색             선택 학생 결과
학생 / 처리 상태           평균 등급 / 반영 학점 / 반영 과목 / 제외·확인 필요 수
                           학년·학기별 결과 / 실제 분자·분모 / 저장 상태
                           [반영 과목] [제외 과목] [확인 필요]
                           교과 / 과목 / 학년·학기 / 학점 / 석차등급 / 반영 사유 / 출처
```

1. 최초에는 빈 화면과 두 가져오기 버튼을 표시한다. 초기 반영 교과는 `전교과`, 학년·학기 범위는 `전체`이다.
2. 사용자가 파일을 선택하면 확장자·내용·크기를 확인하고 로컬에서 판독한다. PDF와 XLSX는 여러 파일을 순차 처리할 수 있으며 파일별 취소와 오류를 표시한다.
3. 학생별 구분, 교과 분류, 등급 체계, 학점·등급을 검증한다. 불확실한 행은 `확인 필요`에 모으고 완성된 결과와 구분한다.
4. 사용자가 확인을 마치면 학생별 전체 결과와 학년·학기별 결과를 표시한다. 선택 범위를 바꾸면 같은 원자료로 다시 계산하며 파일을 다시 읽거나 서버에 조회하지 않는다.
5. 판독한 최소 성적 자료와 검토 상태·사용자가 확인한 수정사항을 자동 저장한다. `확인 필요` 자료는 상태를 유지해 재실행 후 검토를 이어가되 확정 결과에는 섞지 않는다. 저장 성공 후에만 `이 PC에 저장됨`을 표시한다. 저장 실패 시 `저장되지 않음`과 재시도를 제공하고 메모리의 자료는 유지한다.
6. 앱 재실행 시 이 기능의 로컬 자료만 복원한다. 시험판과 정식판 자료를 자동으로 합치지 않는다.

결과 기본 표시는 소수 둘째 자리이며 표시 직전에 반올림한다. 미확인 행이 결과에 영향을 줄 수 있으면 숫자에 `확인 전 임시 결과`를 붙인다. 원본과 대조해 필요한 필드만 수정할 수 있게 하고 원래 값·수정 값·원본 위치를 로컬에 함께 남긴다. 실제 학생 자료는 공개 시안·오류 화면 예시에 사용하지 않는다.

## 3. 계산 규칙

### 3.1 동일한 과목 집합으로 분자·분모 계산

반영 교과, 학생, 학년·학기, 등급 체계, 검증 상태에 맞는 과목 집합을 먼저 만든다. 그 집합에서 유효한 숫자 석차등급과 양수 학점이 있는 과목만 계산한다.

`평균내신등급 = Σ(학점 × 석차등급) / Σ(학점)`

- 학점은 파일의 `학점`, 또는 해당 서식의 `단위수·이수단위` 열을 읽고 원래 표제를 보존한다. 숫자 문자열을 엄격히 파싱하며 빈칸·0·음수·비수치·무한값은 유효한 학점으로 보지 않는다. 소수 학점도 허용한다.
- 석차등급은 등급 체계에 맞는 양의 정수만 허용한다. 빈칸, `·`, `-`, P, A/B/C 등은 숫자 등급으로 환산하지 않는다. `2(공동)` 같은 별도 표기는 확인 없이 2로 잘라 읽지 않는다.
- 등급이 없는 과목은 분자·분모에서 함께 제외한다. 등급은 있으나 학점이 잘못된 행은 확인 대상으로 표시하고 완성 결과로 확정하지 않는다. 학점 기본값 1을 대입하지 않는다.
- 과목 유형이 진로선택·체육·예술이라는 이유만으로 제외하지 않는다. `전교과`에서는 유효한 석차등급·학점이 있으면 같은 규칙을 적용한다.
- 반영 학점 합이 0이면 `산출 불가 — 반영할 석차등급 과목이 없습니다`를 표시한다. 등급 0으로 표시하지 않는다.
- 중간 학기 평균이나 과목 평균을 반올림해 재사용하지 않는다. 학점을 공통 소수 자릿수로 정수화하는 등의 방식으로 합계를 정확히 유지하고 마지막 표시에서만 반올림한다.
- 전체 결과는 모든 선택 과목의 가중합으로 계산한다. 학년별 평균·학기별 평균의 단순 평균을 사용하지 않는다.

합성 검증 예: 3학점·2등급과 2학점·4등급은 `(3×2 + 2×4) ÷ 5 = 2.80`. 여기에 석차등급이 없는 2학점 과목을 추가해도 2.80을 유지한다.

### 3.2 두 가지 반영 교과

| 선택 | 반영 원칙 |
| --- | --- |
| 전교과 평균 등급 · 기본 | 교과 이름과 관계없이 유효한 학점·석차등급이 있는 모든 과목 |
| 국어·영어·수학·과학·사회 평균 등급 | 원래 교과(군)를 아래 매핑으로 정규화한 다섯 군의 유효 과목 |

| 원본 교과(군) | 기본 매핑 |
| --- | --- |
| 국어 / 영어 / 수학 / 과학 / 사회 | 같은 이름의 군 |
| 사회(역사/도덕 포함), 띄어쓰기·괄호 표기 차이 | 사회 |
| 체육·예술·기술가정·제2외국어·한문·교양 등 명확한 다른 군 | 다섯 교과 방식에서 제외. 전교과에서는 등급·학점 기준 적용 |
| 별도 `한국사` 군, 융합·전문 교과, 교과(군) 누락 등 | 다섯 교과 방식에서 분류 확인 필요. 과목명만으로 자동 편입하지 않음 |

한국사가 원본에서 `사회(역사/도덕 포함)`에 속하면 사회로 반영한다. 별도 `한국사` 군으로 들어오면 원본 군과 과목을 보여주고 사용자가 사회 포함 여부를 확인한 뒤 적용한다. 같은 입력 묶음에 대한 분류 확인은 재사용하고 결과 화면에 적용 기준을 표시한다. 이는 대학별 반영 규칙을 가정한 자동 보정이 아니다.

### 3.3 등급 체계와 계산 범위

- 5등급제·9등급제는 원본의 교육과정·학년도 등 확인 가능한 정보로 구분한다. 모든 관측 등급이 5 이하라는 이유만으로 5등급제로 추정하지 않는다. 근거가 없으면 사용자가 확인한다.
- 서로 다른 등급 체계는 별도 결과로 표시한다. 단순 합산하거나 임의 환산해 하나의 평균으로 만들지 않는다.
- 동일 학생의 여러 학년·학기는 기본 `전체`로 합산한다. 사용자가 학년·학기를 한정하면 반영 범위를 결과에 명확히 표시한다. 학년도와 재학 학년은 다른 필드로 다룬다.
- 표시값은 사용자가 요청한 일반 가중평균이며 대학별 공식 환산점수로 표현하지 않는다.

## 4. PDF 판독 설계

1. 사용자 선택 파일을 로컬 바이트로 읽고 PDF 형식·암호화·쪽 수를 점검한다. 텍스트와 글자 좌표는 번들에 포함한 PDF 파서로 추출한다. 폰트·CMap·worker 등 필요한 자산도 로컬에 포함한다.
2. 학교생활기록부의 학생 시작 구간과 교과학습발달상황의 시작·끝을 구분한다. 인적사항 전체나 세특·행동특성 텍스트를 성적 데이터로 저장하지 않는다.
3. 표마다 학년·학기·교과·과목·학점·석차등급 머리글의 위치를 찾아 열을 설정한다. 기존 파서의 단일 고정 x좌표·한 자리 학점 조건을 그대로 복제하지 않는다.
4. 페이지 이어짐과 반복 머리글을 처리한다. 위 행 값 계승은 동일 학생·동일 표의 병합·반복 생략이 확인된 열에서만 허용한다. 다음 학생·다른 표·요약 행으로 넘어가면 계승 상태를 초기화한다.
5. 학생·학년·학기 경계가 확실하지 않거나 학점과 등급 열을 구분할 수 없으면 확정하지 않는다. 원본 쪽 번호·표 위치와 확인 사유를 남긴다.
6. 처음에는 제공한 텍스트형 나이스 PDF를 필수 지원 대상으로 삼는다. 이미지형 PDF는 온라인 OCR로 넘기지 않고 `텍스트형 학생부 PDF 또는 나이스 XLSX DATA 파일이 필요합니다`로 안내한다. 오프라인 OCR 확대는 별도 요구가 있을 때 검토한다.

암호화 PDF는 암호를 영구 저장하지 않는다. 테스트판의 필수 범위는 암호화되지 않은 예시 서식이며, 지원하지 않는 암호화 서식은 사유를 표시한다. 기존 외부 AI 분석·범용 추출 경로를 실패 시 자동 호출하지 않는다.

## 5. XLSX DATA 판독 설계

1. `.xlsx` 확장자뿐 아니라 ZIP/OOXML 내용도 확인한다. 매크로 실행·외부 링크 업데이트·수식 실행은 하지 않는다. 필요한 값이 수식에만 있거나 캐시가 없어 읽을 수 없으면 확인 대상으로 표시한다.
2. 제공 자료에서 확인된 잘못된 사용 영역 선언 `A1`에 대응한다. 실제 존재하는 셀과 표 머리글을 제한된 범위 안에서 확인해 실제 영역을 구성한다. 선언된 범위만 보고 빈 파일이라고 판단하지 않는다.
3. 시트별로 `학년·학기·교과·과목·학점·석차등급` 등의 머리글을 찾는다. 반복된 머리글에서 매핑을 다시 만들고 석차등급 없는 성취도 표를 구분한다. 고정 G/K열만 읽지 않는다.
4. 번호·성명과 문서의 학급 정보를 이용해 학생을 구분한다. 소속 학급이 파일에서 확인되지 않으면 사용자 확인을 받아 가져오기 묶음의 맥락으로 저장한다. 이름이나 반 번호 하나만으로 서로 다른 파일의 학생을 합치지 않는다.
5. 빈칸 계승은 같은 학생·표의 반복 생략으로 확인된 식별·학기·교과 열에만 적용한다. 과목·학점·석차등급은 이전 행 값을 무조건 복사하지 않는다. 병합 셀·반복 표·표 사이 공백에서 경계를 검증한다.
6. 합계·비고·반복 인쇄 제목·세특 등 장식과 서술 행을 성적 행에서 제외한다. 읽은 성적 수·확인 필요 수·등급 없는 과목 수를 구분해 표시한다.
7. 여러 시트·여러 학생을 순차 처리하며 한 시트 실패가 다른 정상 자료를 지우지 않게 한다. 지원되지 않는 서식은 파일·시트 단위 오류로 안내한다.

현재 설치된 `xlsx`와 정식 기준 버전의 파서를 먼저 대조한다. 최신 공식 문서의 `nodim` 같은 옵션이 현재 설치 버전에도 있다고 가정하지 않는다. 실제 셀 확인 또는 검증한 지원 버전의 옵션으로 대응하고 회귀검사를 붙인다. 읽기 옵션의 근거는 [SheetJS 공식 읽기 문서](https://docs.sheetjs.com/docs/api/parse-options/)이다.

## 6. 학생 병합·중복·수정

- 가져오기 묶음과 학생에 로컬 ID를 부여한다. 원본 식별정보는 표시·대조에 필요한 범위만 저장하고 주민등록번호·주소·전화번호는 수집하지 않는다.
- 같은 파일의 재가져오기는 로컬 파일 해시로 감지한다. 이미 처리된 파일은 다시 더하지 않고 기존 자료 보기 또는 확인 후 교체를 제공한다.
- PDF·XLSX 간 병합은 학교·학생 맥락과 학년·학기 정보를 대조한 뒤 확인한다. 이름 일치만으로 자동 병합하지 않는다. 학생별 문서 경계가 모호하면 분리를 먼저 확인한다.
- 성적 충돌은 학생 ID·학년도(알 수 있을 때)·재학 학년·학기·교과·과목·이수 구분을 기준으로 찾는다. 같은 키·같은 값은 한 번만 반영하고 두 출처를 연결한다. 학점·등급이 다르면 어느 값을 사용할지 확인받는다. 실제로 다른 이수 건을 단지 과목명이 같다는 이유로 제거하지 않는다.
- 사용자가 고친 값은 원본 값과 분리해 기록한다. 재가져오기가 수정사항을 몰래 덮어쓰지 않게 한다. 수정 후 모든 관련 합계·상태를 다시 계산한다.

## 7. 데이터 구조와 저장

| 구조 | 저장 필드 |
| --- | --- |
| 가져오기 묶음 | 로컬 ID, 파일 형식, 경로를 제외한 표시 파일명, 로컬 해시, 처리 상태, 필요한 학급 맥락 |
| 학생 | 로컬 ID, 필요한 이름·학급·번호, 동일인 확인 상태 |
| 과목 성적 | 학생 ID, 학년도/학년/학기, 원본 교과·과목, 정규화 군, 학점·석차등급, 등급 체계, 검증·수정 상태 |
| 출처 | 가져오기 ID, PDF 쪽·표 위치 또는 XLSX 시트·행·셀 위치. 전체 원문은 저장하지 않음 |
| 화면·기준 | 두 교과 방식, 선택 학년·학기, 사용자가 확인한 교과 분류, 계산 규칙 버전 |
| 파일 머리정보 | 스키마 버전, 암호화 형식 버전, 저장 세대. 학생 정보는 암호문 내부에만 보관 |

- 저장 위치는 Windows `LocalAppData` 아래 앱의 `private/average-grade/v1` 전용 범위로 정한다. 공통 `electron-store` 설정, 학교 공유 캐시, OneDrive·MYBOX·문서 폴더에 저장하지 않는다. 프리뷰는 별도 앱 경로를 사용한다. 비정상 리디렉션·경로 사용 불가 시 임의 공유 경로로 대체하지 않는다.
- 원본 PDF·XLSX와 전체 추출 텍스트는 기본적으로 복사·저장하지 않는다. 판독 중 메모리에서만 사용하고 작업 완료·취소 시 참조를 해제한다. 다시 원본을 대조할 때에는 사용자가 파일을 다시 선택한다.
- 정규화 자료와 검토 상태는 로컬 암호화 파일로 저장한다. 무작위 자료 키로 인증 암호화를 적용하고 자료 키는 기준 Electron에서 지원하는 Windows OS 보호 API로 감싼다. 암호화 불가 시 평문으로 조용히 전환하지 않고 메모리에서 계산을 계속하며 저장 불가 사유를 표시한다.
- Windows의 OS 암호화는 같은 Windows 계정으로 실행하는 다른 프로그램까지 모두 차단하는 장치가 아니다. 앱 로그인 이름만 바꾸면 완전히 다른 보안 주체가 된다고 안내하지 않는다. API 호환성과 보안 범위는 [Electron safeStorage 공식 문서](https://www.electronjs.org/docs/latest/api/safe-storage)와 실제 기준 버전으로 검증한다. 최신 문서의 새 API를 현재 버전에 무조건 적용하지 않는다.
- 저장은 변경이 있을 때만 지연 병합하며, 암호화된 임시 파일 작성 → 검증 → 원자적 교체 순서로 한다. 새 스냅샷을 쓰려고 전체 공유 DB를 읽지 않는다. 영구 파생 결과는 최소화하고 필요 시 원자료에서 다시 계산한다.
- 저장 중단·손상·복호화 실패는 빈 자료로 덮어쓰지 않는다. 오류를 표시하고 `자료 비우기`로 해당 기능을 초기화할 수 있게 한다. 복호화되지 않은 파일을 외부 오류 수집에 첨부하지 않는다.
- 스키마 마이그레이션이 필요하면 이 전용 범위 안에서만 수행한다. 이전본·임시본 역시 암호화하며 자료 비우기 대상에 포함한다. 공통 앱 백업·진단 첨부·동기화 대상에는 이 경로를 포함하지 않는다.

## 8. 로컬 전용 실행과 외부 전송 차단

### 8.1 독립 화면·제한된 API

- 메인 앱에는 `AverageGradeCalculatorPage.tsx`를 메뉴와 본문 자리로 연결한다. 실제 자료를 표시하는 화면은 번들에 포함한 별도 React 진입점과 전용 `WebContentsView`로 구성한다. 학생 자료를 앱의 공통 전역 상태·검색 인덱스에 올리지 않는다.
- 계산기 전용 비영구 세션과 preload를 사용한다. 기본 앱 세션·외부 생기부 사이트·대학 웹진과 저장소를 공유하지 않는다. `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`, `webSecurity: true`를 적용한다.
- 전용 preload는 파일 선택·선택 파일 바이트 읽기·이 기능의 저장/불러오기/삭제·취소·상태만 노출한다. 앱 전체 `config:getAll`, AI·학교 서버 요청, 임의 경로 읽기·쓰기, 임의 URL 열기 API는 제공하지 않는다.
- 파일 선택에서 발급한 유효 기간이 있는 로컬 토큰으로 읽기를 제한한다. 사용자가 선택한 파일 외의 경로를 렌더러 문자열로 받아 읽지 않는다. 폴더 전체 자동 검색도 하지 않는다.
- IPC는 계산기 자신의 신뢰한 최상위 프레임·webContents ID·요청 스키마·파일 크기·작업 세대를 확인한다. 외부 프레임이나 메인 앱의 일반 화면에서 성적 저장/불러오기 채널을 직접 호출하면 거부한다.
- 메인 앱과는 활성 상태·본문 좌표·테마·팝업 가림 상태만 공유한다. 학생 이름·성적·파일 경로·실제 결과를 웹 보기 관리 이벤트에 넣지 않는다. 공통 뷰 관리자 재사용 시 자료 전달 API는 별도로 제한한다.

### 8.2 네트워크·자산·로그

- 전용 세션은 패키지 내부 계산기 자산만 허용하고 HTTP(S)·WebSocket·외부 탐색·새 창·원격 폰트·CDN·원격 이미지 요청을 차단한다. CSP에도 연결 금지와 로컬 스크립트·worker만 허용하는 규칙을 적용한다. 개발 모드의 로컬 개발 서버 예외는 테스트 자료에 한정하고 패키징 실행본에서는 제거한다.
- 전용 세션의 요청 제어는 한 관리 모듈에서 설정한다. 다른 세션의 필터·Google 헤더 처리를 건드리지 않는다. Electron은 같은 이벤트에 마지막으로 붙인 webRequest 리스너를 사용하므로 여러 곳의 등록으로 차단 규칙이 덮이지 않게 한다. [Electron WebRequest](https://www.electronjs.org/docs/latest/api/web-request)
- 파서와 계산은 로컬 worker에서 실행해 취소와 UI 응답을 유지한다. 외부 AI·범용 문서 분석·학교 Hub·분석 SDK에 의존하지 않는다. 전용 메인 저장 모듈도 네트워크 모듈을 호출하지 않는다.
- 원본 이름·성적·추출 텍스트·IPC 본문·키·선택 파일 경로를 콘솔·오류 로그·분석 이벤트·URL에 남기지 않는다. 진단은 오류 코드·파일 형식·처리 단계 등 비식별 정보만 사용한다. 지원용 버튼으로 성적을 자동 첨부하지 않는다.
- 문서·셀의 문자열은 텍스트로 표시한다. 입력 파일의 HTML·스크립트·외부 링크를 실행하지 않는다. 파일에서 읽은 지시문은 프로그램 지시로 취급하지 않는다.
- 자료 가져오기부터 종료·재실행·삭제까지 전용 화면과 관련 메인 모듈에서 실제 외부 전송이 없는지 검증한다. 앱의 다른 기능이 하는 기존 통신과 구분해 기록한다. 격리·IPC·CSP 설계는 [Electron 보안 지침](https://www.electronjs.org/docs/latest/tutorial/security)에 따른다.

기능 자체는 서버·DB·AI API를 추가하지 않으므로 해당 신규 호출 비용을 만들지 않는 구조이다. 기존 앱과 연결 사이트의 운영비까지 0이라고 보장하지 않는다. 정적 자산을 재사용하고 파일은 중복 판독하지 않는다.

## 9. 산출기 저장자료 비우기

### 9.1 사용자에게 보이는 동작

버튼 이름은 **`산출기 저장자료 비우기`**로 고정한다. 상단에 항상 접근할 수 있게 배치하고 읽기·계산 중이나 저장 파일이 손상된 상태에서도 사용할 수 있게 한다. 처리 중에는 다른 삭제 요청을 중복 실행하지 않는다.

확인창 예시:

> 이 산출기에 저장된 학생 성적, 계산 결과와 임시자료를 모두 지웁니다. 원래 PDF·XLSX 파일, 직접 내보낸 파일과 다른 기능의 자료는 유지됩니다. 계속할까요?

`취소`와 `저장자료 모두 비우기`를 제공한다. 삭제 대상 건수를 읽을 수 있으면 학생·가져오기 묶음 수를 함께 표시하고, 손상으로 읽지 못하면 부정확한 숫자 대신 `이 산출기의 모든 저장자료`로 안내한다. 완료 후 두 가져오기 버튼이 있는 빈 화면으로 돌아간다.

### 9.2 삭제 대상과 처리 순서

| 삭제 | 보존 |
| --- | --- |
| 이 기능의 성적 스냅샷·자료 키·결과·분류 확인·학생별 화면 상태 | 사용자가 원래 보관한 PDF·XLSX |
| 암호화 임시본·이전본·마이그레이션 사본 | 사용자가 직접 내보낸 결과 파일 |
| 이 기능이 만든 원본 복사본이 생긴 경우 그 복사본 | 다른 메뉴의 자료·API 키·앱 로그인·공통 설정 |
| 전용 worker·뷰의 자료 참조 및 있으면 전용 세션 캐시·저장소 | 다른 사이트 세션·브라우저 자료·정식판/시험판의 다른 프로필 |

1. 삭제 확인 후 새 가져오기·계산·저장을 잠그고 삭제 중임을 표시한다.
2. 개인정보 없는 정리 진행 표식을 전용 관리 범위에 기록하고 작업 세대를 바꾼다. 대기 중 저장도 같은 잠금·세대 검사로 폐기한다.
3. 진행 중인 worker를 취소·종료하고 파일 핸들·객체 URL·메모리 참조를 해제한다. 이전 세대의 비동기 완료 응답은 표시하거나 저장하지 않는다.
4. 저장 잠금 아래에서 전용 데이터·키·임시/이전 파일을 삭제한다. 고정 전용 루트를 절대경로로 검증하고 경로 이탈·junction 등 예상 밖 연결을 거부한다. 렌더러가 임의 삭제 경로를 전달할 수 없게 한다.
5. 계산기 전용 세션의 자료 저장소·캐시만 정리하고 뷰를 새로 만든다. 전역 `localStorage.clear()`, 기본 세션 전체 정리, 앱 `userData` 전체 삭제는 하지 않는다.
6. 전용 저장자료가 남지 않았는지 확인한 뒤 정리 표식을 해제하고 `산출기 저장자료를 비웠습니다`를 표시한다. 기본 교과 방식·전체 학기 선택으로 초기화한다.
7. 파일 잠금·권한 오류 등이 있으면 `일부 자료를 지우지 못했습니다`와 재시도를 표시한다. 삭제 미완료 자료를 다시 읽거나 새 저장으로 섞지 않는다. 삭제 도중 앱이 종료되면 다음 실행에서 표식을 확인해 정리부터 재개한다.

원본 선택 경로와 내보낸 파일 경로는 삭제 입력으로 사용하지 않는다. 삭제는 이 기능이 관리하는 범위의 논리적 삭제이며 SSD·운영체제 백업까지 포함한 완전한 복구 불가 삭제로 표현하지 않는다.

## 10. 나이스 다운로드 안내

- 두 번째 업로드 카드에 `나이스 XLSX DATA 파일 받는 방법`을 연결한다. 학생부 PDF 업로드 설명과 구분한다.
- 안내 순서: 학교생활기록부 → 학생부 항목별 조회 → 교과학습발달상황 → 학년도·학년·반 선택 → 조회 → 뷰어 저장 메뉴 → XLSX DATA 형식 선택 → 내려받은 `.xlsx` 선택.
- 제공 캡처에서 확인한 조회 조건·왼쪽 메뉴·저장 아이콘을 표시한다. 저장 메뉴 내부 옵션의 실제 이름은 보이지 않으므로 시험 단계에서 대조해 문구를 확정한다. 검증 전에는 추정한 드롭다운 화면을 실제 캡처처럼 제시하지 않는다.
- 안내 이미지는 개인정보를 가린 별도 사본으로 제작하고 최종 화면을 직접 확인한다. 원본 파일을 덮어쓰지 않으며 공개 자산에는 교직원·학생 정보가 남지 않게 한다. 잘 보이도록 메뉴·조회 조건·저장 도구를 나눠 확대할 수 있게 한다.
- 엑셀 인쇄용 그림·PDF와 XLSX DATA가 다름을 설명하고, 불러오기 실패 시 해당 DATA 파일인지 확인하도록 안내한다. 자료가 로컬에서 처리되며 저장자료 비우기는 원본을 지우지 않는다는 설명도 함께 제공한다.

## 11. 오류·처리량·접근성

- 파일별 상태는 `대기 → 읽는 중 → 확인 필요/완료/실패/취소`로 구분한다. 학생별로도 확정·미확정 상태를 유지해 파일 일부 성공을 전체 성공으로 표시하지 않는다.
- 초기 제한안은 PDF 한 개 100MiB·500쪽, XLSX 한 개 30MiB·실제 셀 범위 20만 행, 한 번 선택 10개이다. XLSX 압축 해제량은 256MiB 안에서 제한한다. 시험판 실측으로 조정할 수 있으나 초과 자료를 몰래 잘라 계산하지 않는다. 예상 범위를 넘으면 분할 안내를 제공한다.
- 거대한 사용 영역 선언만으로 메모리를 할당하지 않는다. worker 순차 처리·취소·단계별 진행 표시를 적용하고 대용량 파일이 메인 UI를 멈추지 않게 한다.
- 테이블은 검색·행 단위 렌더링으로 필요한 부분만 표시한다. 선택 변경 시 파일 재판독·디스크 저장을 반복하지 않고 계산용 원자료를 재사용한다.
- 900×600, 최대화, 밝은/어두운 모드, 키보드 이동·확인창 초점 복원·스크린리더 이름을 확인한다. 삭제 상태를 색만으로 표현하지 않는다. 앱 공지·검색·업데이트 팝업이 뜨면 전용 뷰를 숨겨 가리지 않게 한다.

## 15. 테스트버전·정식 반영·복구

- 테스트판은 최신 기준 버전을 확인한 뒤 별도 preview 식별자·LocalAppData 경로·출력 경로로 패키징한다. 정식 자동업데이트에 게시하지 않고 실제 학생 자료를 설치파일에 포함하지 않는다.
- 제공물은 Windows 실행본, 기준 커밋·버전, 합성 자료 화면, 검증표, 지원하는 입력/미지원 형식, 저장·삭제 범위 설명이다. 시험판 자료를 정식판으로 자동 이전하지 않는다.
- 사용자 확인 순서: XLSX 가져오기 → 학생/학점/등급 확인 → 두 방식 비교 → PDF 가져오기와 중복 확인 → 앱 재실행 복원 → 자료 비우기 취소/실행 → 재실행 빈 화면 → 원본 및 다른 기능 보존.
- 정식 반영·배포 요청 시 최신 소스에 검증 변경만 통합한다. 기준 버전 변경으로 영향을 받는 검사와 AG 필수 항목을 수행하고 메뉴·사용 안내·버전·Release·자동업데이트 게시 결과를 기록한다.
- 복구는 자료 스키마 호환성을 유지한 더 높은 패치 버전으로 수정·되돌림을 제공한다. 기능을 되돌리기 위해 자료를 자동 삭제하지 않으며, 이전판이 새 형식을 읽지 못하면 덮어쓰기 대신 안내한다. 삭제한 자료를 롤백 사본에서 자동 복원하지 않는다.
- 계획 완료 조건은 입력·계산·교과 분류·로컬 격리/저장·삭제·구현 파일·검증·배포/복구 기준의 문서화이다. 실제 개발 완료 조건은 AG-01~18 필수 검증과 Windows 실행본의 실제 동작 확인이다.
