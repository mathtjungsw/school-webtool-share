# 대학 추천도서: 서울대 권장도서 100선 상세 개발계획

- 작성일: 2026-11-03
- 현재 단계: **3. 초기 테스트버전 개발·검증**. [개발·검증 기록](../testing/2026-11-03-preview.md)의 구현 범위와 미확인 항목을 함께 확인한다.
- 통합 계획: [진학·대입 및 독서교육 탭 통합 상세 개발계획](2026-11-03-admissions-reading-tabs.md)
- 참고 조사: [원목록·분류·진로 연계 자료 조사 메모](../research/2026-11-03-recommended-books-sources.md)
- 범위: `독서교육 > 대학 추천도서`의 첫 컬렉션으로 서울대 권장도서 100선을 제공한다. 이번 단계는 계획과 시안이며 앱 구현·전권 콘텐츠 작성·정식 배포 완료를 뜻하지 않는다.

## 1. 메뉴와 핵심 경험

```text
독서교육
  ├ 웅천 서가
  └ 대학 추천도서
      서울대 권장도서 100선
      [제목·저자·주제 검색] [관심 학과] [관심 직업]
      [전체] [한국문학] [외국문학] [동양사상] [서양사상] [과학기술]

      책 카드 목록                  선택한 책 상세
      제목·저자·짧은 소개            어떤 책인가 / 왜 읽을까
      핵심 주제·연결 전공            전공·직업과 연결되는 이유
                                     독서 질문 / 후속 탐구
                                     근거·해설 출처 / 판본
```

- 메뉴 ID: `university_recommended_books`. 일반 사용자 메뉴로 등록하고 기존 고정·숨김·순서·검색 규칙을 따른다.
- 표시명은 기존 `대학 권장과목`과 혼동하지 않도록 `대학 추천도서`로 정한다. 외부 사이트를 띄우는 탭과 달리 기본 화면은 앱 자체의 편집·검토한 도서 정보다.
- 첫 화면에 목록의 선정 맥락과 책을 찾는 경로를 짧게 보여준다. 입학에 유리한 필독서나 특정 전공 진학의 필수 조건으로 표시하지 않는다.
- 다른 대학의 목록이나 AI 추천은 자동 추가하지 않는다. 현재 한 컬렉션이므로 의미 없는 대학 선택 드롭다운은 만들지 않는다.

## 2. 목록과 책 정보 확보

### 2.1 원목록 확정

- 서울대 공식 강좌 소개의 2005년 목록 발표 사실과, 당시 목록·대학 재게시 자료를 대조한다. 출처와 확인 범위는 조사 메모에 기록되어 있다.
- 한국문학·외국문학·동양사상·서양사상·과학기술의 원분류를 보존한다. 이를 학과·직업 태그로 대체하지 않는다.
- 구현 초기에 100개 선정 항목의 제목·저자·원분류·원래 순서·출처를 확정하고 중복·누락·불일치를 검사한다.
- 전집, 선집, 여러 작품을 묶은 항목은 하나의 선정 항목 아래에 실제 작품과 판본을 연결한다. 목록을 임의로 분할하거나 다른 책을 채워 넣어 100개를 맞추지 않는다.
- 출처별 차이가 있으면 원자료를 우선하고 근거를 남긴다. 확인되지 않은 항목은 준비 중으로 관리하고 검증을 완료했다고 표시하지 않는다.

### 2.2 소개와 판본

- 출판사·공공도서관·대학·저자의 공식 소개 등 확인 가능한 자료를 참고해 짧은 해설을 직접 작성한다. 타인의 서평·해제를 대량 복제하지 않는다.
- 목록 카드는 소개 한두 문장과 핵심어 3개를 우선 표시한다. 상세 화면의 설명은 짧은 문단으로 나눈다.
- 작품 단위 정보에는 제목·저자·주제·선정 분류를 저장한다. 출판사·역자·ISBN·출간일·쪽수는 판본 단위로 관리한다.
- 번역본이나 판본이 미확정이면 쪽수·출판사·읽는 시간을 임의로 붙이지 않는다. 난이도·추천 학년·읽기 순서를 제공한다면 판단 근거와 검토 상태를 별도로 갖춘다.
- 첫 시안의 책 디자인은 제목과 색을 활용한 배치 예시다. 특정 출판사의 실제 표지로 오인하지 않게 하며, 실제 표지 사용 시 제공 출처와 사용 범위를 확인한다. 이미지 없이도 기본 정보는 읽을 수 있게 한다.

## 3. 전공·직업 연결과 출처 구분

### 3.1 근거 구분

| 구분 | 저장·표시 기준 |
| --- | --- |
| 원목록 사실 | 선정 목록·원분류·선정 맥락. 원목록 확인 자료에 연결 |
| 외부 자료 확인 | 기관이 특정 책과 전공·직업을 연결한 실제 항목을 직접 대조한 경우. 기관·자료명·쪽/위치·URL·확인일 기록 |
| 탐구 제안 | 책의 주제를 바탕으로 웅천고용으로 작성한 연결·질문·활동. `탐구 제안` 표시와 연결 이유 제공 |
| 미확인 | 출처 접근 불가·상충·내용 미대조. 확인한 사실과 섞지 않고 상태 기록 |

- 대전학생교육문화원 `진로이음도서 목록(전공별)`은 공개 게시글과 첨부 존재를 확인한 상태다. 상세 원문을 확보·대조한 뒤 겹치는 책의 전공 연결만 출처 있는 자료로 등록한다.
- 경기도교육청전자도서관·서초구립도서관의 스쿨북스 안내는 학과·직업별 탐색 방식의 참고다. 안내 페이지만으로 서울대 100선 전체의 진로 매핑을 확보했다고 보지 않는다.
- 직업은 책의 주제와 연결해 생각할 수 있는 탐색 방향이다. 해당 직업의 공식 필독서나 취업 자격 조건으로 단정하지 않는다.
- 책 한 권에 여러 전공·직업을 연결할 수 있으며 각 연결에 짧은 이유를 붙인다. 근거가 약한 직업 연결은 빈 상태를 허용한다.
- 자체 작성한 질문·활동을 서울대 또는 외부 기관의 공식 해설처럼 표시하지 않는다.

### 3.2 상세 구성 예시

『과학혁명의 구조』에 과학사·철학·과학교육을 연결하고, 기존 설명과 새로운 설명을 비교하는 탐구를 제안한다. 연구자·과학교사·과학 커뮤니케이터 등의 직업 연결은 해당 역할에서 질문을 다루는 방식과 함께 제시할 수 있다. 이 문장은 설계 예시이며 서울대의 공식 학과·직업 추천이 아니다.

## 4. 화면과 상호작용

### 4.1 카드와 상세 패널

- 넓은 창에서는 카드 목록과 오른쪽 상세 패널을 나란히 표시한다. 900px 수준에서는 목록 열 수를 줄이고, 더 좁은 화면에서는 상세를 별도 화면 또는 아래 영역으로 전환한다.
- 카드에는 제목·저자·원분류·짧은 소개·핵심어를 표시한다. 전공 태그를 넣으면 `탐구 연결` 등 의미를 함께 보여준다.
- 카드를 선택하면 선택 표시와 상세 제목이 함께 바뀐다. 책의 전체 해설을 카드마다 펼쳐 과밀하게 만들지 않는다.
- 상세 순서: `어떤 책인가` → `읽어볼 이유` → `전공·직업과 연결` → `읽으며 생각할 질문` → `후속 탐구` → `출처·판본 정보`.
- 출처는 상세 패널에서 펼쳐 볼 수 있게 한다. 원목록 근거와 추가 해설·탐구 제안의 출처를 묶어서 오인시키지 않는다.
- 초기 실제 앱에서는 목록을 먼저 보여주고 사용자가 책을 고르게 한다. 이번 시안은 구성 설명을 위해 과학혁명의 구조를 선택한 예시 상태를 사용한다.

### 4.2 검색·필터

- 제목·다른 표기·저자·주제·연결 전공·직업을 한 검색창에서 찾는다. 책의 소개와 연결 근거도 필요한 범위에서 검색 대상으로 포함한다.
- 원분류, 관심 학과, 관심 직업 필터를 제공한다. 필터 종류 사이는 AND, 같은 필터에서 여러 값을 선택하는 경우 OR로 적용한다.
- 표시되는 결과 수는 실제 필터 결과로 계산한다. 비어 있으면 필터 해제 방법을 안내하고 임의의 관련 없는 책을 추천 결과로 채우지 않는다.
- 필터 결과에 선택했던 책이 없으면 상세 선택을 해제하고 선택 안내를 표시한다. 목록과 다른 책의 상세가 남아 있지 않게 한다.
- 메뉴 이동 후 복귀 시 같은 앱 실행 중의 검색·필터·선택을 유지한다. 앱 재실행 시 기본은 전체 목록이다.

### 4.3 관심 도서

- 간단한 관심 도서 표시를 제공한다면 책 ID 목록만 로컬에 저장한다. 학생별 명단·학번·독후감·평가를 수집하는 기록 시스템으로 확장하지 않는다.
- 키는 기존 허용 범위와 대조해 `readingBooks.favorites.v1` 등 전용 키를 등록하고, 오래된 ID·중복을 정규화한다. 실제 파일 쓰기 실패는 화면에서 처리한다.
- 관심 표시는 현재 앱 프로필에 저장되는 개인 설정이며 학교 공유 서버나 웅천 서가로 자동 동기화하지 않는다. 도서 정보 갱신 시 ID를 유지한다.
- 독후감 자동 생성·학생부 문장 자동 작성·독서 점수·합격 가능성 표시는 이번 범위에 포함하지 않는다.

## 5. 데이터 구조와 검토 상태

| 엔터티 | 주요 필드 |
| --- | --- |
| 컬렉션 | 안정적인 ID, 이름, 기관, 선정연도/기준, 근거 source ID, 검증한 총 항목 수 |
| 선정 항목 | ID, 원래 순서, 원제/표시명·별칭, 저자, 원분류, 포함 작품 ID, 원목록 출처, 검토 상태 |
| 책 해설 | 한 문장 소개, 기본 설명, 읽을 이유, 주제 태그, 독서 질문, 후속 탐구, 문단별 출처/작성 구분 |
| 진로 연결 | 책 ID, 전공/직업 ID, 연결 이유, `외부 확인/탐구 제안`, source ID, 확인 위치·일자, 검토 상태 |
| 판본 | 작품 ID, 제목, ISBN, 역자, 출판사, 출간 정보, 확인한 도서정보 URL. 미확정 필드는 비워둠 |
| 출처 | ID, 기관·저자, 자료명, 원문 URL, 자료 기준일·확인일, 직접 확인 범위 |
| 로컬 상태 | 관심 도서 ID 배열. 검색·필터·현재 책은 실행 중 상태로 관리 |

- 실제 100선 자료는 검토한 정적 데이터로 앱에 포함하고, 저자·연결·출처를 참조하는 ID의 무결성을 검사한다.
- 내용 확정 전에는 임시 데이터에 `시안용/검토 중` 상태를 붙인다. 일부 책만 작성한 상태에서 완성된 100권 해설로 보고하지 않는다.
- 원목록 대비 누락·중복, 출처 없는 사실, 편집 제안 표시 누락을 검출하는 콘텐츠 검사를 마련한다. 작품명·판본 별칭을 비교해 잘못 합치지 않는다.

## 6. 외부 연결·성능·비용

- 원목록·해설·출판사·도서관 검색을 원하는 사용자가 외부 브라우저에서 열 수 있게 한다. 본문·학생 정보·앱 API 키는 보내지 않는다.
- 기본 목록·검색·상세·관심 표시는 오프라인에서도 작동하도록 한다. 외부 자료 열기에는 인터넷이 필요함을 버튼 맥락에서 안내한다.
- 목록을 열 때마다 100개 책의 서지 API를 호출하거나 AI 해설을 생성하지 않는다. 로컬 데이터와 검색 인덱스를 사용한다.
- 원문 전체·책 파일·표지 100장을 실행 시 자동 다운로드하지 않는다. 검토한 이미지가 있다면 필요한 것만 사용하고, 실패 시 제목 디자인으로 대체한다.
- 새 서버·DB·유료 도서 API·AI 서비스 가입을 필요 조건으로 추가하지 않는다. 외부 자료의 사용 조건과 필요한 API가 있다면 구현 전에 실제 조건을 확인해 적용 범위를 기록한다.
- 기존 학생·교직원 명렬이나 독서 기록을 연계하지 않아 불필요한 개인정보 저장과 동기화 요청을 만들지 않는다.

| 업무 도우미 검색·사용 매뉴얼 | 진입 방법·자료 성격·제안 구분·로컬 저장 안내 |
| 콘텐츠 검증 스크립트·테스트 | 100개 선정 항목 대조·참조 무결성·검색/필터·저장 회귀 검사 |

1. 최신 정식 소스를 기준으로 작업 공간을 준비하고 100개 선정 항목과 원분류를 확정한다.
2. 먼저 대표 도서로 데이터 구조·카드·상세·근거 표시를 구현하고 사용성을 확인한다.
3. 남은 책의 소개·질문·연결과 출처를 작성·검토한다. 상세한 직업 연결이 없는 책은 빈 값과 안내를 허용한다.
4. 검색·필터·관심 로컬 저장과 메뉴·검색 안내를 구현한다.
5. 전권 콘텐츠와 동작 검사를 수행하고 Windows 테스트 실행본에서 화면을 확인한다.
6. 통합 계획의 다른 네 항목과 함께 회귀 검사 후 테스트판으로 제공한다. 정식 반영·배포는 후속 단계에서 수행한다.

## 9. 시안과 완료 범위

- 시안은 원목록에 실린 대표 작품 6개와 직접 작성한 짧은 소개·탐구 제안으로 구성한다. 실제 출판사 표지·판본·쪽수·평점은 넣지 않는다.
- 카드에서 책을 선택해 오른쪽 설명을 읽는 상태를 보여준다. 화면에 `시안 예시 6권`, `탐구 제안`을 표시해 실제 100권 검증·공식 전공 분류와 구분한다.
- 결과 이미지와 함께 상세계획을 제공한다. 시안의 로컬 검색·필터·선택 동작 확인은 앱 테스트버전 검증으로 보고하지 않는다.
- 테스트버전 완료에는 실제 원목록 대조·콘텐츠 검토·동작·Windows 표시 검증이 필요하다. 정식판은 통합 계획의 기존 식별자·사용자 데이터 경로를 유지하고 더 높은 버전으로 배포·복구한다.
