# 수시모집 우수사례 상세 개발계획

- 작성일: 2026-11-03
- 현재 단계: **3. 초기 테스트버전 개발·검증**. [개발·검증 기록](../testing/2026-11-03-preview.md)의 구현 범위와 미확인 항목을 함께 확인한다.
- 통합 계획: [진학·대입 및 독서교육 탭 통합 상세 개발계획](2026-11-03-admissions-reading-tabs.md)의 일곱 번째 개선 항목.
- 기준 요구사항: [누적 개선계획](../IMPROVEMENT_PLAN.md)의 수시모집 우수사례 탐색 및 비밀번호 열람.
- 입력 조사: [자료집 목차·사례 구조 확인 메모](../research/2026-11-03-admission-success-cases.md). 목차와 일부 본문의 확인 결과를 사용하며, 전체 사례 추출·색인 정확도 검증은 아직 수행하지 않았다.
- 이 문서는 설계 기준이다. 별도 테스트버전에서 중앙 제공 흐름을 구현했으며 정식 앱·서버·배포는 변경하지 않았다. 자료집 원문·실제 성적·학생부 본문을 계획서나 공개 테스트 자료에 복사하지 않는다.

## 2026-11-03 개발 중 변경: 관리자 중앙 등록

사용자의 후속 요구에 따라 아래의 개인별 PDF 등록 흐름을 **관리자 중앙 등록 → 교직원 로그인 후 열람**으로 변경한다. 이 변경 내용이 개인별 최초 등록·공개 기능만 배포 관련 이전 문구보다 우선한다.

- 관리자가 자료집 두 권을 비공개 저장소에 한 번 등록한다. 정식 서비스는 비공개 Drive 파일 ID·제목·개정 정보를 서버의 보호된 설정으로 관리한다. 다운로드 가능한 공개 링크를 만들지 않는다.
- 앱은 일반 로그인과 기존 0000 추가 잠금 후 인증된 자료 목록을 읽는다. 원문 요청마다 서버가 세션·자료 ID·허용 범위를 검증하며 실제 저장소 ID·우회 다운로드 주소를 클라이언트에 제공하지 않는다.
- 처음 열거나 개정이 달라진 권만 인증된 경로로 받아 이 PC에 암호화 보관한다. 본문 추출·검색 색인은 계속 로컬에서 만든다. 검색어·학생 개인 자료를 서버에 보내지 않는다.
- 원문·추출 본문·색인은 공개 GitHub·설치파일에 넣지 않는다. 재배포되는 설치파일과 비공개 중앙 자료를 분리한다. 인증이 풀리면 암호화 캐시도 화면에서 다시 열 수 없게 한다.
- 테스트버전은 정식 서버와 분리된 loopback 시험 서비스로 같은 인증/자료 목록/자료 내려받기 계약을 확인한다. 관리자용 시험 설정은 코드·설치파일 밖에 두고 원문은 해당 서비스에서 읽는다. 이 PC의 시험 서비스가 다른 PC에서도 이용 가능한 정식 중앙 서비스라고 안내하지 않는다.
- 정식 반영에서는 관리자 등록·저장소 권한·서버 인증 강제·자료 개정·캐시 재사용·비인증 요청 거부와 접근 해제를 실제 배포 대상으로 확인한다. 기존 개인별 등록 시험 항목은 이 중앙 등록 시험으로 교체한다.

## 1. 목표와 기능 범위

[공통 로그인 상세계획](2026-11-03-staff-password-login.md)의 일반 인증을 먼저 확인하고 이 탭의 0000 잠금을 별도로 적용한다. 앱 시작의 서버 세션 검증과 인증된 실행 세션 안의 로컬 원문/검색을 구분하며, 자료집·검색어·색인을 인증 요청에 첨부하지 않는다. 일반 로그아웃·만료 시 이 탭의 열람 권한도 폐기한다.

`진학·대입 > 수시모집 우수사례`를 추가한다. 메뉴 ID는 `admission_success_cases`로 정하고 개인별 고정·숨김·순서와 검색 진입 규칙을 따른다. 새 관리자 계정이나 외부 인증 서비스는 추가하지 않는다.

필수 기능은 비밀번호 `0000` 입력, 인문·자연 자료집의 로컬 등록, 대학별·학과별 탐색, 가나다 색인, 전형·지원 결과 필터, 본문 검색, 사례 상세와 PDF 원문 쪽 연결, 다시 잠금이다. 관심 사례 저장은 이 PC 안에서 제공한다. 외부 공유·AI 해설·합격 가능성 예측·대학별 합격선 통계·온라인 자료 다운로드는 초기 범위에 넣지 않는다.

자료집의 `2026` 표기를 보존하고 최신 모집요강으로 안내하지 않는다. 대학별 환산 내신이 포함될 수 있으므로 성적 수치를 임의로 통일하거나 평균내신등급 산출기의 결과와 자동 비교·연결하지 않는다.

## 2. 화면과 기본 동작

### 2.1 잠금 화면

```text
수시모집 우수사례
자료를 열람하려면 비밀번호를 입력하세요.
[비밀번호 · 마스킹 입력] [열람하기]
자료는 이 PC에서 검색하고 열람합니다.
```

잠금 전에는 대학 목록·사례 목록·검색어·검색 결과·최근 열람·관심 목록·원문 미리보기를 만들거나 표시하지 않는다. 비밀번호가 맞은 뒤 등록 여부를 확인한다. 미등록 상태이면 `인문계열 PDF 등록`, `자연계열 PDF 등록`을 제공한다. 자료가 한 권만 있어도 그 권부터 사용할 수 있고 등록하지 않은 계열은 `미등록`으로 안내한다.

### 2.2 열람 화면

```text
수시모집 우수사례 · 2026 자료집       [자료 관리] [잠그기]
[전체 / 인문계열 / 자연계열]         [관심 사례]
[대학별 보기 / 학과별 보기 / 전체 사례]
[검색어] [전체 / 대학·학과 / 전형 / 본문] [검색]
[대학] [학과] [전형 유형] [지원 결과]  [필터 초기화]
□ 다른 지원 대학·학과도 포함

가나다 색인·목록           선택한 사례
대학 또는 학과 묶음        목차 대학·학과 / 자료집 / 사례 번호 / 원문 쪽
사례 카드·일치 건수        [지원 현황] [성적 추이] [선택과목] [학생부] [원문]
                          검색 일치 부분 / 해당 지원 행 / 출처 이동 / 관심 저장
```

- 기본은 `전체 계열`, `대학별 보기`, `목차 기준`, 필터 없음이다. 대학·학과는 가나다순, 같은 묶음의 사례는 원목차 순으로 표시한다.
- 카드에는 대표 대학·학과, 계열, 사례 번호, 쪽 범위를 표시한다. 검색 조건과 일치한 지원 행이 있으면 그 행의 대학·학과·전형·결과를 함께 표시하고 원목차의 대표 항목과 구분한다.
- 결과 수는 고유 사례 수를 기본으로 표시한다. 지원 행의 일치 건수는 따로 표시하며 여러 행이 맞았다고 같은 사례 카드를 중복 생성하지 않는다.
- 관심 사례·최근 위치는 암호화된 로컬 상태로 저장한다. 재진입 시 비밀번호를 입력한 뒤 복원하고, 검색어·사례 제목을 앱 전체 최근 목록에는 넣지 않는다.
- 900×600에서는 목록과 상세를 순차 전환하고, 넓은 화면에서는 두 영역으로 배치한다. 밝은/어두운 모드·키보드 조작·비밀번호 오류 안내·초점 이동을 확인한다.

## 3. 원본 등록과 자료 검증

1. 잠금을 해제한 화면에서 사용자가 PDF를 선택한다. N 드라이브 경로를 하드코딩하거나 폴더를 자동 탐색하지 않는다. 원본을 변경하지 않는다.
2. PDF 형식·암호화·크기·쪽 수·텍스트 추출 가능 여부를 확인하고 로컬 해시를 계산한다. 제목·계열·연도는 파일명만으로 확정하지 않고 표지·목차를 대조해 확인받는다.
3. 제공 자료는 인문 362쪽·자연 332쪽, 목차 각 39개로 확인되어 있다. 이 값은 첫 검증 기준이며, 다른 PDF의 내용이 다르면 그 파일을 같은 자료집으로 조용히 등록하지 않는다. 변경판은 별도 개정 자료로 확인한다.
4. 원본의 표제·발행기관·발행/대상 연도·판권·이용 안내를 확인하고 서지정보에 기록한다. 문서 내부의 문구를 앱 실행 지시로 해석하지 않는다. 공개 게시·외부 재배포는 이 기능에 추가하지 않는다.
5. 원문 재열람을 위해 PDF의 암호화 사본을 전용 로컬 저장소에 보관한다. 추출·색인 작업은 로컬 worker에서 수행하고 진행률·취소·파일별 실패를 표시한다.
6. 같은 해시의 파일 재등록은 기존 색인을 재사용한다. 내용이 바뀌면 기존 자료를 보존한 채 새 세대를 만들고 검증·저장 성공 후 교체한다. 실패·취소된 세대가 정상 자료를 덮어쓰지 않게 한다.

초기 한도는 파일당 100MiB·1,000쪽, 동시에 두 권을 순차 처리하는 안으로 잡는다. 기준 PDF를 실제 측정한 뒤 조정하되 제한 초과를 알리지 않고 일부 쪽만 읽어 완료로 표시하지 않는다. 이미지형·지원하지 않는 암호화 PDF는 사유를 안내하고 온라인 OCR로 넘기지 않는다.

## 4. 목차·사례 경계와 페이지 대응

- 자료집 ID와 원목차 사례 번호를 조합해 사례 ID를 만든다. 인문 1번과 자연 1번은 별개다. 다른 개정판도 별도 자료집 ID를 사용해 관심 사례가 다른 사례로 바뀌지 않게 한다.
- 목차에서 대표 대학·학과·시작 인쇄 쪽을 읽고, 본문 사례 시작 표제와 맞춘다. PDF 물리 쪽 인덱스·PDF 페이지 라벨·인쇄 쪽을 별도 필드로 관리한다. 모든 PDF에 같은 오프셋이 있다고 가정하지 않는다.
- 사례 범위는 시작 쪽부터 다음 사례 시작 직전까지를 후보로 잡고 원본으로 검증한다. 빈 쪽·발간사·목차·부록을 사례 본문에 섞지 않는다. 마지막 사례는 파일 끝을 무조건 끝 쪽으로 삼지 않고 실제 마지막 본문과 대조한다.
- 필수 개발 검증은 두 권의 목차 78개와 각 시작·끝 쪽의 전수 대조이다. 사례 번호 중복·누락·범위 겹침·다음 사례 혼입을 검사한다. 앱에서 새 개정판을 읽을 때도 대응이 불명확하면 확인 필요 상태를 유지한다.
- 색인은 검증된 사례 범위와 본문 구획을 연결한다. 아직 사례가 특정되지 않은 쪽은 일반 사례 결과에 자동 편입하지 않고 `사례 경계 확인 필요`로 분리한다.

## 5. 사례와 지원 내역의 구조화

| 구조 | 주요 필드 |
| --- | --- |
| 자료집 | 로컬 ID, 원본 해시, 제목·연도·계열·서지정보, 쪽 수, 개정/색인 버전 |
| 목차 사례 | 자료집 ID, 원목차 번호, 대표 대학·학과의 원문/검색용 명칭, 검증된 쪽 범위 |
| 지원 행 | 사례 ID, 행 ID, 대학·학과·전형 유형·세부전형명·결과의 원문과 검토한 정규화 값, 원본 위치 |
| 본문 구획 | 사례 ID, 지원 현황·성적 추이·선택과목·학생부·후기 등 실제 존재하는 구획, 쪽·위치 |
| 성적 표 | 원본 표제·열·값·반영방법 문구와 출처. 같은 산식이라고 가정하지 않음 |
| 검색 단위 | 사례/구획/지원 행 ID, 원문 텍스트, 정규화 텍스트와 원문 위치 대응 |
| 개인 상태 | 관심 사례 ID, 마지막 위치, 필터·보기 설정. 암호문 안에서 관리 |

- 한 사례의 여러 지원 행은 1:N으로 관리한다. 표의 대학·학과·전형·성적·결과는 같은 행과 열의 관계를 보존한다. 여러 행을 붙인 텍스트에서 가까운 단어만 보고 연결하지 않는다.
- 원목차의 대학·학과를 `최종 등록 대학`, 첫 지원 행을 `대표 합격`으로 추정하지 않는다. 자료에 명시되지 않은 실제 학생 신원도 추정·추가하지 않는다.
- 대학·학과의 원문은 보존한다. 띄어쓰기·확인한 약칭만 별도 검색용 이름으로 관리하고 현재 대학명·통합 학과명으로 덮어쓰지 않는다. 넓은 전공 분야 태그는 원문 분류와 구분한 검토 자료로 둔다.
- 결과는 원문을 함께 표시한다. 명확한 `합/합격`은 합격(유형 미상), `최초합`은 최초합격, `추합/충원합격`은 추가합격, `불/불합격`은 불합격으로 정규화한다. 그 밖의 표기·빈칸은 추정하지 않고 원문/확인 필요로 둔다. 합격 전체 필터에는 확인된 합격 유형만 포함한다.
- 성적·선택과목·학생부 구획은 원문을 충실히 보여준다. 없는 후기·면접 항목은 생성하지 않는다. 세특 활동을 합격 원인으로 자동 요약하지 않으며 AI 호출을 추가하지 않는다.
- 신뢰할 수 없는 표는 구조화 완료로 표시하지 않고 원문 열람과 확인 필요 안내를 제공한다. 미확인 결과를 합격 필터에 넣거나 집계에서 몰래 확정하지 않는다.

## 6. 대학·학과별 탐색과 필터 의미

### 6.1 목차 기준 · 기본

대학·학과 묶음은 원목차 대표 항목으로 만든다. 전형·결과 필터를 함께 쓰면 해당 대표 대학·학과와 대응하는 지원 행에서 확인한다. 대응 행이 확실하지 않으면 전형·결과를 임의로 가져오지 않고 확인 필요로 표시한다.

### 6.2 다른 지원 대학·학과도 포함

지원 표의 모든 검증된 행을 탐색 대상으로 넓힌다. **대학·학과·전형·지원 결과 조건은 반드시 같은 지원 행에서 함께 일치해야 한다.** 예를 들어 가상 사례의 A대 합격 행과 B대 불합격 행을 결합해 `B대+합격` 결과를 만들면 안 된다. 일치 행을 카드와 상세에 명시하고 사례는 한 번만 센다.

### 6.3 공통 규칙

- 서로 다른 필터 종류는 AND, 같은 종류에서 여러 값을 선택하면 OR로 해석한다. 계열은 자료집 분권을 따른다. 학과 이름만 보고 사례를 다른 계열로 옮기지 않는다.
- 대학을 바꾸면 그 조건에서 가능한 학과를 갱신한다. 해제된 조건과 결과 수를 즉시 반영하고 `필터 초기화`로 빈 결과에서 돌아올 수 있게 한다.
- 가나다 색인은 현재 보기와 필터에 맞는 대학 또는 학과 묶음으로 이동한다. 초성이 없는 영문·기타 명칭은 별도 묶음에 표시한다.
- 본문에서 대학 이름이 언급됐다는 이유만으로 지원 대학 필터에 넣지 않는다. 필터의 구조화된 지원 행과 본문 검색 결과를 구분한다.
- 사례 수와 지원 건수, 합격 전체와 최초/추가합격을 구별해 표시한다. 표본으로 합격률·입시 확률을 계산하지 않는다.

## 7. 로컬 본문 검색과 색인

- 검색 범위는 `전체`, `대학·학과`, `전형`, `본문`으로 제공한다. 빈 검색어는 현재 조건의 전체 사례 목록을 보여준다.
- 원문과 검색용 텍스트를 별도로 보관한다. Unicode·띄어쓰기·PDF 줄바꿈을 정규화하되 원문 위치 대응을 유지한다. 확인한 대학 약칭·학과 별칭만 확장하며 임의 유사어가 원문 일치처럼 표시되지 않게 한다.
- 초기 검색은 정확한 이름/구문 → 확인한 별칭 → 본문 일치 순으로 정렬한다. 여러 일반 검색어는 AND, 따옴표는 정확한 구문으로 처리한다. 사용자 입력을 정규식·실행 코드로 해석하지 않는다.
- 검색어는 최대 200자·10개 단어를 초기 상한으로 잡는다. 한국어 부분 검색을 지원하는 로컬 인덱스와 원문 재확인을 조합한다. 클라우드 벡터 DB·임베딩·LLM은 사용하지 않는다.
- 쪽·본문 구획별로 색인해 일치 미리보기, 일치 종류, 원문 쪽 이동을 제공한다. 표 셀과 다른 구획의 텍스트를 이어 붙여 존재하지 않는 구문을 만들지 않는다. 길이가 긴 문서도 필요한 검색 결과만 화면에 렌더링한다.
- 빠르게 검색어를 바꿨을 때 이전 응답을 폐기한다. 잠금 세대·자료집 개정 버전이 다른 결과도 표시하지 않는다. 검색어·결과를 공통 전역 상태·URL·로그에 저장하지 않는다.
- 색인은 원본 해시·파서 버전·정규화/별칭 버전·스키마 버전으로 재사용 여부를 판단한다. 앱 진입이나 필터 변경 때 694쪽을 다시 추출하지 않는다. 필요한 자료집·바뀐 세대만 재색인한다.

## 8. 사례 상세와 PDF 원문

- 상세 첫 화면은 목차 대학·학과, 계열·사례 번호·출처, 검증된 지원 현황이다. 이후 성적 추이·선택과목·학생부 주요 내용 등 실제 존재하는 구획으로 이동한다.
- 지원 행이나 검색 미리보기에서 원본 쪽·표 위치로 이동한다. 실제 쪽과 일치 부분을 강조하되 PDF 좌표·회전·축척을 변환한 뒤 검증한다. 강조 위치가 불확실하면 잘못 표시하는 대신 해당 쪽과 문구를 제시한다.
- PDF는 번들에 포함한 로컬 파서·뷰어 자산으로 표시한다. 외부 브라우저·클라우드 뷰어·원본 N 드라이브의 file URL을 열지 않는다. 폰트·CMap·worker도 패키지 내부 자산을 사용한다.
- 현재 사례 범위를 안내하고 다음/이전 쪽은 그 범위 안에서 이동한다. 다른 사례는 목록이나 명시적인 다음 사례 선택으로 이동한다. 원문 버튼이 다른 학생의 다음 사례로 잘못 연결되지 않게 한다.
- 보이는 쪽과 인접한 최소 범위만 렌더링한다. PDF 전체 쪽을 이미지로 미리 만들어 저장하지 않는다. 원문 PDF 바이트·텍스트층·캔버스·객체 URL은 열람 화면 메모리에서만 사용하고 잠글 때 폐기한다.
- PDF 안의 스크립트·첨부 실행·외부 링크·원격 리소스는 실행하지 않는다. 초기 UI에 원문 다운로드·외부 공유·인쇄 도구를 추가하지 않는다. 이 조치가 사용자의 화면 촬영·내용 전달까지 막는다고 안내하지 않는다.

## 9. 비밀번호 0000과 재잠금

### 9.1 판정과 열람 권한

- 사용자가 지정한 비밀번호는 **`0000`**이다. 메인 프로세스의 전용 잠금 모듈에서 입력을 판정한다. 렌더러의 `unlocked=true` 같은 값만 신뢰하지 않는다. 입력값을 로그·URL·공통 설정·브라우저 저장소에 남기거나 자동 기억하지 않는다.
- 성공하면 현재 전용 webContents·최상위 프레임·진입 세대에 묶인 임의 열람 토큰을 메모리에서만 발급한다. 재사용 가능한 영구 토큰을 저장하지 않는다. 토큰은 URL에 넣지 않는다.
- 자료집 목록·등록·색인 읽기·검색·사례 상세·관심 저장·PDF 제공의 모든 전용 API에서 송신 프레임·토큰·활성 탭·세대를 확인한다. 잠긴 요청은 내용·건수·파일 위치를 반환하지 않는다. 임의 파일 경로·임의 URL·다른 기능의 저장소 접근도 허용하지 않는다.
- 틀린 입력은 일반 오류로 안내하고 짧은 재시도 지연을 적용한다. 고정 4자리 공유 비밀번호를 개인별 인증이나 강한 기밀 보안으로 표현하지 않는다. 소스·실행파일을 조작할 수 있는 사용자까지 통제한다고 보장하지 않는다.

### 9.2 상태 전환

| 상황 | 처리 |
| --- | --- |
| 앱 시작·잠긴 메뉴 진입 | 제목·비밀번호 폼만 표시. 원문·색인을 미리 복호화/로딩하지 않음 |
| 올바른 비밀번호 | 현재 진입에만 유효한 권한 발급 → 필요한 자료 로딩 |
| 잘못된 비밀번호 | 자료 읽기 없음. 오류 안내와 입력 재시도 |
| 같은 탭을 다시 클릭 | 기존 권한 폐기 후 비밀번호 화면. 메뉴 ID가 같다고 재잠금을 생략하지 않음 |
| 다른 메뉴·고정 메뉴·검색·뒤로 가기로 이탈 | 전용 뷰를 즉시 숨기고 메인에서 권한 폐기 → 작업 취소·메모리 정리 → 다른 메뉴 표시 |
| 다시 진입 | 이전 세션을 복원하지 않고 비밀번호 재입력 |
| 앱 종료·뷰 충돌·Windows 세션 잠금 | 권한 폐기. 복구·재실행 시 잠금 화면 |
| 앱 내 팝업 가림·창 크기 변경 | 뷰 숨김/좌표만 관리. 메뉴 진입 횟수를 늘리거나 자료를 배경에 노출하지 않음 |

재잠금은 UI 가리기보다 먼저 또는 같은 전환에서 메인의 읽기 권한을 폐기한다. 검색·PDF 렌더·색인 worker와 대기 중 응답을 취소하고, 전용 뷰를 폐기해 이전 DOM·화면·텍스트층이 뒤로 가기로 복구되지 않게 한다. 복호화한 본문·원문 바이트·자료 키의 메모리 참조도 해제하되 완전한 물리적 메모리 삭제로 표현하지 않는다. 늦은 결과의 화면 표시·개인 상태 저장도 진입 세대 검사로 거부한다.

잠금 이탈 중 새 자료 색인 작업은 취소하고 기존 정상 세대를 보존한다. 완성되지 않은 임시 세대는 암호화 상태로만 존재하게 하고 다음 열람 때 정리한다. 매번 다시 색인하는 대상은 취소된 미완성 세대에 한정한다.

## 10. 보관·암호화·외부 전송 차단

### 10.1 배포와 저장 경계

- **공개 앱에는 탐색 기능만 배포한다.** 두 원본 PDF, 추출 텍스트·표, 검색 색인, 미리보기, 실제 자료 fixture는 GitHub·공개 Release·설치파일·웹 자산에 넣지 않는다. 각 PC에서 사용자가 자료를 등록한다. 다른 PC로 자동 동기화하지 않는다.
- 전용 위치는 Windows `LocalAppData` 아래 앱의 `private/admission-cases/v1`로 정한다. 공통 electron-store·학교 캐시·문서·OneDrive·MYBOX에 넣지 않으며 비정상 경로/공유 경로로 임의 대체하지 않는다. 프리뷰 저장 경로도 분리한다.
- 원문 사본·본문·구조화 자료·색인·관심 목록을 인증 암호화한다. 무작위 자료 키를 Windows OS 보호 API로 감싸며 `0000` 자체를 암호화 키로 사용하지 않는다. 기준 Electron의 실제 지원 API로 구현하고 검증한다.
- 평문 PDF·본문·원문 이미지를 디스크 임시 파일로 만들지 않는다. 작업은 메모리에서 수행하고 스테이징·이전 세대도 암호화한다. 암호화/복호화 불가·저장 손상은 안내하고 평문 저장이나 원본 훼손으로 대체하지 않는다.
- 저장 성공은 암호화 파일 작성·검증·원자적 교체를 마친 뒤에만 표시한다. 자료 관리의 등록 해제는 확인 후 해당 기능의 사본·색인·개인 상태를 지우고 원본은 보존한다. 고정 전용 루트와 파일 ID만 허용하고 삭제 도중 종료·실패의 복구도 기록한다.
- 공통 백업·진단 첨부·공유 캐시 대상에서 제외한다. 평균내신등급 산출기의 자료 비우기와 상호 영향을 주지 않으며 시험판 자료를 정식판으로 자동 복사하지 않는다. OS 계정이 같은 다른 프로그램까지 차단하는 암호화라고 설명하지 않는다.

### 10.2 전용 화면과 통신

- 실제 자료 화면은 독립 React 진입점·비영구 세션의 `WebContentsView`·전용 preload로 구성한다. 메인 앱에는 자리·메뉴 활성·좌표·테마·팝업 상태만 연결하고 원문·검색어·사례 제목·결과를 전달하지 않는다.
- `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`, `webSecurity: true`를 적용한다. preload에는 잠금/해제와 이 기능의 검증된 동작만 노출한다. 앱 범용 파일·설정·AI·학교 서버 요청 API는 주입하지 않는다.
- CSP와 전용 세션의 요청 제어에서 패키지 자산만 허용한다. HTTP(S)·WebSocket·beacon·원격 폰트·이미지·CDN·외부 탐색·새 창을 막는다. 다른 세션의 네트워크 필터·Google 헤더 설정은 변경하지 않는다. 개발 서버 예외는 합성 자료 개발에만 적용하고 패키징 검증에서는 제거한다.
- 파서·색인·검색과 저장 모듈은 외부 AI/OCR·학교 Hub·클라우드 검색·분석 SDK를 호출하지 않는다. 파일 선택은 사용자 선택으로 발급한 단기 토큰만 받고 임의 경로를 수락하지 않는다.
- 로그는 비식별 오류 코드·처리 단계에 한정한다. 원문·검색어·미리보기·학교/학생 정보·PIN·권한 토큰·선택 파일 경로를 콘솔·오류 보고·URL에 남기지 않는다. 입력 문구는 텍스트로 표시하며 HTML이나 문서 안 지시문을 실행하지 않는다.
- 구현 원칙은 [Electron 보안 지침](https://www.electronjs.org/docs/latest/tutorial/security), [WebRequest](https://www.electronjs.org/docs/latest/api/web-request), [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)를 참고한다. 지원 API와 제한은 개발 시작 때 최신 정식 기준의 설치 버전으로 대조한다.

## 11. 비용·성능·오류 처리

- 신규 서버·DB·외부 검색·AI 호출을 만들지 않는 로컬 기능으로 설계한다. 기존 앱 전체의 운영비나 자료를 원래 받은 경로의 비용까지 0이라고 보장하지 않는다.
- 파서·PDF 뷰어 자산은 번들에서 재사용한다. 한 번 검증한 색인은 해시·버전 기준으로 재사용하고, 한 자료집만 바뀌면 그 자료집만 다시 처리한다. 필터·정렬 변경으로 원본을 반복 읽지 않는다.
- 파서·색인·검색은 worker에서 순차 처리하고 취소할 수 있게 한다. 검색 결과 목록은 필요한 행만 표시하고 PDF 렌더 캐시는 메모리의 제한된 쪽만 보관한다. 잠그면 캐시를 폐기한다.
- 상태를 `미등록 / 읽는 중 / 색인 중 / 확인 필요 / 사용 가능 / 실패 / 취소`로 구분한다. 잠금 전에는 상태에 포함된 자료 식별정보도 노출하지 않는다. 한 권 실패로 다른 정상 권을 지우지 않는다.
- 검색 결과 없음·아직 미색인·표 판독 불명확·원문 위치 불일치·저장 불가를 구분한다. 존재하지 않는 결과를 `사례 없음`으로 확정하거나 실패를 자동 온라인 처리로 우회하지 않는다.
- 성능은 제공 두 권으로 로컬 측정한다. 패키징 실행본에서 검색 응답·첫 쪽 표시·최대 메모리·첫 색인 시간을 기록하고 필터 변경 중 UI 응답·취소·재잠금을 확인한다. 측정 전 고정 속도를 보장하지 않는다.

## 14. 테스트버전·정식 반영·복구

- 테스트판은 최신 정식 기준을 확인한 뒤 preview 앱 ID·LocalAppData·출력 경로로 패키징한다. 자료집을 내장하지 않으며 사용자 PC에서 PIN 입력 후 등록한다. 시험판 자료/잠금 상태를 정식판으로 자동 이전하지 않는다.
- 제공물은 Windows 실행본, 기준 커밋·버전, 합성 화면 이미지, SC-01~20 검증표, 지원/미지원 형식, 로컬 등록·잠금·자료 관리 설명이다. 정식 자동업데이트에 게시하지 않는다.
- 사용자 확인 순서: PIN 오류/성공 → 두 자료 등록 → 대학별/학과별/가나다 탐색 → 다른 지원 대학 포함 → 같은 행의 전형·결과 필터 → 본문 검색·원문 이동 → 관심 저장 → 이탈/재진입 재잠금 → 재실행 PIN 후 자료 복원.
- 정식 반영·배포 요청 때 검증한 변경만 최신 정식 소스에 통합한다. 영향받는 필수 검사와 공개 배포물 자료 미포함 검사를 다시 수행하고 버전·사용 안내·Release·자동업데이트 게시 결과를 기록한다.
- 자료 스키마·색인 버전을 분리한다. 색인이 바뀌면 암호화 원문에서 필요한 권만 다시 만들고 원본을 반복 등록하지 않게 한다. 마이그레이션 이전본도 전용 암호화 범위에서만 관리한다.
- 문제 복구는 높은 패치 버전으로 수정·되돌림을 제공한다. 읽지 못하는 새 스키마를 빈 자료로 덮어쓰거나 롤백을 이유로 원본·관심 자료를 자동 삭제하지 않는다. 권한 상태는 어떤 복구에서도 잠금으로 시작한다.
- 계획 완료는 입력·탐색·지원 행 관계·검색·원문·0000 재잠금·로컬 보관/통신·구현/검증/배포 기준의 문서화이다. 실제 개발 완료는 SC-01~20과 Windows 실행본에서 두 실제 자료집의 정확도·격리·잠금을 확인한 뒤 판정한다.
