# 10번 상세계획 · 모바일 로그아웃과 72시간 만료 후 개인정보 정리

2026년 11월 18일 · 모바일 일정 도우미 · 전체 항목 검토 후 통합 시험판에서 검증

## 현재 동작과 수정 지점

- 모바일 앱에서 직접 로그아웃하면 화면과 저장된 로그인 정보를 비우고 해당 교사의 일정 사본 삭제를 요청한다. 앱을 닫아 둔 사이 72시간이 지나면 시작 시 로그인 정보만 지우는 경로가 있어 일정 사본이 남을 수 있다.
- 일정 저장소는 삭제 오류를 내부에서 처리하여 화면에서 실제 삭제 여부를 알기 어렵다. 현재 서버는 발급한 세션별로 만료 시각을 확인하지만, 모바일의 직접 로그아웃은 서버에 전달되지 않는다.
- 점검한 모바일 소스는 `ungcheon-mobile-pwa/src/App.tsx`의 세션 복원·로그아웃 처리와 `ungcheon-mobile-pwa/src/cache.ts`의 사용자별 일정 저장소다. 서버의 발급·만료 처리는 [공용 서버 코드](../../server/Code.gs)에서 확인했다.

## 교사에게 보이는 동작

| 상황 | 화면과 자료 처리 |
| --- | --- |
| 인터넷이 연결된 상태에서 로그아웃 | 즉시 로그인 화면으로 돌아간다. 이 기기의 개인 일정 사본을 지우고, 서버에도 방금 사용한 모바일 로그인 한 건의 종료를 요청한다. |
| 인터넷이 끊긴 상태에서 로그아웃하거나 서버 종료를 확인할 수 없음 | 기기는 즉시 로그아웃하고 개인 사본을 정리한다. ‘이 기기에서 로그아웃했습니다. 서버의 로그인 종료는 확인할 수 없습니다.’라고 안내한다. 서버에서 종료되지 않은 세션도 최초 만료 시각까지만 유효하다. |
| 사용 중 또는 앱을 닫은 사이 72시간 경과 | 다음 표시 시 ‘로그인이 만료되었습니다. 다시 로그인해 주세요.’를 보여 준다. 일정이나 출결 상세를 그리기 전에 잠그고 이전 자료를 정리한다. 서버에서 세션 무효를 확인한 경우에도 같은 정리 절차를 적용한다. |
| 유효한 로그인 중 일시적으로 통신이 끊김 | 받아 둔 본인 시간표·일정만 마지막 정상 갱신 시각과 함께 표시한다. 내려받은 일정이 없으면 이 기기에 저장된 일정이 없다고 안내한다. 오프라인 조회로 72시간을 연장하지 않는다. |

## 구현 순서

1. 로그아웃, 앱 시작 시 만료, 사용 중 만료, 백그라운드 복귀 시 만료, 서버가 확인한 세션 무효를 하나의 정리 절차로 연결한다. 로그인 정보를 지우기 전에 정리할 캐시 키를 확보한다. 일정·출결 팝업과 선택 상세를 닫고, 같은 브라우저 프로필의 다른 탭에도 종료 사실을 전달한다.
2. 요청 취소와 기존 캐시 쓰기 무효화 처리를 활용한다. 종료 전 시작한 읽기·쓰기가 늦게 끝나도 이전 자료가 다시 표시되거나 저장되지 않게 한다. 사용자가 바뀌면 새 로그인과 해당 교사의 캐시를 연결한다. 상세 출결 명렬은 화면 메모리에서만 다룬다.
3. 캐시 삭제의 성공·실패를 구분한다. 삭제가 막히면 해당 사본의 열람을 차단하고 저장소가 열리는 다음 기회에 정리를 다시 시도한다. 시작 시 세션 정보가 없거나 손상되어 소유자를 확인할 수 없으면 모바일 개인 일정 저장소의 잔여 사본을 정리한다. 정리에는 이름·일정 본문을 읽을 필요가 없다. 기기의 테마와 앱 설치 파일은 유지한다.
4. 서버는 종료 요청으로 받은 세션 한 건을 기존 토큰 확인 방식에 맞춰 찾아 폐기한다. 중복 요청과 이미 만료된 세션도 처리하며 같은 교사의 다른 휴대전화나 PC 로그인에는 영향을 주지 않는다. 로그아웃 버튼 한 번에 종료 요청 한 건을 보내며, 재전송을 위해 로그아웃한 접근 토큰을 기기에 다시 저장하지 않는다.

## 통합 시험판 합격 기준

| 시험 | 확인할 결과 |
| --- | --- |
| 가상 교사 A가 두 기기에서 로그인한 뒤 한쪽에서 온라인 로그아웃 | 해당 기기의 일정 사본이 실제 저장소에서 사라지고 종료한 세션으로 일정·출결 조회가 거절된다. 두 번째 기기에서는 기존 로그인이 유효하다. |
| 네트워크를 끊고 A의 일정 열기 → 오프라인 로그아웃 → 재실행 | 로그아웃 전에는 A의 마지막 일정과 갱신 시각이 보인다. 이후에는 오프라인에서도 로그인 화면이 나오며 A의 캐시가 열리지 않는다. |
| 시험 시계로 72시간 직전과 만료 시각 재현 | 앱을 계속 열어 둔 경우와 닫았다 다시 연 경우 모두 경계 시각부터 잠긴다. 만료된 상태에서 저장된 A의 일정이 순간적으로 표시되지 않으며 사본이 삭제된다. |
| 로그아웃 직전 시작한 요청을 지연시키고 같은 전화에서 교사 B로 로그인 | 뒤늦은 응답, 뒤로 가기, 다른 탭 복귀로도 A의 이름·일정·열어 둔 출결이 나타나지 않는다. B의 새 일정은 정상적으로 저장된다. |
| 저장소 삭제를 일시 실패시킨 뒤 앱 재실행 | 실패 중에도 이전 개인 자료를 열 수 없다. 저장소가 복구되면 미처 지우지 못한 사본이 실제로 삭제된다. |

가상 계정과 합성 일정으로 화면·기기 저장소·서버의 세션 종료 결과를 각각 확인한다.
