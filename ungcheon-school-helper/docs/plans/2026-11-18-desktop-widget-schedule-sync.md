# 3번 상세계획 · PC 본창과 위젯의 시간표 동기화

2026년 11월 18일 · 확인 주기 확정 · 전체 항목의 상세계획 작성 후 통합 시험판 제작

## 교직원이 보는 동작

| 상황 | 확인 시점 | 화면 반영 |
| --- | --- | --- |
| 본창과 위젯 중 하나 이상이 보일 때 | PC 한 대에서 30초마다 한 번 | 원격에서 승인한 교환·대강, 휴강·취소 등 변경이 확인되면 같은 기준의 시간표를 두 화면에 반영한다. 위젯만 실행한 경우도 같다. |
| 본창과 위젯이 모두 숨겨지거나 최소화되어 트레이에서 실행 중일 때 | 5분마다 한 번 | 다음 표시를 위해 허용된 변경만 갱신한다. |
| 숨긴 창이나 위젯을 열거나 최소화에서 복원할 때 | 즉시 한 번 | 직전 정상 자료를 먼저 보여 주고 새 결과를 반영한다. 절전에서 깨어나거나 네트워크가 복구되면 밀린 횟수를 누적하지 않고 한 번 확인한다. |
| ‘지금 확인’을 누르거나 이 PC에서 시간표 변경이 서버에 저장됐을 때 | 즉시 | 수동 확인은 진행 상태를 표시한다. 저장 성공 후에는 영향을 받는 날짜·교사·자료를 다시 확인한다. 승인 대기 중인 변경은 기존 공개 범위와 승인 규칙을 따른다. |
| 로그아웃·세션 만료·완전 종료 | 정기 확인 중지 | 개인 시간표를 화면에서 비우고 이전 세션의 응답은 폐기한다. |

접힌 위젯도 화면에 표시된 상태면 30초를 적용한다. 다른 창에 포커스를 옮겨도 주기는 달라지지 않는다. 30초와 5분은 변경 여부를 **확인하는 간격**이다. 실제 표시까지는 서버 응답과 변경 자료를 받는 시간이 더해진다.

## 구현 방식

1. **주기를 PC 한 곳에서 결정한다.** Electron 메인 프로세스에서 두 창의 표시·최소화·복원·종료 이벤트와 로그인 상태를 관찰하고 확인 타이머 하나를 관리한다. 본창을 닫아도 위젯·트레이에서 계속 동작한다. 두 창의 동시 시작·복원, 수동 확인과 정기 확인이 겹치면 같은 진행 요청을 공유한다.
2. **버전 목록을 먼저 확인한다.** 기존 공유자료 버전 조회와 [1번 계획](2026-11-18-private-rosters-timetables.md)의 권한별 자료 범위를 사용한다. 교사 시간표, 교환·대강, 날짜별 예외, 당김·개별 편성 중 현재 화면에 영향을 주는 자료의 버전을 비교한다. 변경이 없으면 본문을 다시 받지 않는다. 서버의 날짜·교사 범위가 필요한 자료에는 그 범위를 캐시 키에 포함한다.
3. **확인된 결과를 두 화면에 전달한다.** 같은 사용자·권한·기간의 자료 요청은 한 번 수행한다. 각 창은 같은 버전에서 자신의 표시 범위만 다시 계산한다. 수정 전 시작된 조회가 저장 후 끝나도 오래된 시간표로 되돌리지 않는다. 저장 완료가 기존 조회와 겹치면 저장된 버전을 확인하는 후속 조회를 한 번 수행한다. PC 내 다른 사용자·보호 메뉴 전용 자료를 위젯에 전달하지 않는다.
4. **기존 갱신 기능과 연결한다.** 본창의 공유자료 서비스와 위젯의 5분 갱신 중 시간표 조회 부분을 공동 경로에 연결한다. 위젯 시계·로컬 메모·날씨·급식·업무 알림은 각각 기존 동작을 유지한다. 30초 타이머가 이 자료들까지 매번 새로 내려받지 않도록 한다. 모바일 조회와 GitHub 프로그램 업데이트 확인은 이번 계획의 대상에서 제외한다.
5. **일시 오류에서 복귀한다.** 망 단절 시 유효한 세션에서는 마지막 정상 시간표와 확인 시각을 표시하고 ‘이전 자료’로 안내한다. 일시 실패를 공강·휴강으로 해석하지 않는다. 반복 실패에는 재시도 간격을 늘리고 복구·수동 확인 시 즉시 다시 시도한다. 세션 만료는 네트워크 오류와 구분해 개인 화면을 잠근다.

## 시험판 검증 기준

| 시험 상황 | 합격 기준 |
| --- | --- |
| 본창과 위젯 모두 표시 / 위젯만 표시 / 본창만 표시 | 세 경우 모두 정상 연결에서 30초 주기다. 가상 시계로 최초 조회 완료 직후부터 10분간 측정하면 정기 버전 조회가 각각 20회이고, 두 창을 열어도 두 배가 되지 않는다. 변경 없는 자료 본문 다운로드는 0건이다. |
| 둘 다 숨김 → 위젯 복원 | 같은 조건에서 10분간 정기 조회 2회. 위젯을 열면 5분이 차기 전에도 즉시 한 번 조회한다. 본창까지 동시에 열어도 같은 응답을 재사용한다. |
| 다른 PC의 대강 승인·휴강 취소 | 시험 서버에서 정상 저장한 변경이 다음 정기 확인과 본문 수신 후 본창과 위젯의 해당 날짜·교시에 일치한다. 3학년 오후 수업 종료와 기존 날짜별 예외도 보존한다. |
| 직접 수정·수동 확인·느린 응답 | 직접 수정한 내용은 다음 주기를 기다리지 않는다. 두 창이 동시에 ‘지금 확인’을 눌러도 같은 요청은 한 번만 실행한다. 이전 응답이 뒤늦게 와도 새 결과가 유지된다. |
| 인터넷 단절·절전·세션 종료 | 데이터 수신 실패 시 마지막 정상 시각이 유지된다. 복귀 시 즉시 한 번만 확인한다. 로그아웃 중 도착한 응답이 위젯에 이전 교사의 수업을 다시 표시하지 않는다. |
| 호출 비용·기능 회귀 | 위젯만 쓸 때 변경 확인 빈도는 높아지고, 둘 다 숨기면 빈도는 낮아진다. 시험판에서 버전 조회 횟수·자료 본문 수신 횟수·응답 시간·수신량을 비교한다. 이름이나 시간표 원문을 로그에 쓰지 않는다. 정상적인 시계·급식·알림·프로그램 업데이트 동작도 확인한다. |

**시험 범위.** 합성 시간표와 분리된 시험 서버에서 먼저 검증한다. 실제 교내망에서의 반영 시간과 서버 비용은 운영 측정 전까지 확정할 수 없다.
