## 1. 목표와 화면 구성

메뉴를 선택하면 안내용 중간 화면 없이 이수증 제출 웹앱을 본문에 바로 연다. 상단에 아래 두 전환 버튼을 항상 표시한다.

| 순서 | 버튼 이름 | 연결 주소 |
| --- | --- | --- |
| 1 · 기본 | 이수증 제출 웹앱 | https://script.google.com/macros/s/AKfycbxG52rulCO1jtpxtkus-YMkZrhxaTB4bXpP-2TxDtv37MTb9rAJWzspakNIK8U7GdFIWA/exec |
| 2 | 이수증 엑셀 내려받기 웹앱 | https://script.google.com/macros/s/AKfycbxG52rulCO1jtpxtkus-YMkZrhxaTB4bXpP-2TxDtv37MTb9rAJWzspakNIK8U7GdFIWA/exec?x=%EC%A0%81%EA%B7%B9%ED%96%89%EC%A0%95 |

선택한 버튼은 금색 배경과 선택 상태로 구분한다. 제목·전환 버튼은 앱 영역에 남고 아래 웹앱 영역만 바뀐다. 좁은 창에서는 두 버튼이 줄바꿈되며 본문과 겹치지 않도록 한다.

제목 오른쪽에는 현재 선택한 웹앱을 대상으로 하는 새로고침과 기본 브라우저로 열기를 둔다. 새로고침에는 입력 내용 확인 안내를 표시한다. 기존 사이트의 내부 양식·제출 버튼·엑셀 생성 방식은 그대로 사용한다.

## 2. 이용 순서와 화면 보존

1. 로그인 후 업무·학교운영 모음을 펼친다.
2. 법정의무연수를 선택하면 이수증 제출 웹앱이 바로 표시된다.
3. 상단의 이수증 엑셀 내려받기 웹앱을 선택하면 두 번째 주소를 연다.
4. 다시 제출 화면으로 전환하면 기존 웹 보기를 재사용해 입력 상태와 스크롤을 유지한다.
5. 다른 업무 메뉴를 보고 돌아올 때에는 제출 화면을 기본 선택으로 표시하되, 같은 앱 실행 중 보관된 제출 화면을 재사용한다.
6. 앱을 완전히 종료한 뒤에는 제출 화면으로 시작한다. 제출 중인 양식의 종료 후 복원까지 보장하지 않는다.

두 웹 보기는 처음 선택할 때에만 만들고 이후에는 숨김·표시로 전환한다. 보이지 않는 화면을 버튼 클릭 때마다 다시 다운로드하지 않는다. 단, 사이트 자체의 자동 새로고침·세션 만료·탐색 동작은 해당 사이트의 정책을 따른다.

## 3. 외부 웹앱 연결 방식

- 기존 외부 도구용 WebContentsView를 확장해 앱 내부에 표시한다. iframe 보안 헤더를 제거하는 전역 우회는 추가하지 않는다.
- 등록된 두 HTTPS 주소만 앱의 전환 요청으로 받는다. 두 번째 주소의 `x=적극행정` 쿼리를 삭제하거나 다른 값으로 바꾸지 않는다.
- 제출용·엑셀용 웹 보기의 저장 세션을 공유해 같은 웹앱의 로그인·쿠키가 필요한 경우 재사용한다. 학교 업무용 메인 화면의 권한·preload는 외부 사이트에 제공하지 않는다.
- Google 계정 로그인 등이 내부 보기에서 제한되면 현재 선택 주소를 기본 브라우저에서 열 수 있게 한다. 앱의 교직원 로그인을 외부 웹앱의 로그인으로 간주하지 않는다.
- 로딩·연결 실패를 구분해 안내하고 다시 시도와 외부 열기를 제공한다. 새 창은 HTTPS 링크에 한해 기본 브라우저로 연다.
- 엑셀 생성·내려받기는 원래 웹앱의 기능으로 수행한다. 내려받기 완료·취소·실패와 저장 위치 안내를 검증하며, 실제 이수증 제출·명단 내려받기는 시안 제작 과정에서 실행하지 않는다.

## 4. 메뉴·검색과 수정 대상

| 대상 | 예정 변경 |

| Layout.tsx | 법정의무연수 페이지 연결 |

| feature-views.ts | 두 URL 허용 목록, 각각의 웹 보기, 공유 외부 세션, 로딩·오류·다운로드 상태 |

다른 진학·독서 외부 도구의 URL·화면 상태·대학 전환 방식은 보존한다. 변경은 기존 시험판 작업 공간에서 진행하되 실제 구현은 후속 지시 후 시작한다.

## 5. 자료·비용 원칙

이 기능을 위해 새 DB나 유료 서비스를 추가하지 않는다. 별도 학교 서버가 이수증 파일과 엑셀을 중계·복제하지 않는다. 실제 제출은 연결된 웹앱이 처리하므로 해당 웹앱의 저장·통신 정책을 따른다. 첫 선택 때만 로드하고 화면을 재사용해 중복 요청을 줄인다. 연결된 Apps Script의 기존 사용량·할당량이 적용되며 비용 0원을 보장하는 표현은 사용하지 않는다.

## 6. 구현 후 검증 기준

| ID | 확인할 내용 |
| --- | --- |
| MT01 | 업무 모음의 메뉴와 업무 검색에서 같은 페이지로 진입 |
| MT02 | 첫 진입 시 제출 웹앱이 본문에 바로 표시 |
| MT03 | 두 번째 버튼이 지정한 쿼리를 유지한 주소로 연결 |
| MT04 | 두 버튼 선택 상태와 표시된 웹 보기 일치, 화면 겹침 없음 |
| MT05 | 합성 입력으로 두 화면 전환 후 양식·스크롤 보존 확인 |
| MT06 | 다른 메뉴·팝업·검색창·로그아웃 시 외부 화면이 앱 UI를 덮지 않음 |
| MT07 | 새로고침 안내, 현재 화면 기준 기본 브라우저 열기 확인 |
| MT08 | 웹앱 오류·연결 실패·Google 로그인 제한에서 복구 경로 확인 |
| MT09 | 합성·비개인 자료로 엑셀 다운로드의 완료·취소·실패·저장 위치 확인 |
| MT10 | 창 크기·확대율 변경과 밝은 모드의 가독성 확인 |
| MT11 | 기존 생기부·서가·대학 웹진 회귀 확인 |
| MT12 | 타입검사·빌드 후 시험 설치파일에서 메뉴·전환 확인 |

실제 웹앱 두 주소의 역할은 사용자의 지정에 따라 연결한다. 현재 웹 조회 도구로 내부 화면을 확인하지 못했으므로 두 번째 주소의 실제 동작과 계정별 접근 권한은 구현 단계에서 추가 확인한다. 시안의 본문은 **배치 예시**이며 실제 사이트를 새로 설계한 화면이 아니다.
