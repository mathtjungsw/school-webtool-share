# 본창·위젯 업데이트 알림 상세 개발계획

- 작성일: 2026-11-03 / 현재 단계: **3. 초기 테스트버전 개발·검증**. [개발·검증 기록](../testing/2026-11-03-preview.md)의 구현 범위와 미확인 항목을 함께 확인한다.
- [통합 상세계획](2026-11-03-admissions-reading-tabs.md)의 아홉 번째 개선 항목. [이름·비밀번호 로그인 계획](2026-11-03-staff-password-login.md)과 로그인 전 업데이트 경로를 함께 적용한다.
- 목표: 위젯만 사용해도 업데이트를 발견하고 실제 설치까지 완료하도록 안내한다. 별도 테스트버전에서 알림 UI·이벤트 연동과 시험 흐름을 구현했다. 정식 updater·버전·배포는 변경하지 않았다.

## 1. 현재 확인과 개선 방향

저장된 origin/main에는 본창 대상 updater 이벤트, 로그인 뒤 표시되는 UpdateModal, 나중에/지금 설치 버튼이 있다. 다운로드 표시는 실제 퍼센트가 아닌 애니메이션이다. 확인한 위젯에는 프로그램 업데이트 상태 표시 연결이 보이지 않는다. 최신 소스·패키징 실행본에서 재현한 뒤 변경하며 사용자 증상의 원인을 확정한 조사로 표현하지 않는다.

메인 프로세스 하나가 확인·다운로드·설치와 상태를 관리하고 본창·로그인 화면·위젯·트레이가 이를 공유한다. 팝업을 닫아도 설치 대기 표시를 유지한다.

## 2. 상태 모델과 전달

| 상태 | 표시·동작 |
| --- | --- |
| 아직 확인 전/확인 중 | 확인 전/확인 중. 최신이라고 표시하지 않음 |
| 최신 | 마지막 성공 확인 시각과 현재 버전 |
| 업데이트 발견 | 현재→대상 버전·핵심 변경·다운로드 상태 안내 |
| 다운로드 중 | 실제 진행률/수신 바이트, 알 수 없으면 진행 중 표시 |
| 설치 준비 완료 | 다운로드 검증 완료 후 지금 설치/나중에 제공 |
| 설치 시작 | 저장 확인·단일 설치 잠금·종료/재시작 안내 |
| 적용 완료 | 재실행 버전으로 확인 후 적용 안내 |
| 실패/확인 불가 | 단계·일반 사유·마지막 정상 상태·재시도 |
| 프리뷰 비활성 | 정식 업데이트 대상 아님. 최신과 구분 |

상태에는 revision, currentVersion, targetVersion, phase, progress, checkedAt, 일반 오류 코드와 안전하게 정리한 변경 안내를 둔다. renderer가 보낸 버전·다운로드 완료 여부는 설치 근거로 믿지 않는다.

- 구독 시작 시 snapshot을 요청하고 상태 변경 이벤트를 받는다. revision으로 지난 응답을 버려 구독 직전 이벤트나 위젯 재생성으로 알림을 잃지 않게 한다.
- downloader 이벤트와 다운로드된 실제 버전을 연결한다. 새 대상이 나오면 이전 버전의 무시·재안내 이력을 새 대상에 적용하지 않는다. 이미 내려받은 버전이 있으면 어떤 버전을 설치하는지 정확히 표시한다.
- 진행률 이벤트는 화면 갱신만 최대 약 4회/초로 병합한다. 네트워크 확인·다운로드는 하나의 진행 중 작업을 공유한다. 이벤트 구독은 창 종료/재마운트 때 정리한다.
- 디스크에는 대상 버전·준비 상태 힌트·확인/알림 시각·설치 시도 버전만 저장한다. 재시작 후 파일 유효성은 updater로 다시 확인하고 저장된 boolean만으로 설치 가능 상태를 만들지 않는다.

## 3. 화면별 안내

| 위치 | 구성 |
| --- | --- |
| 로그인 화면 | 개인정보 없는 버전/새 업데이트/다운로드/지금 설치. 로그인 없이 동작 |
| 본창 | 상단 고정 배너·메뉴 배지와 업데이트 상세. 닫아도 배지는 유지 |
| 펼친 위젯 | 헤더 인접 업데이트 영역·실제 다운로드 상태·업데이트 설치 버튼 |
| 접힌 위젯 | 작은 배지와 접근성 이름. 클릭 시 본창 업데이트 화면 활성화 |
| 트레이 | 업데이트 상태·설치 준비 메뉴. 숨긴 본창을 업데이트 안내로 복원 |
| Windows 알림 | 업데이트 발견/설치 준비 완료 알림. 클릭 시 동일 안내 화면 |

위젯은 별도 설치를 실행하지 않고 본창의 공통 설치 흐름으로 이동한다. 미인증 위젯에도 업데이트 정보만 표시하며 개인 업무를 함께 열지 않는다. 앱 내 웹 보기와 우수사례 화면은 업데이트 팝업이 뜨면 가려 초점·버튼이 덮이지 않게 한다.

상세에는 현재/대상 버전, 다운로드·설치의 차이, 짧은 변경 내용, 지금 설치/나중에/실패 시 재시도를 둔다. 변경 내용에 위젯 안내가 있으면 사용법과 위젯 열기/설정으로 연결한다. 로그인이 필요한 설정은 로그인 후 이동하고, 위젯·자동 실행 설정을 임의로 켜지 않는다.

변경 내용은 실행되지 않는 텍스트/안전한 제한 형식으로 표시한다. 외부 내용의 HTML·명령·임의 설치 URL을 실행하지 않고 설치 공급자는 기존 검증된 경로로 고정한다.

## 4. 확인·재안내·비용 기준

- 정식 패키징 앱 시작 시 한 번 확인한다. 트레이 복원·네트워크 복구·위젯 재표시에서는 마지막 성공 확인이 **6시간 이상** 지났을 때 같은 작업을 재사용해 확인한다. 장시간 실행 중에는 6시간보다 자주 확인하지 않는다. 화면별 개별 폴링은 만들지 않는다.
- 수동 확인은 즉시 요청하되 진행 중 작업을 공유하고 연속 클릭은 제한한다. 오류 자동 재시도는 5분→30분→6시간으로 늘린다. 네트워크가 없으면 반복 요청을 중단하고 연결 복구/사용자 확인을 기다린다.
- 대상 버전의 발견·설치 준비 전환은 각각 한 번 알린다. 최초 자동 팝업은 한 실행 세션·대상 버전당 한 번이며 이미 보이는 안내를 중복 열지 않는다. 아래 24시간 재안내는 장시간 실행의 별도 예외로 하루 한 번만 허용한다. 상태가 준비 완료가 되면 열린 안내는 갱신한다.
- `나중에` 뒤에도 본창/위젯/트레이 배지는 남긴다. 다음 실행에서 준비된 버전을 다시 안내하고, 계속 켜 둔 앱에서는 마지막 재안내 후 **24시간**이 지나면 한 번 더 안내한다. 재안내 시각은 대상 버전·프로필별 로컬 값으로 관리한다. 시계 변경으로 반복 팝업이 생기지 않게 한다.
- 토스트가 방해금지·권한으로 보이지 않거나 사용자가 닫아도 지속 배지는 남는다. 매 진행률 이벤트를 Windows 알림으로 내보내거나 본창을 반복적으로 앞으로 가져오지 않는다.
- 자동 확인은 작은 업데이트 메타데이터를 활용하고 이미 내려받는 설치파일을 중복 다운로드하지 않는다. GitHub에 별도 사용자별 설치 확인 보고·DB·상시 모니터링 서버를 만들지 않는다.

## 5. 설치·적용·실패 처리

1. 지금 설치는 메인이 확인한 준비 완료 상태에서만 허용한다. renderer의 임의 파일 경로·URL이나 버전 문자열을 받지 않는다. 로그인 전에도 신뢰한 앱 최상위 화면에서만 설치 IPC를 호출할 수 있다.
2. 본창·위젯·로컬 기능의 저장 중/미저장 상태를 모은다. 확인창에 종료·재시작과 저장 영향을 안내한다. 저장 완료 확인을 받지 못한 작업은 완료로 간주하지 않고 설치를 미룰 수 있게 한다. 별도 외부 사이트의 저장 상태를 읽을 수 없으면 저장 확인을 사용자에게 명확히 안내한다.
3. 설치 호출을 한 번만 실행하고 대상 버전·시도 시각을 기록한다. 모든 창의 중복 설치를 잠그고 updater로 종료/설치를 수행한다. 강제 자동 재시작이나 전체 자료 비우기는 하지 않는다.
4. 다음 실행에서 실제 app 버전을 의미 있는 버전 비교로 대조한다. 대상 이상으로 실행됐으면 대기 배지를 해제하고 한 번 적용 완료를 알린다. 이전 버전이면 설치 미완료 안내를 유지한다. 단순 문자열 크기 비교를 쓰지 않는다.
5. 설치파일 손상·다운로드 실패·권한/백신·취소·재시작 실패를 확인 가능한 범위에서 구분한다. 내려받기 실패는 재시도, 설치 실패는 다시 설치/검증된 공식 수동 설치 경로를 제공한다. 설치 완료로 거짓 표시하지 않는다.
6. 다운로드 준비 상태는 앱 재실행에서 updater의 확인을 통해 복원한다. 저장 경로를 스스로 추정해 임의 exe를 실행하지 않는다. 대상이 바뀐 경우 내려받은 버전과 새 최신 버전을 구분한다.

버전 비교·준비 파일 확인·Windows 알림 API는 개발 시작 시 실제 기준 Electron/electron-updater 버전으로 대조한다. 최신 문서에 있는 API가 현재 설치 버전에도 있다고 가정하지 않는다.

## 6. 파일과 구현 순서

| 영역 | 변경 |
| --- | --- |
| electron/main/update-manager.ts (신규 또는 동등 모듈) | updater 연결·상태 snapshot/revision·중복 방지·확인 간격·재시도·설치 시도/완료 |
| 메인 창/트레이/Windows 알림 관리 | 모든 창 상태 배포·알림 클릭·복원·단일 설치·사용자 작업 확인 |
| preload·API 타입·shared/update.ts | 상태 구독/get/check/open/install·신뢰한 송신자·요청 검증 |
| appStore·App·UpdateModal·공통 배너 | boolean 조합을 상태 모델로 전환, 로그인 전 안내·상세·실제 진행률 |
| WidgetApp·접힌 위젯·트레이 UI | 공통 상태·지속 배지·본창 업데이트 이동 |
| 저장 상태 조정 모듈·각 저장 기능 | 저장 중/미저장 확인·종료 안내. 값이나 학생자료를 알림에 전달하지 않음 |
| 도움말·변경 안내·프리뷰 설정·검증 | 위젯 안내·첫 배포 전환·격리 피드·상태/시간/패키징 시험 |

순서는 최신 소스/재현 → 메인 상태·snapshot/타이머 → 로그인 전/본창 → 위젯/트레이/토스트 → 실제 진행률·저장 확인·설치/버전 복원 → 시간/실패/프리뷰 검사 → Windows 두 버전간 실제 업데이트이다.

## 7. 검증과 제공·복구

| ID | 통과 기준 |
| --- | --- |
| UP-01 | 로그인 전/본창/위젯/접힌 위젯/트레이에 같은 버전·상태 표시 |
| UP-02 | 초기 구독보다 이른 이벤트·창 재생성·응답 순서 역전에도 최신 snapshot 유지 |
| UP-03 | 실제 바이트/진행률 표시, 확인/다운로드/설치 준비를 혼동하지 않음 |
| UP-04 | 앱 시작·6시간 경과·복구·수동 확인과 중복 작업 공유 정확 |
| UP-05 | 5분/30분/6시간 재시도·오프라인 복구, 실패를 최신으로 표시하지 않음 |
| UP-06 | 발견/준비 토스트·클릭 이동·알림 차단 시 지속 배지, 앱 강제 전면 반복 없음 |
| UP-07 | 나중에 후 배지 유지, 다음 실행/24시간 재안내·버전별 초기화·과도한 팝업 없음 |
| UP-08 | 본창/위젯 동시 클릭에서 다운로드/설치 한 번만 실행 |
| UP-09 | 미저장/저장 중·외부 사이트 작업 안내·취소, 자료 유실 없는 종료 |
| UP-10 | 준비 안 된 설치·임의 경로/URL·외부 프레임 IPC 거부 |
| UP-11 | 다운로드 검증/손상/취소/권한 오류를 단계별 안내하고 안전한 재시도 제공 |
| UP-12 | 두 패키징 버전의 실제 업데이트와 재시작 버전 대조. 설치 클릭만으로 완료 처리 없음 |
| UP-13 | 재시작 후 준비 상태 복원·다른 대상 버전·더 높은 버전의 대기 배지 처리 정확 |
| UP-14 | 위젯 사용법/열기/설정 이동·개인 설정 유지, 로그인 전 개인 자료 미노출 |
| UP-15 | 우수사례/외부 웹 보기와 팝업·초점·배율·테마·키보드 정상 |
| UP-16 | 로그/알림에 암호·토큰·학생자료 없음, 위젯/본창별 중복 네트워크 호출 없음 |
| UP-17 | 프리뷰는 정식 피드·설치 경로·프로필에 영향 없음. 타입/빌드/필수 검사 통과 |
| UP-18 | 구버전 최초 설치 안내와 업데이트 장애의 수동 복구, 더 높은 패치 복구 기록 |

프리뷰는 정식 피드를 사용하지 않는다. 실제 설치 시험은 별도 앱 ID·프로필·로컬/격리 테스트 피드의 두 버전으로 수행하고 운영 Release를 시험 목적으로 게시하지 않는다. 제공물은 실행본·버전/기준 커밋·상태별 화면·UP-01~18 결과·첫 배포 안내이다.

정식 단계에서는 로그인 계획의 서버 전환 시점을 맞추고 버전·Release·업데이트 파일·기존 사용자 설치 결과를 검증한다. 구버전에 새 배지가 소급 생기지 않는다는 점을 안내한다. 복구는 더 높은 패치와 검증된 공식 설치 경로로 제공하며 사용자 자료·설정을 삭제하지 않는다. 실제 설치/재실행과 UP-01~18을 확인하기 전에는 개발 완료로 보고하지 않는다.
