## 1. 목표와 화면 구성

사이드바에 새 탭 모임을 만들고, 그 안에서 사용자가 제공한 사이트를 열 수 있게 한다.

```text
진학·대입
  ├ 대학 권장과목
  └ 웅천고 생기부 생성 도우미
```

- 연결 주소: https://ungcheon-tools.github.io/saenggibu/
- 새 모임은 기본적으로 펼쳐 표시하며, 기존 `평가·교육과정·진로` 다음에 배치한다.
- 사용자 추가 요구(2026-11-03)에 따라 기존 `대학 권장과목` 탭을 `평가·교육과정·진로` 모임에서 `진학·대입` 모임으로 옮긴다. 사용자가 말한 `대학 과목 추천`은 이 기존 탭으로 해석한다. 나머지 메뉴의 위치는 유지한다.
- 일반 사용자도 현재 앱의 로그인 절차를 거친 뒤 이용할 수 있도록 한다. 관리자 전용 메뉴로 제한하지 않는다.
- 하위 탭을 누르면 앱의 본문 영역에 사이트를 표시한다. 상단에는 제목, `새로고침`, `기본 브라우저로 열기`를 제공한다.
- 본문은 남은 창 높이를 사용한다. 앱 전체와 사이트 본문에 불필요한 이중 스크롤이 생기지 않도록 조정한다.
- 메뉴명이 긴 점을 고려해 펼친 사이드바의 글자 잘림을 처리하고 전체 이름을 확인할 수 있게 한다. 접힌 사이드바에서는 아이콘과 툴팁을 제공한다.

## 2. 확인한 근거와 개발 기준 소스

### 사이트 확인

- 2026-11-03 한국시간 13:53~13:54 직접 HTTP 조회에서 `200 OK`를 확인했다.
- HTML 제목은 `생기부 자동 생성기`, 사이트 코드의 버전 표시는 `2026.10.30`이다.
- 조회 응답에는 `X-Frame-Options`와 `Content-Security-Policy` 헤더가 없었다. 이는 내장 표시를 시도할 근거이며 실제 Electron 표시 성공을 뜻하지는 않는다.
- 소스에서 브라우저 `localStorage` 저장, 파일 선택, 클립보드 복사, Excel·HTML 다운로드, 인쇄, 외부 링크 열기 및 AI API 호출 코드를 확인했다. 각 기능을 실제 실행해 검증한 상태는 아니다.
- 웹 조회 도구는 접근 오류를 반환했지만 직접 HTTP 조회는 성공했다. 웹 조회 도구의 오류를 사이트 장애로 단정하지 않는다.

### 기준 소스 확인

- 현재 프로젝트 작업 브랜치는 `codex/ungcheon-visual-identity`이며 로컬 `package.json` 버전은 `1.0.1`이다.
- 로컬에 저장된 `origin/main` 참조는 `d186ce0a`(2026-10-08)이고 해당 소스의 버전은 `1.1.37`이다. 이는 이번에 원격 최신 상태와 대조한 결과가 아니다.
- 위 정식 계열 소스에는 공통 메뉴 등록부, 메뉴 고정·숨김·모임 접기, 업무 도우미 검색 등이 있다. 현재 작업 폴더의 오래된 사이드바만 수정하면 이후 기능이 누락될 수 있다.

- 아래 수정 대상은 확인한 정식 계열 소스 구조를 기준으로 하며, 개발 시작 때 최신 구조와 다시 대조한다.

## 3. 구현 방식

### 메뉴와 이동

- 새 메뉴 ID: `saenggibu_generator`
- 새 모임 ID: `admissions`, 표시명: `진학·대입`
- 이동할 기존 메뉴 ID: `recommended_subjects`, 표시명: `대학 권장과목`. 기존 페이지와 기능은 그대로 연결하고 소속 모임만 변경한다. 이전 모임의 메뉴 목록에서는 제거해 두 모임에 중복 표시되지 않게 한다.
- 공통 메뉴 등록부에 메뉴명, 아이콘, 검색 분류와 검색어를 등록한다.
- 사이드바의 모임 목록에 새 모임과 하위 메뉴를 등록한다. 검색으로 이동했을 때도 해당 모임이 펼쳐지고 현재 메뉴가 표시되게 한다.
- 기존 메뉴 순서·고정·숨김·모임 접기 설정을 초기화하지 않는다. 저장된 목록에 새 메뉴가 없으면 기존 정규화 방식으로 한 번만 추가한다.
- `대학 권장과목`의 개인별 고정·숨김 상태와 저장된 순서는 기존 메뉴 ID를 유지해 보존한다. 기본 구성은 대학 권장과목 다음에 생기부 생성 도우미를 표시하고, 기존 사용자의 개인 메뉴 순서는 기존 규칙을 따른다. 검색·뒤로 가기로 대학 권장과목에 진입해도 새 소속 모임이 활성화되게 한다.
- 신규 메뉴도 고정·고정 해제, 숨기기·환경설정에서 복원, 메뉴 순서 편집이 기존 규칙대로 동작하게 한다.
- 업무 도우미에서 `생기부 생성`, `생기부 생성 도우미`, `학생부 생성`, `진학`, `대입`으로 검색할 수 있게 한다. 기존 개인정보 블라인드·세특 인쇄와 구별되는 설명을 제공한다.

### 사이트 본문 표시

- 전용 React 페이지 `SaenggibuGeneratorPage.tsx`를 만들고, 원본 HTTPS 주소를 `iframe`으로 표시하는 방식을 우선 적용한다.
- 이 방식은 [Electron 공식 Web Embeds 문서](https://www.electronjs.org/docs/latest/tutorial/web-embeds)의 지원 방식에 해당한다. 실제 앱에서 저장·복사·다운로드·출력을 검증한 뒤 사용 가능한 범위를 확정한다.
- 주소는 한곳에 상수로 정의하고 본문 표시와 브라우저 열기에서 함께 사용한다. URL에 학생 정보, 앱 로그인 정보, API 키를 붙이지 않는다.
- 사이트를 처음 선택했을 때만 프레임을 만든다. 앱 시작, 다른 메뉴 이용, 사이드바 펼침만으로 사이트를 미리 불러오지 않는다.
- 현재 `Layout.tsx`는 메뉴가 바뀌면 페이지를 교체한다. 새 사이트 페이지는 첫 방문 후 같은 앱 창에서 한 개만 유지해, 다른 메뉴를 다녀와도 입력 내용과 진행 중 작업이 프레임 재생성으로 끊기지 않게 한다.
- 프레임을 유지하는 영역을 페이지 전환 애니메이션의 재마운트 대상에서 분리한다. 비활성 상태에서는 숨기고 키보드 초점·포인터 입력을 받지 않게 한다. 다른 기존 페이지의 수명주기는 필요한 범위에서만 수정한다.
- 사이트 탭을 다시 누르는 동작은 새로고침으로 처리하지 않는다. 명시적인 `새로고침`에는 입력·진행 중 작업이 영향을 받을 수 있다는 확인을 제공한다.

### 연결 지연과 브라우저 열기

- 최초 로딩 중에는 안내를 표시하고, 약 15초 이상 지연되면 재시도와 기본 브라우저 열기를 안내한다. 타이머로 프레임을 자동 재생성하지 않는다.
- 교차 출처 프레임은 내부 오류·HTTP 상태를 부모에서 정확히 읽기 어렵다. `onLoad`만으로 사이트 정상 동작이나 저장 성공을 보장하는 표시를 하지 않는다.
- 오프라인·학교망 차단·사이트 표시 제한 상황에서도 앱 메뉴와 다른 기능은 계속 사용할 수 있게 한다.
- `기본 브라우저로 열기`는 기존 `window.electron.openExternal` 경로로 고정된 HTTPS 주소를 연다. 실패 시 짧은 오류와 재시도 방법을 표시한다.
- 앱 내부 표시와 기본 브라우저는 저장 공간이 다를 수 있음을 사용 안내에 명시한다. 브라우저로 열 때 현재 프레임의 자료가 자동 이동한다고 안내하지 않는다.

## 4. 데이터 보존·권한·비용

- 사용자 보완 요구(2026-11-03): API 키는 로컬에만 저장하고 서버에 업로드·보관하지 않는다. 학교 공유 서버·별도 중계 서버·GitHub 저장소·로그에 키를 수집하거나 기록하는 기능을 추가하지 않는다.
- 현재 사이트 코드에서 `이 컴퓨터에 키 기억하기`를 선택하면 `localStorage`에 키를 저장하고, 선택 해제 시 저장된 키를 제거하는 동작을 확인했다. 이는 암호화 저장은 아니다. AI 생성과 모델 목록 조회 시에는 선택한 AI 제공업체의 공식 API로 인증 키가 전송되므로, 로컬 저장과 제공업체 인증 전송을 구분해 안내한다. 모든 외부 서버로의 키 전송을 금지한다는 조건이면 API 키를 사용하는 온라인 AI 호출은 그 조건을 충족할 수 없다.
- 앱 내부 사이트의 저장 공간과 기존 Chrome·Edge에서 사용하던 사이트 저장 공간은 자동 통합하지 않는다. 앱의 다른 업무 데이터와도 자동 연동하지 않는다.
- 사이트의 기존 저장·내보내기 기능을 사용하며, 연결을 위해 학교 공유 서버나 DB에 학생 자료·생성 내용·API 키를 새로 저장하지 않는다.
- 사용자 이름, 교직원·학생 명렬, 앱에 저장된 AI API 키를 사이트로 자동 전달하지 않는다. 사이트의 AI 설정과 사용 여부는 사이트 화면에서 사용자가 선택한다.
- 이 사이트는 AI 사용 시 선택한 제공자의 API를 호출하는 코드가 있다. 이 연결 기능 자체에 새 유료 서비스를 추가하지 않지만, 실제 AI 생성은 사용자의 API 요금제에 따라 비용이 발생할 수 있다. 이번 조사에서 실제 호출량·요금은 측정하지 않았다.
- 앱 wrapper는 AI 생성·재시도·모델 조회를 자동 실행하지 않는다. 저장과 API 키 기억은 사이트 자체 정책을 따르며, 앱의 암호화 저장과 동일하다고 표현하지 않는다.
- 앱 로그인 계정마다 사이트 저장 자료가 자동 분리된다고 가정하지 않는다. 저장 범위는 실제 Electron 프로필과 사이트의 동작을 확인해 안내한다.
- 프레임은 필요한 스크립트·사이트 저장·사용자 실행 다운로드·인쇄 기능만 허용하도록 설정한다. 클립보드는 사용자 클릭에 따른 쓰기 기능을 검증하고 불필요한 읽기 권한을 추가하지 않는다.
- 외부 사이트에 앱의 preload·파일 접근·설정 IPC를 노출하지 않는다. 기존 `contextIsolation`, `sandbox`, `nodeIntegration: false` 등 격리 설정을 유지한다.
- 사이트를 넣기 위해 `webSecurity`를 끄거나 사이트의 보안 헤더를 제거하는 범위를 확대하지 않는다. 외부 링크가 앱 본체를 덮어쓰거나 임의 창을 생성하지 않도록 필요한 범위만 처리한다. [Electron 보안 지침](https://www.electronjs.org/docs/latest/tutorial/security)을 기준으로 검토한다.
- 새 서버, DB, 주기적 상태 확인, 사이트 복제본은 추가하지 않는다. 프레임 재사용과 기존 HTTP 캐시를 사용하고, 상태 확인용 별도 GET 요청이나 자동 반복 재시도를 만들지 않는다.

## 6. 개발 순서

1. 최신 정식 소스와 Release를 대조하고 기준 커밋을 기록한다. 별도 개발 공간에 해당 변경만 적용한다.
2. 새 메뉴·모임·검색 등록, 대학 권장과목의 소속 모임 이동 및 기존 메뉴 설정 보존을 구현한다.
3. 사이트 페이지와 첫 방문 지연 로딩, 프레임 유지, 브라우저 열기·연결 안내를 구현한다.
4. 개발 실행과 패키징된 Electron 앱에서 저장·파일 선택·복사·다운로드·인쇄를 확인한다. 개발 서버에서만 확인하고 완료 처리하지 않는다.
5. 타입검사·기존 필수 검사·프로덕션 빌드를 수행하고 테스트 전용 실행본을 제공한다.
6. 사용자가 테스트한 결과를 반영하고 정식 반영 후보를 확정한다. 이후 정식 반영 및 배포 요청 범위에서 4단계를 수행한다.

## 7. 테스트 항목과 완료 기준

테스트에는 가상 학생·샘플 문구만 사용한다. 메뉴 연결 검증에 실제 학생 정보나 유료 AI 생성은 필요하지 않다.

| 구분 | 확인할 동작과 통과 기준 |
| --- | --- |
| 메뉴·모임 | 일반 사용자에게 `진학·대입 > 웅천고 생기부 생성 도우미`가 한 번만 표시되고 접기·펼치기가 작동한다. |
| 대학 권장과목 이동 | 기본 구성에서 `진학·대입 > 대학 권장과목`으로 표시되고 이전 모임에 중복되지 않는다. 기존 기능·메뉴 ID·고정·숨김 상태가 유지되며 검색·뒤로 가기도 같은 페이지와 새 모임으로 연결된다. |
| 기존 설정 | 메뉴 순서·고정·숨김·모임 접기 설정이 있는 프로필에서도 기존 설정이 유지되고 새 메뉴가 중복 없이 추가된다. 새 메뉴 숨김·복원도 작동한다. |
| 검색·이동 | 생기부 생성 관련 검색에서 올바른 메뉴로 이동하고, 앱의 뒤로 가기와 기존 대시보드 이동이 작동한다. |
| 사이트 표시 | 개발 실행과 패키징 실행 모두에서 지정 HTTPS 사이트가 본문에 표시된다. 실제 표시 검증과 HTTP 응답 확인을 구분해 기록한다. |
| 프레임 유지 | 다른 메뉴를 왕복해도 입력과 동일한 프레임이 유지되며 사이트 로딩 요청이 반복되지 않는다. 숨겨진 프레임으로 키보드 초점이 이동하지 않는다. |
| 로컬 저장 | 샘플 입력 후 앱 종료·재실행 시 사이트의 저장 자료가 복원된다. 기본 브라우저 자료가 자동 복사되거나 정식판 자료가 변경되지 않는다. |
| 주요 사이트 조작 | 작은 샘플 파일 선택, 문구 복사, Excel·인쇄용 HTML 다운로드와 출력 화면이 동작한다. AI 호출 없이 확인 가능한 범위를 기록한다. |
| 지연·오프라인 | 연결 실패·15초 지연 상황에서 안내·수동 재시도·브라우저 열기가 제공되고 다른 앱 기능을 사용할 수 있다. 자동 반복 로딩은 없다. |
| 새로고침·외부 열기 | 새로고침 시 확인을 제공한다. 브라우저 열기는 지정 사이트만 열며 자료가 자동 이동한다고 표시하지 않는다. 사이트 외부 링크가 앱 본체를 덮어쓰지 않는다. |
| 표시·접근성 | 900×600 최소 창과 최대화 상태, 밝은·어두운 앱 테마에서 메뉴·버튼이 잘리지 않고 키보드로 새 메뉴와 도구 버튼을 사용할 수 있다. 사이트 자체 테마는 원본 동작을 따른다. |
| 데이터·격리 | 탭 연결만으로 학교 공유 서버에 학생 자료·API 키를 보내지 않는다. 외부 프레임에서 앱의 `window.electron` 등 권한 API에 접근할 수 없다. |
| 기존 기능 | 대시보드, 교사 시간표, 환경설정, 기존 내장 프레임 도구와 업무 도우미 검색이 정상 동작한다. |
| 빌드·검사 | 기준 소스의 `npm run typecheck`, `npm run build`, 필요한 Windows 패키징 검사를 통과한다. 기존 실패가 있으면 변경 관련 여부와 해결 결과를 분리해 기록한다. |

내장 화면에서 저장·다운로드·복사 같은 핵심 조작에 제약이 있으면 먼저 최소 범위로 보완한다. 해결되지 않으면 브라우저 열기는 제공하되, 내장 기능을 모두 완료했다고 처리하지 않고 제한 사항과 대안을 테스트 결과에 명시한다.

## 8. 테스트버전 제공과 정식 배포

### 3단계: 테스트버전

- 버전은 기준 버전을 확인한 뒤 `<다음 후보 버전>-preview.1` 형식으로 지정한다. 이번 문서에서 정식 버전 번호를 확정하지 않는다.
- 테스트 전용 앱 이름·식별자·바로가기와 별도 `userData` 경로를 적용하고, 정식판의 설치 위치와 로컬 저장 자료를 덮어쓰지 않는 실행본을 제공한다.
- 프리뷰 버전에 대한 기존 자동업데이트 제외 처리와 프로필 분리를 각각 확인한다. 둘은 별개의 검증 항목이다.
- 자동 실행 등록이나 기존 파일 연결·바로가기에 영향을 주지 않는 패키징 방식을 사용하고, 결과물 경로·기준 커밋·시험 항목별 결과·남은 제한을 기록한다.
- 정식 자동업데이트 피드와 `latest.yml`을 변경하지 않으며 정식 Release를 게시하지 않는다.

### 4단계: 정식 반영 및 배포

- 정식 반영 및 배포 요청이 있으면 테스트한 변경을 최신 정식 소스에 통합한다. 테스트 이후 정식 소스가 바뀌었다면 충돌을 해결하고 영향을 받는 검사를 수행한다.
- 테스트 전용 식별자·데이터 경로 설정이 정식 빌드로 섞이지 않도록 확인한다. 정식판의 기존 앱 식별자와 사용자 데이터 경로를 유지한다.
- 버전·릴리스 노트·사용 안내를 갱신하고 타입검사·빌드·Windows 설치파일과 자동업데이트 구성을 검증한다.
- `main`의 앱 소스 변경은 기존 GitHub Actions 배포를 유발하므로 정식 반영 단계에서만 수행한다. 게시된 설치파일, blockmap, `latest.yml`과 Actions 성공을 확인한다.
- 초기 사용자 프로필과 기존 설정이 있는 프로필에서 새 메뉴 진입을 확인하고 배포 결과를 기록한다.

### 문제 발생 시 복구

- 테스트 중 문제는 테스트 전용 실행본과 프로필 안에서 수정하며 정식판 데이터를 덮어써 복구하지 않는다.
- 배포 후 앱 연결 문제가 확인되면 추가 변경만 되돌린 수정 버전을 더 높은 패치 버전으로 배포한다. 기존 사용자 자료와 사이트 저장 자료를 삭제하지 않는다.
- 외부 사이트 자체 장애라면 연결 안내와 브라우저 열기를 유지한다. 사이트 장애를 이유로 전체 앱 기능을 중단하지 않는다.

## 9. 이번 단계의 확인 범위

- 완료: 요구사항 정리, 로컬·정식 계열 소스 구조 조사, 사이트 HTTP 응답·소스 기능 확인, 개발계획 저장.
- 후속 검증: 실제 Electron 내장 표시와 조작, 저장 지속성, 테스트판 격리, 빌드·패키징 및 정식 배포.
- 계획 작성 당시 앱 코드·버전·설치파일은 변경하지 않았다. 현재 별도 테스트버전의 구현·검증 상태는 위 개발 기록을 따른다. 정식 앱·서버·외부 사이트는 변경하지 않았다.
