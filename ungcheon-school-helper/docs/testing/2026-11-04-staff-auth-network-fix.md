# 학교망 로그인 연결 오류 수정 후보 v1.1.40

2026-11-04, 사용자가 다른 PC에서 `staff:auth: TypeError: fetch failed`가 표시되어 로그인 불가함을 신고했다.

## 확인한 원인과 한계

- v1.1.39의 `electron/main/staff-auth.ts`는 Node 전역 fetch를 사용했다. 기존 공유 조회는 Electron net.fetch를 우선 사용한다. 두 통신 경로는 Windows 시스템 프록시/PAC·인증서 적용 방식에 차이가 있어 학교 PC별 접속 차이를 설명할 수 있는 코드 결함이다.
- 첨부 화면은 서버 통신 실패를 나타낸다. 문제가 발생한 다른 PC의 네트워크·인증서 설정을 직접 수집한 것은 아니므로 이 수정으로 모든 학교망 차단이 해결되었다고 보장하지 않는다.

## 수정

- 로그인, 세션 확인, 로그아웃, 인증된 우수사례 조회를 기존 앱과 같은 Electron net.fetch로 통일했다.
- 비밀번호/토큰은 POST 본문으로만 전송한다. 인증 실패 검증과120시간 세션 정책을 유지한다.
- HTTP 오류·HTML 등 잘못된 응답·네트워크 실패·본문 수신 시간 초과를 구분해 한국어로 안내한다. 내부 IPC 오류 접두어를 사용자 안내에서 정리한다.
- 제한시간은 로그인/세션35초·자료90초, JSON 본문 수신까지 적용한다. 로그인 POST를 자동 반복하지 않는다.
- 인증서 검증·Windows 전역 설정을 변경하지 않는다. 원격 서버의 비밀번호·세션 설정도 초기화하지 않는다.

## 검증

- 필수 npm run typecheck 및 전체 계약·타입 검사 통과.
- 의미 있는 전송 검증: Chromium 경로, Node fetch 호출0, 비밀정보의 POST 본문 보관, 1회 요청, HTTP/HTML/네트워크/시간초과 구분, 타이머 해제, 서버의 비밀번호 거부 유지.
- 실제 Windows 패키지에서 앱 전용 HTTPS CONNECT 프록시를 지정하고 Node fetch가 실패하는 조건을 재현했다. 실제 고정 서버 로그인·120시간 만료·세션 복원·로그아웃·잘못된 비밀번호 거부가 통과했다. 앱의 Node 통신 호출은0회였다.
- 프록시 연결을 끊은 조건에서 인증되지 않은 상태 유지와 한국어 오류 안내를 확인했다. Windows 전역 프록시/인증서는 변경하지 않았다. 실제 자격증명·인증 응답 원문은 로그/화면으로 내보내지 않았다.
- Windows NSIS 설치파일 생성 완료. 패키지12,403파일 개인정보 감사 통과.
- 읽기 전용 Apps Script 사전검사: 최신 main aadb94d5, 고정 배포 @86, 후보 서비스58. 업로드·서버 재배포 없음.

## 현재 상태

수정 소스와 로컬 설치파일 준비 후 사용자가 “지금 바로 배포해줘”라고 승인했다. 준비한 검증 완료 설치본을 그대로 정식 게시하며, 최신 main과 고정 서버를 재확인해 서비스58로 반영한다. 최종 검증 결과는 아래에 기록한다.
