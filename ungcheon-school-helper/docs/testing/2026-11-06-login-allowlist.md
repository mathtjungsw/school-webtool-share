# PC 로그인 허용 명단 분리 (2026-11-06)

사용자가 지정한 이름1개를 업무도우미 로그인에만 허용하고 교직원 명렬에는 추가하지 않도록 요청했다. 기존 기능은 교직원 명렬을 직접 검증했으므로 PC 인증 전용 허용 경로를 분리했다.

- `StaffAuth.gs`에 정규화된 이름 해시의 추가 허용 목록과 `staffAssertViewer_`를 추가했다. 실제 추가 이름을 공개 소스·테스트 픽스처·문서에는 기록하지 않는다. 이름 해시는 비밀번호나 인증 토큰이 아니며, 기존 공통 비밀번호 검증을 계속 필수로 적용한다.
- PC 로그인과 PC 세션 재검증에만 적용한다. 명렬 생성·편집·출력·공유 데이터 및 모바일 명렬 기반 인증 함수는 수정하지 않는다. 기존 PC120시간·모바일72시간 정책과 활성 세션을 보존한다.
- 합성 테스트: 비명렬 허용 이름의 로그인·세션 발급, 잘못된 비밀번호 거부, 미등록 이름 거부, 허용 이름의 명렬 조회/쓰기 의존 없음, 제거 후 접근 거부, 모바일 인증 범위와 기존 세션 보존을 검증했다.
- 필수 typecheck·서버 인증·모바일 계약23개·배포 가드56개 통과. 앱 설치파일과 버전은1.1.40을 유지하며 서버만 서비스59로 반영한다.
- 기존 고정 배포/원격 HEAD를 확인한 뒤 통상 배포 스크립트를 사용한다. 비밀번호 설정·세션 초기화·명렬 교체를 실행하지 않는다.

## 실제 반영 결과

- 소스94118738a793f7177f64748777d1cb2e4948db1c를 최신 main에 반영하고 고정 Apps Script 배포 @88/서비스59에 적용했다. 배포 직후 첫 URL/추가 로그인 검사는 완료되지 않아, 읽기 전용 사전검사와 실제 요청을 다시 확인했다.
- 사용자 지정 이름의 실제 로그인·120시간 세션·세션 확인·인증 자료 목록 조회 성공. 잘못된 비밀번호 거부와 로그아웃 후 세션 폐기 확인.
- 교직원 명렬66명의 반영 전후 전체 응답 해시 일치. 지정 이름은 명렬에 추가되지 않았다. 모바일 명렬 기반 인증 범위와 기존 모바일 계약3을 유지했다.
- 기존 일반 PC 로그인 및 모바일 조회도 실제 서버에서 확인했다. 비밀번호 설정·활성 세션 초기화·명렬 교체는 실행하지 않았다.
- 서버만 변경했으므로 앱 재설치 및 새 Windows Release는 필요하지 않다. 최신 설치본은1.1.40을 유지한다.
