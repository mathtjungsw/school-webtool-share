# 웅천고 업무도우미 메뉴별 PDF 설명서 제작 지침

## 1. 제작 목적

- 하루에 한 가지 기능을 동료 교사에게 소개할 수 있도록 **메뉴당 PDF 한 개**를 만든다.
- 단순한 기능 목록이나 딱딱한 사용 매뉴얼이 아니라, 옆자리 동료 교사에게 직접 알려주는 것처럼 친절하고 자연스럽게 설명한다.
- 컴퓨터 사용이 익숙하지 않은 사람도 PDF만 보고 바로 따라 할 수 있어야 한다.
- 각 PDF는 그날 소개할 기능의 장점과 실제 활용 장면을 충분히 보여주되, 한 번에 너무 많은 다른 메뉴를 설명하지 않는다.

## 2. 제작 전 필수 확인

각 메뉴의 PDF를 만들기 전에 사용자에게 다음 내용을 먼저 받거나 기존 대화에서 확인한다.

1. 이번 메뉴에서 반드시 강조할 부분
2. 가장 자주 사용하는 실제 업무 상황
3. 실수하기 쉬운 부분이나 꼭 넣어야 할 경고
4. 반드시 보여주어야 하는 버튼·탭·출력 결과
5. 공개 가능한 예시 이름과 가려야 할 개인정보

사용자가 지정한 중요 사항은 일반 설명보다 우선한다. 빠뜨리지 않도록 제작 전 체크리스트와 최종 검수표에 모두 기록한다.

## 3. 문체 원칙

- “이 메뉴에서는 ○○할 수 있습니다.”에서 끝내지 말고, “이럴 때 이 기능을 쓰시면 편합니다.”처럼 실제 상황과 연결한다.
- 명령조보다 권유형을 사용한다.
  - 권장: “먼저 학급을 선택해 주세요.”
  - 지양: “학급 선택 버튼을 클릭한다.”
- 전문 용어는 가능한 한 쉬운 말로 풀고, 꼭 필요한 용어는 화면에 표시된 명칭과 동일하게 쓴다.
- 사용자가 불안해할 수 있는 작업에는 결과와 영향 범위를 함께 알려준다.
  - 예: “이 작업은 현재 PC에만 저장되며 학교 공유 서버로 전송되지 않습니다.”
- 한 문단은 짧게 유지하고, 긴 설명보다 화면 캡처와 번호 표시를 우선한다.
- 과장된 홍보 문구는 피하고, 친근하지만 정확한 동료 교사의 말투를 유지한다.

## 4. PDF 한 편의 기본 구성

### 4.1 첫 페이지

- 메뉴명과 한 줄 소개
- “이럴 때 사용해 보세요” 실제 활용 상황 2~3개
- 이 기능으로 줄일 수 있는 업무를 짧게 설명
- 실제 완성 화면 또는 핵심 결과 화면을 크게 배치
- 설명서 제작 버전, 앱 버전, 제작일 표기

### 4.2 빠르게 살펴보기

- 전체 사용 흐름을 3~6단계로 요약
- 각 단계에 작은 실제 화면 캡처 또는 아이콘을 배치
- 처음 사용하는 사람이 먼저 눌러야 할 버튼을 명확하게 표시

### 4.3 화면별 자세한 안내

- 사용자가 실제로 누르는 순서대로 설명한다.
- 버튼, 탭, 입력칸, 팝업, 미리보기, 저장·출력 결과 등 **상태가 바뀔 때마다 별도 화면을 캡처**한다.
- 한 화면에 설명 번호를 너무 많이 넣지 않는다. 권장 개수는 1~4개이다.
- 캡처 아래에는 다음 세 가지를 짧게 적는다.
  1. 어디를 누르는지
  2. 무엇을 입력하거나 선택하는지
  3. 누른 뒤 무엇이 달라지는지
- 탭이 여러 개인 기능은 모든 주요 탭을 실제로 열어 각각 보여준다.
- 미리보기, 다운로드 파일, 인쇄 화면처럼 앱 밖에서 확인해야 하는 결과도 가능한 한 캡처한다.

### 4.4 꼭 알아두세요

- 저장 위치, 공유 여부, 서버 전송 여부
- 원본 데이터가 수정되는지 여부
- 관리자 승인이나 상대방 승인이 필요한지 여부
- 자동 반영 범위와 나이스와의 관계
- 자주 발생하는 오류와 바로 해결하는 방법

### 4.5 실제 사용 예시

- 웅천고 업무 상황을 바탕으로 한 짧은 예시를 한 가지 이상 넣는다.
- 입력 전 → 작업 중 → 완료 결과가 연결되도록 보여준다.
- 예시는 가능하면 실제 앱 화면을 사용하고, 임의로 만든 화면 이미지는 사용하지 않는다.

### 4.6 마지막 페이지

- “오늘 바로 해보기” 형태의 3단계 실습
- 자주 묻는 질문 3~5개
- 검색도우미에 입력할 수 있는 질문 예시
  - 예: “내 수업 출석부를 출력하고 싶어.”
  - 예: “교환·대강 계획서를 어디서 인쇄해?”
- 문제가 해결되지 않을 때 확인할 위치 또는 문의 방법

## 5. 화면 캡처 원칙

- 설명은 실제 배포 중인 최신 버전의 웅천고 업무도우미 화면을 기준으로 한다.
- 가능한 한 많은 실제 사용 화면을 넣되, 같은 화면을 의미 없이 반복하지 않는다.
- 다음 상태는 각각 따로 캡처하는 것을 원칙으로 한다.
  - 메뉴 진입 직후
  - 입력 전 화면
  - 입력·선택 중 화면
  - 팝업이나 확인 메시지
  - 처리 완료 화면
  - 미리보기 화면
  - 다운로드한 파일을 실제로 연 화면
  - 인쇄 미리보기 또는 출력 결과
- 화면은 밝은 모드를 기본으로 하며 글자가 충분히 진하고 선명하게 보이는지 확인한다.
- 마우스 포인터가 중요한 위치를 가리지 않게 하고, 불필요한 바탕화면·다른 프로그램·알림은 잘라낸다.
- 버튼이나 입력칸을 강조할 때는 얇은 테두리, 번호 원, 화살표를 일관된 색으로 사용한다.
- 지나치게 작은 전체 화면 한 장보다 필요한 영역을 읽기 좋은 크기로 잘라 보여준다.
- 전체 화면이 필요한 경우 다음 페이지나 바로 아래에 확대 화면도 함께 넣는다.
- 화면 캡처 원본은 삭제하지 않고 메뉴별 폴더에 보관한다.

## 6. 캡처 파일 보관 및 이름 규칙

권장 폴더 구조:

```text
manual-assets/
  메뉴명/
    원본캡처/
    편집캡처/
    출력결과/
```

파일 이름은 다음 형식을 사용한다.

```text
메뉴명_순번_화면상태_앱버전_YYYYMMDD.png
```

예시:

```text
출석부출력_01_메뉴첫화면_v1.1.11_20260812.png
출석부출력_02_교사선택_v1.1.11_20260812.png
출석부출력_03_엑셀결과_v1.1.11_20260812.png
```

## 7. 개인정보 처리 원칙

- 학생의 이름과 학번이 화면에 노출되면 원칙적으로 블러 처리한다.
- 설명에 필요하지 않은 학생 연락처, 보호자 정보, 특이사항 등은 캡처하지 않는다.
- 교사 이름은 사용자가 공개해도 된다고 지정한 예시 이름을 우선 사용한다.
- 블러 처리 전 원본 캡처도 재사용을 위해 별도 보관하되, 최종 PDF에는 처리된 화면만 넣는다.
- 서버 주소, API 키, 비밀번호, 개인 토큰, 내부 경로가 보이면 반드시 가리거나 잘라낸다.

## 8. 디자인 원칙

- A4 세로형을 기본으로 하되, 넓은 표나 시간표 설명은 필요한 경우 A4 가로형 페이지를 사용한다.
- 한 페이지에 내용을 억지로 넣지 않는다. 화면 글자가 읽히는 크기를 우선한다.
- 웅천고 업무도우미의 색상과 학교 로고를 일관되게 활용한다.
- 제목, 설명, 주의사항, 팁의 시각적 구분을 일정하게 유지한다.
- 사용자가 지정한 중요 기능에는 동일한 “중요” 표시를 사용하고 다른 부분에 남용하지 않는다.
- 캡처의 테두리와 설명 번호 스타일은 모든 메뉴 설명서에서 통일한다.
- 페이지 하단에 메뉴명, 앱 버전, 페이지 번호를 표시한다.

## 9. PDF 제작·검증 절차

1. 최신 앱 버전과 해당 메뉴의 현재 기능을 확인한다.
2. 사용자 중요 사항을 체크리스트로 만든다.
3. 실제 사용 흐름을 처음부터 끝까지 실행하며 화면을 캡처한다.
4. 친절한 동료 교사 말투로 본문을 작성한다.
5. 캡처와 설명이 같은 동작을 가리키는지 확인한다.
6. PDF로 생성한다.
7. PDF의 모든 페이지를 이미지로 렌더링하여 100% 크기로 직접 확인한다.
8. 잘린 글자, 겹친 이미지, 너무 작은 캡처, 흐린 글자, 어색한 페이지 나눔을 수정한다.
9. 앱 화면 또는 기능이 바뀌었다면 관련 PDF와 검색도우미 설명도 함께 갱신한다.
10. 최종 PDF와 캡처 원본을 메뉴별로 보관한다.

## 10. 최종 검수표

- [ ] 메뉴 하나만 집중적으로 설명했는가?
- [ ] 사용자가 지정한 중요 사항을 모두 반영했는가?
- [ ] 딱딱한 매뉴얼 문체가 아니라 동료 교사에게 알려주는 말투인가?
- [ ] 실제 사용 화면을 충분히 넣었는가?
- [ ] 클릭 전·후와 최종 결과가 연결되어 보이는가?
- [ ] 모든 주요 탭, 팝업, 미리보기, 출력 결과를 보여주었는가?
- [ ] 컴퓨터 사용이 익숙하지 않은 사람도 순서대로 따라 할 수 있는가?
- [ ] 학생 이름·학번 등 개인정보를 필요한 만큼 처리했는가?
- [ ] 검색도우미 질문 예시를 넣었는가?
- [ ] 앱 버전과 설명서 제작일을 적었는가?
- [ ] PDF 전 페이지를 렌더링하여 시각적으로 검수했는가?
- [ ] 캡처 원본을 규칙에 맞는 이름으로 보관했는가?

## 11. 사용자 중요 사항 기록란

실제 메뉴별 설명서를 시작할 때 아래 항목을 복사하여 작성한다.

```text
메뉴명:
소개 예정일:
기준 앱 버전:
가장 중요하게 설명할 내용:
반드시 보여줄 화면:
꼭 넣을 실제 예시:
주의·경고 사항:
공개 가능한 예시 이름:
개인정보 처리 범위:
사용자가 추가로 요청한 내용:
```
