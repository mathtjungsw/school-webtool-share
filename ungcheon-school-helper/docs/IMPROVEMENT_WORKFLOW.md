# 웅천고 업무도우미 개선 진행 절차

- 적용일: 2026-11-03
- 사용자 지정 절차: 개선안 저장 → 구체적인 개발계획 작성 → 테스트버전 개발 → 정식 버전 반영 및 배포
- 각 단계는 사용자가 요청한 범위까지 진행한다. 여러 단계를 함께 요청한 경우에는 해당 범위를 순서대로 수행하며 같은 승인을 반복해서 묻지 않는다.

- 2026-11-04 재확인: 새 개선 항목은 상세 개발계획과 화면 시안을 먼저 보여준다. 사용자가 다음 절차를 지시한 뒤 테스트버전에 반영한다. 이전 시험판 개발 지시를 새 항목의 즉시 개발 지시로 확대하지 않는다.

## 1. 개선안 저장

- 사용자가 개선안을 말하면 `IMPROVEMENT_PLAN.md`에 원래 의도, 원하는 동작, 적용 대상을 기록한다.
- 기존 항목과 관련되면 해당 항목에 보완하고, 기존 요구사항을 임의로 삭제하지 않는다.
- 아직 개선 대상으로 선택하지 않은 참고 아이디어는 기존 `IDEA_NOTE.md`에서 관리한다.
- 기록만 요청한 단계에서는 앱 코드, 버전, 설치파일, 서버와 배포 상태를 변경하지 않는다.
- 새 항목에는 기록일과 현재 단계를 표시한다. 기존 기록은 별도 요청 없이 일괄 개발 대상으로 전환하지 않는다.

## 2. 구체적인 개발계획 작성

- 사용자가 선택한 개선안에 대해 현재 동작과 문제, 목표 동작, 구현 범위와 수정 대상, 작업 순서를 작성한다.
- 기존 데이터 보존과 호환성, 저장 위치와 동기화 방식, 필요한 마이그레이션을 정리한다.
- 서버·DB·외부 서비스 접근을 최소화하고 캐시 재사용, 변경분 동기화, 중복 실행 방지를 검토한다. 의미 있는 비용 증가 가능성이 있으면 근거와 함께 알린다.
- 테스트 사례, 완료 기준, 테스트버전 제공 방법, 정식 반영 및 복구 방법을 구체화한다.

## 3. 테스트버전 개발

- 개발계획의 범위에 따라 구현하고 테스트버전을 제공한다.
- 정식 사용자 데이터와 기존 설정을 보존하고, 테스트 실행·설치가 정식 환경에 미칠 영향을 확인한다.
- 타입검사·빌드와 변경 기능에 필요한 동작 검증을 수행하고, 확인한 결과와 남은 문제를 기록한다.
- 테스트버전은 정식 자동 업데이트로 게시하지 않는다. 정식 반영 및 배포는 4단계 요청 범위에서 수행한다.

## 4. 정식 버전 반영 및 배포

- 사용자가 정식 반영 및 배포를 요청하면 검증한 변경을 정식 버전에 반영한다.
- 버전·변경 안내와 필요한 사용 안내를 갱신하고, 배포에 필요한 검사와 패키징을 수행한다.
- 기존 `UPDATE_RELEASE.md`의 배포 절차를 확인하고 GitHub Actions와 Release의 완료 여부를 확인한다. `main` 반영이 자동 배포를 유발할 수 있으므로 테스트 단계에서는 해당 경로를 사용하지 않는다.
- 최종 버전, 배포 결과, 검증 범위와 필요한 후속 조치를 기록한다.

## 항목별 기록 형식

```markdown
## YYYY-MM-DD 개선안 제목

- 현재 단계: 1. 개선안 저장
- 요청 내용:
- 원하는 동작:
- 적용 대상:

### 개발계획

2단계 진행 시 구현 범위·수정 대상·데이터 보존·검증·배포 및 복구 방법 기록

### 테스트버전 결과

3단계 진행 시 테스트버전 위치·검증 결과·남은 문제 기록

### 정식 반영 및 배포 결과

4단계 진행 시 버전·배포 결과·후속 조치 기록
```
