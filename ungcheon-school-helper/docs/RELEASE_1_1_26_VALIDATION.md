## 실제 로그인·응답 검증

- 사용자가 브라우저에 직접 이름과 공통 비밀번호를 입력하여 고정 Apps Script에서 로그인했다. 비밀번호·토큰·인증 응답 원문은 이 문서나 소스에 저장하지 않았다.
- 서비스 38에서 만든 기존 로그인 세션으로 서비스 39의 자료 조회가 성공했다. ScriptProperty 이름이나 활성 세션을 초기화하지 않았다.
- 서비스 39 배포 후 첫 요청은 모든 출처가 `mode: live`인 상태에서 **11.807초**에 완료했다. 서버 응답 캐시를 사용한 측정이 아니다.
- `contractVersion: 3`, 출처별 `sourceStatus`, 교사 시간표 35칸, 요청 기간 급식 8건 및 `todayMeals`를 확인했다.
- 급식 항목은 date/mealType/dishNames/calories의 4개 필드만 포함했다. 검사일은 일요일이어서 오늘 급식은 0건이었다.
- 응답에서 학생 명렬·학생 시간표·NEIS 학사일정·NEIS 학급시간표에 해당하는 금지 필드를 발견하지 않았다.
- 주간계획·창체·시간표·위원회·급식은 정상 자료, 해당 사용자에게 없는 지도·수업 변경은 정상 0건으로 구분됐다. 승인/반영 수업 변경의 포함·제외 규칙은 생성된 테스트 자료로 별도 검증했다.
- 실제 화면에서 다음 수업일의 교시별 시간표, 주간계획, 중식·석식 표시를 확인했다.
- 참고: 배포 전 서비스 38의 최초 요청 1회는 35초 제한을 넘겼다. 그 뒤 응답 캐시 조회는 3.165초, 캐시 만료 후 live 조회는 14.313초였다. 관측값은 모든 네트워크 상황에서의 응답 시간 보장을 뜻하지 않는다.

## 공개 PWA 확인 범위

- 공개 주소 HTTP 200, 로그인 화면 표시, 배포된 서비스 워커 v9의 원본 일치를 확인했다.
- 서비스 워커는 GET이 아닌 요청 또는 외부 출처 요청에 개입하지 않는다. Apps Script POST 미개입을 단위 테스트와 공개 파일 대조로 확인했다.
- 로그인 만료 안내·로그인 화면 전환, IndexedDB 저장 실패 분리, 복귀 이벤트 중복 조회 방지, 로그아웃 뒤 늦은 응답 무시는 통합 테스트로 확인했다.
- 실제 인증된 API 조회는 로컬 검증 화면에서 **실제 고정 서버 주소**에 연결하여 수행했다. 공식 공개 사이트는 별도 origin이므로 로그인 화면에서 사용자의 재로그인이 필요하며, 해당 공개 화면의 로그인 이후 최종 확인은 아직 대기 중이다.
