## 2026-11-03 교직원 이름·공통 비밀번호 로그인

- 현재 단계: **3. 초기 테스트버전 개발·검증**. 실행본과 확인 범위는 공통 개발 기록을 따른다. 원문 전수 대조·콘텐츠·미확인 검증은 남아 있다.
- 요청 내용: 교직원 이름과 사용자가 2026-11-03 대화에서 지정한 공통 비밀번호를 모두 입력해야 로그인되도록 한다.
- 비밀번호 취급: 지정값은 이 대화의 요구사항으로 참조한다. 공개될 수 있는 계획 문서·앱 소스·설치파일·안내 이미지에 평문을 기록하지 않는다. 개발 단계에서 운영 검증값은 서버의 보호된 설정으로 별도 등록하며 사용자에게 비밀번호를 반복 요청하지 않는다.
- 로그인 화면: `교직원 이름`, 마스킹된 `비밀번호`, `로그인` 버튼을 제공한다. 두 항목이 비었거나 인증이 실패하면 업무 기능을 열지 않고 오류를 안내한다. 전송·조회 중 중복 클릭을 막으며 비밀번호는 로그·URL·공통 로컬 설정에 남기지 않는다.
- 이름 확인: 교직원 명렬의 유효한 이름과 공통 비밀번호를 함께 검증한다. 로그인할 때마다 명렬 전체를 PC로 반복 다운로드하는 대신 필요한 이름의 검증 경로와 기존 캐시를 검토한다. 이미 폐기된 이름·세션이 계속 허용되지 않도록 한다.
- 인증 경계: 로그인 화면만 가리는 방식으로 끝내지 않는다. 서버에서 비밀번호 검증값을 확인하고 발급한 세션을 보호된 업무자료 요청·주요 IPC·위젯에도 적용한다. 이름·만료시각 등 로컬 설정값을 바꾸는 것만으로 인증이 통과되지 않게 한다. 전송은 HTTPS를 사용한다.
- 로그인 전 허용: 로그인 화면, 일반 오류 안내, 개인정보 없는 프로그램 버전·업데이트 확인/설치 안내만 제공한다. 개인 시간표·업무·학생자료·자료집 원문을 불러오거나 보여주지 않는다.
- 기존 세션 전환: 과거 이름만의 로그인 유지값은 인정하지 않고 최초 재인증한다. 새 서버 세션은 발급 후 최대 72시간, 자동 연장 없음. 앱 시작 때 서버 재검증이 필요하며 인증 후 일시 단절의 로컬 기능은 유효 세션 안에서 이용한다. 암호 변경·로그아웃·계정 폐기 시 세션도 폐기한다. 업무자료·개인 설정은 보존한다.
- 위젯 연동: 본창과 위젯이 같은 인증 상태를 사용한다. 로그아웃·세션 만료 시 두 화면의 개인 자료를 가리고 진행 중 응답을 폐기한다. 로그인하지 않은 위젯은 본창 로그인으로 안내한다. 업데이트 알림은 개인정보 없이 계속 볼 수 있게 한다.
- 기존 보호 기능: 교장·교감 보호 메뉴의 추가 인증과 수시모집 우수사례의 `0000` 열람 잠금은 별도 요구로 유지한다. 일반 로그인 성공만으로 이 추가 권한을 자동 부여하지 않는다.
- 보안 범위: 이름과 공통 비밀번호를 아는 사람이 다른 교직원 이름으로 시도할 수 있으므로 개인별 본인 인증으로 표현하지 않는다. 설치파일 다운로드 제한이나 이미 공개된 파일의 회수 기능과도 구분한다. 우수사례 원문을 공개 배포물에 포함하지 않는 기존 기준을 유지한다.
- 비용: 기존 인증·공유 서비스 활용을 우선 검토한다. 별도 유료 인증 서비스 가입은 임의로 추가하지 않으며 명렬 전체 반복 조회·불필요한 인증 폴링을 줄인다. 비용 절감을 이유로 서버의 권한 검증을 생략하지 않는다.
- 코드 확인 범위: 저장된 `origin/main` 참조의 `PilotLogin.tsx`는 이름 입력, `authStore.ts`는 명렬 일치와 로컬 72시간 유지 흐름을 가진다. 이는 현재 설치본·원격 최신판의 전체 보안 감사 결과가 아니다. 개발 시작 때 최신 소스·실제 서버와 대조한다.
- 후속 검증: 이름/비밀번호 누락·오류·미등록 이름, 정상 로그인, 구세션 거부, 로컬 값 변조·미인증 직접 요청 거부, 위젯 동기화·로그아웃·만료, 서버 장애·중복 요청, 비밀번호/세션 로그 미노출, 추가 보호 메뉴 분리와 업데이트 화면 접근을 포함한다.

## 2026-11-03 본창·위젯 업데이트 알림 및 설치 누락 방지

- 현재 단계: **3. 초기 테스트버전 개발·검증**. 실행본과 확인 범위는 공통 개발 기록을 따른다. 원문 전수 대조·콘텐츠·미확인 검증은 남아 있다.
- 요청 내용: 위젯을 주로 사용하는 교직원이 업데이트 존재를 쉽게 알 수 있게 하고, 내려받기만 한 뒤 설치를 놓치는 상황을 줄인다.
- 공통 상태: 메인 프로세스에서 `확인 중 / 최신 / 업데이트 발견 / 다운로드 중 / 설치 준비 완료 / 실패 / 확인 불가`와 현재·대상 버전, 진행률, 마지막 확인 시각을 관리한다. 본창·위젯은 같은 상태를 구독하고 새로 열린 화면도 즉시 최신 상태를 받는다. 일회성 이벤트 수신 여부만으로 상태를 결정하지 않는다.
- 본창 표시: 상단 또는 사이드바의 눈에 띄는 위치에 `새 업데이트`·`다운로드 중`·`지금 설치` 상태를 지속 표시한다. 업데이트 내용과 현재/새 버전을 확인하고 설치 위치를 쉽게 찾을 수 있게 한다.
- 위젯 표시: 펼친 화면과 접힌 화면 모두 업데이트 배지·설치 준비 표시를 제공한다. 실제 다운로드가 끝났으면 `업데이트 설치`를 분명히 표시하고, 누르면 본창의 업데이트 안내를 앞으로 열어 설치로 이어지게 한다. 개인 일정 칩이나 일반 업무 알림에 묻히지 않게 한다.
- Windows·트레이 안내: 본창이 숨겨졌거나 위젯만 사용할 때 업데이트 발견·설치 준비 완료를 Windows 알림과 트레이 표시로 안내한다. 알림을 누르면 해당 업데이트 화면으로 이동한다. 알림 권한·방해금지로 토스트가 보이지 않아도 본창/위젯의 표시가 남아 있어야 한다.
- 진행 표시: 다운로드 진행률은 실제 updater 이벤트로 표시한다. 확인 중·다운로드 중·설치 가능을 구분하며 임의의 퍼센트나 다운로드만 끝난 상태를 설치 완료로 표시하지 않는다.
- 미루기와 재안내: `나중에`는 팝업만 닫는다. 설치 대기 배지는 유지하고 다음 앱 실행 또는 24시간 후 재안내한다. 최초 팝업은 실행 세션·대상 버전당 한 번이며 장시간 실행 시 24시간마다 한 번 재안내할 수 있다. 메타데이터 확인은 앱 시작·6시간 경과·수동 확인을 하나로 관리하며 강제 재시작은 추가하지 않는다.
- 설치 흐름: `지금 설치` 전에 앱이 종료·재시작됨을 알리고 저장 중/미저장 작업을 확인한다. 본창과 위젯이 동시에 별도 설치를 실행하지 않게 한다. 실패 시 재시도와 필요한 수동 설치 안내를 제공한다.
- 완료 판정: 버튼 클릭이나 종료만으로 완료 처리하지 않는다. 재시작 후 실제 실행 버전이 대상 버전 이상인지 확인한 뒤 배지·대기 상태를 해제하고 적용 완료를 안내한다. 설치되지 않았으면 안내를 유지한다.
- 로그인과 연동: 새 로그인 요구로 업데이트 설치가 막히지 않게 로그인 전에도 프로그램 업데이트 상태·설치 진입을 제공한다. 비밀번호·교직원 자료·학생자료는 이 알림에 넣지 않는다.
- 위젯 기능 안내: 업데이트 내용에서 위젯 사용법을 쉽게 찾고 `위젯 열기`·`위젯 설정`으로 이동할 수 있게 한다. 업데이트 알림을 이유로 사용자 설정 없이 위젯을 강제로 켜거나 자동 실행 설정을 바꾸지 않는다.
- 확인 비용: 앱 시작·필요한 복원 시점·수동 확인을 기존 updater와 통합한다. 본창/위젯별로 중복 확인·다운로드하지 않고 최근 확인 시각·진행 중 작업을 재사용한다. 오프라인/조회 실패는 `최신`과 구분하며 재시도 간격을 둔다.
- 시험판·정식판: 프리뷰는 정식 업데이트 피드에 연결하지 않는다. 신규 알림을 포함하지 않은 기존 설치본에는 새 UI가 소급 적용되지 않으므로 최초 업데이트는 기존 경로로 설치해야 한다는 전환 안내를 준비한다.
- 코드 확인 범위: 저장된 `origin/main`에는 본창 대상 updater 이벤트, 로그인 후 표시되는 UpdateModal, 다운로드 준비 완료 후 `나중에`/`지금 설치` 흐름이 있다. 진행 표시는 실제 퍼센트와 연동되지 않은 애니메이션이며, 확인한 위젯 코드에는 별도 프로그램 업데이트 안내 연결이 보이지 않았다. 실행 중 현상의 원인을 확정한 것은 아니며 최신판·패키징 실행본에서 재현한다.
- 후속 검증: 본창/위젯/접힘/트레이/로그인 전 상태, 이벤트보다 늦은 창 구독, 확인 실패·오프라인, 실제 진행률, 다운로드 실패/재시도, 나중에 후 재안내, 중복 팝업·다운로드·설치 방지, 미저장 자료 보존, 재시작 후 버전 확인, Windows 알림 제한, 프리뷰 격리를 포함한다.

- 보관 범위: 계산에 필요한 학생 식별정보와 교과·과목·학년·학기·학점·석차등급 등으로 최소화한다. 원본 전체를 자동으로 별도 복제·장기 보관하는 것을 기본으로 삼지 않는다. 앱이 관리하는 자료는 동기화 대상에서 제외된 전용 로컬 저장소에 둔다.
- 계산식: **석차등급이 있는 과목의 `학점 × 석차등급` 합 ÷ 같은 과목들의 학점 합**. 학기 평균을 다시 단순 평균하는 방식으로 대체하지 않는다.
- 선택 방식: `전교과 평균 등급` 또는 `국어·영어·수학·과학·사회 평균 등급` 중 하나를 선택한다. 어느 방식을 선택해도 석차등급이 있는 과목만 분자와 분모에 함께 반영한다.
- 교과 분류: 파일의 원래 교과(군)를 기준으로 하며 `사회(역사/도덕 포함)` 같은 표기는 사회로 정규화한다. 한국사가 원래 사회 군에 속하면 포함하고 별도 한국사 군이면 다섯 교과 방식에서 포함 여부를 확인받는다. 불명확한 분류를 과목명만 보고 조용히 확정하지 않는다. 상세계획에 기본 매핑과 확인 절차를 기록했다.
- 계산 전 확인: 반영·제외 과목, 학점 합, 제외 사유와 판독이 필요한 항목을 보여준다. 석차등급 대신 A/B/C·P·점·빈칸을 등급으로 바꾸지 않으며 누락 학점을 임의로 1로 채우지 않는다. 학점이 잘못된 행이 있으면 미완료 결과임을 표시하고 확인 후 확정한다. 유효한 분모가 없으면 `산출 불가`로 표시한다.
- 학생·학기 구분: 한 파일에 여러 학생이나 여러 학기가 있으면 학생별로 분리한다. 서로 다른 학생의 성적이 합쳐지거나 PDF와 XLSX를 함께 올렸을 때 같은 성적이 중복 반영되지 않게 한다. 등급 체계가 다른 자료는 확인 없이 한 결과로 섞지 않는다.
- 나이스 다운로드 안내: 제공한 화면을 바탕으로 `학생부 항목별 조회 → 교과학습발달상황 → 학년도·학년·반 선택 → 조회 → 저장 메뉴에서 XLSX DATA 내려받기`를 설명한다. 캡처에서는 저장 메뉴가 펼쳐져 있지 않아 실제 옵션 이름은 테스트 단계에서 대조한다. 안내 이미지에는 개인정보를 가린 사본을 사용하고 원본은 보존한다.
- 추가 요청: **`산출기 저장자료 비우기` 버튼**을 화면에서 찾기 쉬운 위치에 제공한다. 삭제 전 산출기에 보관한 학생·자료·결과의 삭제 범위를 안내하고 확인을 받는다.
- 삭제 대상: 산출기가 관리하는 불러온 자료, 정규화한 성적, 산출 결과, 임시 파일·캐시 및 메모리에 남은 관련 자료를 비운다. 산출기가 복사해 관리한 원본이 있다면 그것도 삭제 대상에 포함한다.
- 삭제 제외: 사용자가 원래 보관한 PDF·XLSX, 직접 내보낸 결과 파일, 다른 기능의 저장자료, 앱 로그인·API 키·공통 설정은 삭제하지 않는다. 확인창과 도움말에 이 범위를 명시한다.
- 삭제 동작: 진행 중인 읽기·계산·저장을 취소하고 늦게 도착한 처리 결과가 다시 저장되지 않도록 한다. 일부 삭제에 실패하면 성공으로 표시하지 않고 재시도를 제공한다. 완료 후 빈 화면으로 돌아가며 앱을 다시 실행해도 삭제 자료가 복원되지 않아야 한다.
- 보안 표현: 로컬 저장을 암호화 또는 완전한 복구 불가 삭제와 같은 의미로 안내하지 않는다. 자료 비우기는 산출기 전용 저장 범위에 한정하며 PC 전체나 다른 앱 자료를 지우지 않는다.
- 예시 점검 기록: [PDF·XLSX 구조와 다운로드 화면 확인 메모](research/2026-11-03-average-grade-samples.md). 학생 이름·개별 성적 원문·실제 산출 결과는 개선 문서나 공개 테스트 자료에 넣지 않는다.

## 사이드바 메뉴 고정·숨기기

- 날짜, 시간, 위원회명, 장소의 색상 대비를 각각 확인하고 밝은 모드·다크 모드 화면 검사를 수행한다.

- 카드를 누르면 작은 팝업 또는 펼침 영역에서 카드 그림과 오늘의 메시지를 보여준다.
- `오늘의 행운카드`는 업데이트 후 기본적으로 켜진 상태로 표시한다.
- 위젯 옵션에서 `오늘의 행운카드 표시`를 켜거나 끌 수 있게 한다.
- 사용자가 선택한 표시 상태는 현재 PC의 로컬 설정에 저장하여 앱이나 위젯을 다시 실행해도 유지한다.

### 카드 결과 방식

- 같은 사용자에게 같은 날짜에는 같은 카드와 메시지를 보여주고, 다음 날 자동으로 새 카드가 나오게 한다.
- 카드 선택과 해석은 앱에 내장된 로컬 데이터만 사용하며 인터넷 연결이나 외부 API를 요구하지 않는다.
- 생년월일·성별 등 개인정보를 입력받지 않는다.
- 타로는 정방향만 사용하고 역방향 해석은 사용하지 않는다.
- 화투는 월별 꽃과 패의 전통적인 상징을 참고하되 점괘의 부정적인 단정은 사용하지 않는다.

### 안전한 해석 원칙

- 실제 타로 카드와 화투의 카드 체계·상징은 활용하되, 해석 문장은 교직원용으로 별도 작성한다.
- 죽음·사고·질병·실패·손실·불화 등을 예언하거나 불안감을 주는 문장은 사용하지 않는다.
- 건강, 재물, 인간관계, 인사 결과 등을 확정적으로 단정하지 않는다.
- 부정적으로 해석되는 카드는 다음과 같이 중립적이고 실천 가능한 메시지로 바꾼다.
  - 변화가 큰 카드: `정리와 전환이 필요한 날`
  - 충돌을 뜻하는 카드: `서두르지 말고 서로의 입장을 확인할 때`
  - 지연을 뜻하는 카드: `우선순위를 다시 살펴보면 좋은 날`
- 모든 결과는 긍정적·중립적·애매모호한 범위에서 작성하고 마지막은 가벼운 행동 조언으로 마무리한다.
- 카드 결과 화면에 `재미로 보는 긍정 메시지입니다.`라는 안내문을 항상 표시한다.

### 표시 내용

- 카드 이름
- 카드 그림
- 오늘의 업무 흐름
- 동료 관계에 관한 가벼운 메시지
- 오늘의 작은 조언
- 행운의 색
- 행운의 숫자
- 현재 위젯에 있는 `오늘의 운세`와 내용이 겹치면 두 기능을 통합하여 중복 문장을 표시하지 않는다.

### 카드 디자인과 저작권

- 시중 타로 덱이나 화투 제품의 그림을 그대로 복제하지 않는다.
- 전통적인 상징과 카드 구성을 참고하여 웅천고 업무도우미 전용 일러스트를 새로 제작한다.
- 밝은 모드에서 카드명과 메시지가 어둡고 선명하게 보이도록 대비를 확보한다.
- 위젯 배경 디자인별로 카드 뒷면과 팝업 색상을 조정하되 카드의 의미와 결과는 동일하게 유지한다.

### 완료 기준

- 타로·화투 선택과 선택 상태의 로컬 저장이 정상 작동해야 한다.
- 같은 날 앱을 여러 번 실행해도 같은 결과가 유지되고 날짜가 바뀌면 새 결과가 나와야 한다.
- 인터넷 연결이 없는 상태에서도 모든 카드와 메시지가 정상 표시되어야 한다.
- 전체 문구를 검사하여 부정적 예언, 건강·사고·금전 손실의 단정, 불안감을 주는 표현이 포함되지 않아야 한다.
- 카드 그림이 외부 제품 이미지를 복제하지 않은 전용 디자인이어야 한다.
- 이 항목은 개선계획에만 기록하며 사용자가 `시험판 제작` 또는 `업데이트 배포`를 요청하기 전에는 앱 코드·버전·설치파일을 변경하지 않는다.
