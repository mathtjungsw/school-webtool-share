## 2. XLSX 입력에서 확인한 함정

- 두 파일 모두 워크시트의 사용 영역 선언이 `A1`이지만 XML 내부에는 그보다 많은 행과 셀이 존재한다. 라이브러리의 선언된 사용 영역만 믿으면 파일을 비었다고 오판하거나 대부분의 성적을 누락할 수 있다. 실제 셀 영역을 제한된 범위 안에서 확인하는 대응이 필요하다.
- 대표적인 석차등급 표는 A열 번호, B열 성명, C열 학년, D열 학기, E열 교과, F열 과목, G열 학점, I열 성취도, K열 석차등급, L열 수강자수, M열 비고 구조이다. 이것을 모든 표의 고정 열 배치라고 가정하지 않는다.
- 1학년 자료에는 같은 시트 안에서 성취도·비고 등으로 구성이 다른 머리글이 확인된다. 다른 표의 값을 석차등급으로 잘못 읽지 않도록 표 단위로 경계를 잡는다.
- 교과 값으로 `사회(역사/도덕 포함)` 계열 표기가 확인된다. 주요 교과 선택은 정규화된 원래 교과(군) 기준으로 설계하고 실제 반영 과목을 사용자가 확인할 수 있게 한다.
- 원본 파일의 사용 영역이나 서식을 고치지 않았다. 구조 대응은 향후 산출기의 읽기 단계에서 수행한다.

## 3. 계산과 개인정보 요구를 구현 단계로 넘길 때

- 계산에 필요한 교과 성적만 추출한다. 인적사항·출결·행동특성 등 학생부 전체를 별도 서비스에 전달하는 경로를 사용하지 않는다.
- 기존 외부 AI 학생부 분석 호출과 분리한 로컬 전용 계산 흐름이 필요하다. 기존 계산 코드의 누락 학점 기본값 등도 사용자 지정 계산식과 일치하는지 재검토해야 한다.
- 등급이 없으면 그 과목의 학점도 분모에서 제외한다. 석차등급이 있어도 학점이 없거나 유효하지 않으면 임의 값으로 확정하지 않는다.
- 검증에는 실제 학생 성적을 문서에 복사하는 대신 합성 예시를 사용한다. 예: 3학점·2등급과 2학점·4등급이면 `(3×2 + 2×4) / (3+2) = 2.8`.
- 원본 보관 위치가 클라우드 동기화 폴더인지와 별개로, 산출기 자체 저장소는 공유·동기화 경로에 두지 않는다. 사용자의 기존 원본 보관·동기화 설정은 변경하지 않는다.
- 로컬 자료 비우기는 산출기 관리 자료와 결과를 대상으로 하며, 입력 원본·사용자가 내보낸 파일·다른 앱 기능의 자료는 보존한다. 읽기·계산 중 비우기와 재실행 후 복원 방지까지 검증 대상이다.

## 4. 다운로드 안내의 확인 범위

캡처에서 확인한 항목은 `학교생활기록부`, `학생부 항목별 조회`, `교과학습발달상황`, 학년도·학년·반 선택, 조회 버튼, 뷰어 저장 아이콘이다. 사용자는 이 화면에서 받은 XLSX DATA 파일을 올리는 흐름을 요청했다. 저장 메뉴를 펼친 화면이 없어 XLSX DATA 옵션의 실제 문구·세부 클릭 순서는 향후 사용자 안내 제작 시 대조해야 한다.

원본 캡처는 이 문서나 앱 공개 자산에 복사하지 않았다. 개인정보를 가린 안내용 사본과 앱의 도움말은 후속 단계에서 제작한다.
