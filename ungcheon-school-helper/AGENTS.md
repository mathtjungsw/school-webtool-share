# 웅천고 업무도우미 작업 규칙

- 기능, 메뉴 이름, 이용 순서가 바뀔 때마다 `src/services/workAssistantSearch.ts`의 제목·설명·단계·검색어도 함께 검토하고 갱신한다.
- 새 사이드바 메뉴에는 해당 `page`를 가리키는 검색 도우미 항목을 최소 하나 추가한다.
- 배포 전 `npm run typecheck`를 실행한다. 이 명령에는 사이드바와 검색 도우미의 메뉴 누락 검사가 포함된다.
- 앱은 밝은 모드만 제공한다. UI 수정·검증·화면 캡처·대비 자동 검사는 밝은 모드를 기준으로 하고, 다크 모드나 시간별 자동 테마 전환을 다시 추가하지 않는다.
- 배포할 때 `server/Code.gs`의 `RELEASE_NOTES` 맨 위에 새 버전의 기능 개선 내용을 추가한다.
- 사용자가 **개선의견**을 말하면 앱 코드·버전·설치파일·배포 상태를 변경하지 않고 `docs/IMPROVEMENT_PLAN.md`의 대기 목록에만 누적한다.
- `docs/IDEA_NOTE.md`는 개선계획으로 확정하기 전에 검토할 아이디어를 별도로 보관하는 독립 문서다. 개선계획의 선행 단계나 필수 단계로 취급하지 않는다.
- 사용자가 **아이디어 노트에 넣어달라고 명시한 경우에만** 해당 내용을 `docs/IDEA_NOTE.md`에 기록한다. 일반 질문·제안·개선의견을 임의로 아이디어 노트에 추가하지 않는다.
- 아이디어 노트의 항목은 사용자가 별도로 요청할 때만 개선계획으로 옮기며, 옮기지 않거나 폐기할 수도 있다.
- 사용자가 **시험판 제작**을 요청하면 대기 중인 개선 계획 전체를 `x.y.z-preview.n` 시험판으로 별도 브랜치에서 구현하고, 이 PC에서 사용할 로컬 설치파일까지만 만든다. 시험판 제작과 검증이 성공한 뒤 대기 목록을 비운다.
- 시험판 작업에서는 GitHub 메인 병합·GitHub Release·`latest.yml` 게시·Apps Script 재배포를 하지 않는다.
- 사용자가 **업데이트 배포** 또는 **자동업데이트 진행**을 명시적으로 요청하면 정식 버전을 개발·검증하고, 다른 PC에도 전달되도록 필요한 푸시·릴리스·자동 업데이트 게시와 Apps Script 재배포까지 진행한다.
- 앱 실행 불가, 데이터 손실 위험 등 긴급 배포가 필요해 보이는 예외 상황에서는 즉시 배포하지 말고, 원인과 긴급성을 사용자에게 알린 뒤 바로 업데이트 배포할지 먼저 확인한다.
