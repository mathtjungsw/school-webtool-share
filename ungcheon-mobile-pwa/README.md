# 웅천고 모바일 일정 PWA

PC용 `ungcheon-school-helper`와 같은 최신 main에서 관리하는 교직원용 모바일 일정 앱입니다. 일반 일정은 읽기 전용입니다. Firebase Hosting의 실험실에서 3학년 당일의 담당 학급과 수업 출결을 입력할 수 있습니다.

기본 주소는 <https://ungcheon-school-helper-mobile.web.app/>입니다. <https://mathtjungsw.github.io/school-webtool-share/mobile/>도 같은 앱으로 연결됩니다. 기존 챗사이트와 병행하는 동안 두 앱은 같은 학교 인증 API와 Firestore 운영 자료를 사용합니다. 각 주소에서 처음 한 번 로그인합니다. 10월 13일·11월 9일·11월 17일의 금요일 시간표 운영과 8월 11일의 월요일 운영을 PC와 동일하게 적용하며, 날짜별·주간 화면에 운영 요일을 표시합니다. 3학년 출결도 실제 운영 요일의 수강생을 조회하되 출결 자료의 날짜는 실제 수업일을 유지합니다. 시간표 행과 여백을 줄이고 지난주·이번 주·다음 주 이동, 긴 일정 상세보기, 출처별 확인 시각을 제공합니다. 3학년은 이동수업과 학급수업 모두 실제 수강생 출결을 연결하고, 출결 버튼을 누르면 해당 수업의 전체 명렬 또는 비고가 있는 학생만 학번순으로 확인할 수 있습니다. 출결 비고에 `자습`만 포함된 학생은 실제 결석과 구분해 연두색 `자습 · 장소 이동` 항목으로 표시합니다.

## 재사용하는 조회 계약

Apps Script의 읽기 전용 모바일 조회 액션만 사용합니다.

| 액션 | 사용 데이터 | 모바일 처리 |
| --- | --- | --- |
| `verifyMobileViewer` | 교직원 이름과 기존 공통 비밀번호 | 이름 일치·비밀번호 확인 후 72시간 세션 발급 |
| `getMobileScheduleBundle` | 로그인 교사의 시간표·위원회·수업 변경·일일 시간표 예외, 주간계획·창체·창체 학사일정·등교/급식지도, 요청 기간 급식과 당일 3학년 수강생 출결 | 기본 화면에는 출결·자습 건수와 반별 입력 상태를 전달하며 학생의 이름과 비고는 해당 교시의 상세 조회에서만 받습니다. 모바일은 NEIS API를 직접 호출하지 않음 |
| `getMobileAttendanceRoster` | 선택한 날짜·교시의 실제 수강생 반·번호·이름·비고 | 출결 팝업을 열 때만 해당 수업을 인증 조회. 명렬 상세는 장기 캐시에 저장하지 않음 |

응답은 기존 자료 필드와 함께 출처별 `sourceStatus`를 제공합니다. 한 출처가 일시적으로 실패하면 다른 자료는 최신본으로 갱신하고, 실패한 부분만 사용자별 IndexedDB의 마지막 정상본으로 보완합니다. 정상적으로 0건인 자료와 조회 실패를 구분합니다.

위 조회 외에 로그아웃과 실패한 출처의 개별 재조회가 있습니다. 교사 시간표·위원회·수업 변경은 서버가 로그인 교사 범위로 선별하여 묶음에 포함하며 개별 데스크톱 조회 API를 호출하지 않습니다.

교시 시각과 특정 요일 운영 기준 두 파일은 `npm run sync:shared`로 동기화하고 빌드·타입검사 전에 해시를 비교합니다. 당김수업은 로그인한 교사의 일정 응답에서 받습니다. 정적 수업 파일이 배포 대상에 들어가면 빌드 검사가 실패합니다.

## 보안·캐시 원칙

처음 로그인하면 오늘 화면을 먼저 열고 한국 시간 기준 오늘부터 13일 뒤까지, 모두 14일치 일정·교사 시간표·급식을 한 번에 받아 기기에 저장합니다. 상단의 ‘오프라인 일정 저장 완료’ 옆에 실제 저장 기간이 표시됩니다. 유효한 로그인 상태에서는 미리 열어 보지 않은 날짜도 오프라인으로 볼 수 있습니다. 다운로드가 중단되면 연결을 복구하거나 ‘다시 받기’를 누를 때 재시도합니다. 저장 기간이 지나면 다음 온라인 실행에서 새 14일치를 받습니다. 학생별 출결 명렬은 미리 받는 자료에서 제외합니다.

- 이름 완전 일치와 학교 공통 비밀번호를 함께 확인하며 72시간 후 자동 만료됩니다. 기존 ScriptProperty와 유효 세션은 배포로 초기화하지 않습니다.
- 일정 API는 조회 액션만 사용합니다. 실험실의 출결 입력은 별도 인증 경로를 사용하고, 서버가 담당 학급·수업과 학생을 재확인한 뒤 Firestore에 저장합니다. 교장·교감 전체 조회는 기존 보호 메뉴 인증을 사용하며 읽기 전용입니다.
- 사용자별 정상 조회 스냅샷은 이름의 SHA-256 키로 IndexedDB에 저장합니다. 서비스 워커는 동일 출처 앱 셸만 캐시하며 Apps Script 응답은 캐시하지 않습니다.
- 로그아웃하면 세션 이름과 해당 사용자의 IndexedDB 스냅샷을 삭제합니다.
- API 조회 제한은 35초입니다. 세션 만료는 네트워크 실패와 구분하고 `로그인이 만료되었습니다. 다시 로그인해 주세요.` 안내 후 로그인 화면으로 이동합니다.
- IndexedDB 조회는 API와 병렬이며 저장 실패가 정상 응답을 연결 실패로 바꾸지 않습니다. 저장소가 막혀도 제한 시간 후 조회를 계속하고 최신 자료는 메모리에 표시합니다.
- 앱 복귀·네트워크 복구·한국 시간 날짜 변경 시 자동 갱신합니다. 같은 범위의 진행 중 요청은 공유하고, pageshow/visibilitychange/online 연속 이벤트는 1.5초 안에 합칩니다. 실제 사용자·날짜 범위 변경이나 로그아웃 때만 오래된 요청을 취소합니다.
- 마지막 정상 조회와 비교해 새로 추가되거나 내용이 바뀐 일정만 `NEW`로 표시합니다. 배열 정렬 순서는 변경으로 취급하지 않습니다.
- 모바일 앱은 NEIS 스냅샷이나 NEIS 학사일정을 요청·전송·캐시하지 않습니다.
- 모바일 전용 조회 액션은 로그인한 교직원에게 필요한 자료만 응답하며, 다른 교직원의 명렬·위원회·시간표를 브라우저로 보내지 않습니다.
- 3학년 출결 인원은 해당 교사·요일·교시의 실제 수강생을 기준으로 집계합니다. 학생별 이름·비고는 출결 상세를 열었을 때만 표시합니다. 새 화면의 첫 실행에서 모든 계정의 기기 일정 사본에 남은 개인별 출결도 정리합니다.
- Apps Script는 `ungcheon-school-helper`에서 `npm run deploy:apps-script`로 기존 고정 배포만 갱신합니다. 최신 main·실제 고정 버전·원격 HEAD의 데스크톱/모바일 계약과 릴리스 안내 보존 검사를 통과해야 합니다.

## 검증

- 모바일: `npm run typecheck`, `npm test`, `npm run build`
- 데스크톱: `npm run typecheck`에 서버 계약·배포 가드 검사가 포함됩니다.
- 배포 전 원격 비교: `npm run deploy:apps-script -- -PreflightOnly`
- 실제 로그인은 화면에서 직접 입력하며 비밀번호·토큰·전체 API 응답을 로그로 남기지 않습니다. 서비스 버전, contractVersion, 출처 상태/건수, 조회 소요시간과 금지 필드 부재만 확인합니다.

## Firebase Hosting 배포

`npm ci` 후 `npm run typecheck`, `npm test`, `npm run build:hosting`을 실행합니다. 기존 Firebase 로그인으로 이 폴더에서 `firebase deploy --only hosting --project ungcheon-school-helper`를 실행하면 전용 사이트만 갱신됩니다. GitHub의 안내 페이지에는 로그인 입력칸과 학교 자료가 없습니다. 챗사이트는 같은 소스를 별도 Sites 배포로 갱신합니다.
